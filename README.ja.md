# キャロット漫画翻訳

<p align="center">
  WindowsとApple Silicon macOSの正式版で、マンガ取込、OCR、AI翻訳、編集、インペインティング、PNG／レイヤーPSD出力に対応
</p>

  <strong>日本語</strong> ·

キャロット漫画翻訳は、画像からセリフや効果音を検出し、AIで翻訳ブロックを作成したあと、文章や配置を人の手で整えて完成版PNGまたはレイヤーPSDとして書き出せるマンガ制作支援ツールです。標準の翻訳方向は日本語 → 韓国語ですが、ほかの原文言語・翻訳先言語も選べます。

- v2.4.0正式版のダウンロード（Windows EXE・Apple Silicon DMG/ZIP）：[GitHub Releases](https://github.com/ucx0204/CarrotMangaTranslator/releases)
- 現在のバージョン情報：[v2.4.0 パッチノート](docs/release-notes/v2.4.0.md)
- コントリビューションガイド：[CONTRIBUTING.md](CONTRIBUTING.md)
- コード構成と品質規則：[docs/architecture.md](docs/architecture.md)
- プロジェクトの利用状況と公開資料：[docs/reputation.md](docs/reputation.md)

## 概要

- 1枚の画像、画像フォルダー、ZIP/CBZ・RAR/CBR、PDFを作品・話単位で管理できます。
- Paddle OCRとローカルモデルの`Gemma 4`、`OpenAI Codex`、OpenAI互換`API`を組み合わせて翻訳できます。
- アプリの表示言語は、韓国語、日本語、英語、中国語（簡体字）、中国語（繁体字）に対応しています。
- マンガの原文言語・翻訳先言語は、48種類のプリセットに加えて、BCP 47言語コードの直接入力にも対応しています。
- 翻訳ブロックの文章、位置、方向、フォント、色、縁取り、間隔を直接編集できます。
- 用語集、キャラクターの話し方、翻訳ルール、ストーリー記憶をAI翻訳に反映できます。
- AOT、LaMa、Fluxで原文を消去し、ブラシツールで補正してから完成PNGまたはレイヤーPSDとして出力できます。
- TXTやCSV/TSVで外部校正を行い、`*.mgtshare`で編集可能な作品データを共有できます。

## インストール前の確認

- 対応OS：Windows 10/11 x64、Apple Silicon（M1以降）のmacOS 14以降。Intel Macは対象外です。
- 必要な空き容量：アプリ本体とは別に、選択したGemma、OCR、インペインティングモデルによっては数GB以上必要になる場合があります。
- インターネット接続：インストール、初回のモデルダウンロード、Codex/APIの使用に必要です。ローカルモデルは準備完了後、オフラインで作業できます。
- GPUがなくても一部の処理はCPUで実行できますが、OCR、ローカル翻訳、Fluxインペインティングは大幅に遅くなる場合があります。

Apple Silicon向け正式版には、arm64版FFmpeg、Paddle OCRをCPUで実行するためのPythonランタイム、Metal実行ランタイムが含まれます。Gemma、OCR、インペインティングのモデルの重みは初回使用時にチェックサムを検証してダウンロードし、2回目以降はキャッシュを再利用します。v2.4.0のmacOS版はDeveloper IDと公証の資格情報が設定されていない場合はad-hoc署名となるため、Gatekeeperに初回起動をブロックされた場合は`システム設定 → プライバシーとセキュリティ`で手動承認が必要になることがあります。macOSのデータは`~/Library/Application Support/manga-gemma-translator`に保存されます。

## クイックスタート

1. [v2.4.0正式リリース](https://github.com/ucx0204/CarrotMangaTranslator/releases/tag/v2.4.0)から、Windowsでは`CarrotMangaTranslator-Setup-v2.4.0.exe`、Apple Siliconではarm64版のDMGまたはZIPをダウンロードします。macOSで初回起動がブロックされた場合は、`システム設定 → プライバシーとセキュリティ`でアプリを手動承認します。
2. `設定 → 一般`でアプリの表示言語を確認します。対応しているWindowsの言語は初回起動時に自動で選択され、それ以外の環境では韓国語が使用されます。
3. `設定 → 翻訳エンジン`で原文言語、翻訳先言語、翻訳エンジンを選びます。
   - 自分のPC内で処理する場合は`Gemma 4`
   - 内蔵された公式Codex App ServerでChatGPTアカウントを使う場合は`OpenAI Codex`
   - 画像入力に対応した外部サーバーを使う場合は`API`
4. `設定 → ハードウェア`でOCRの品質とデバイスを選んだあと、`確認/更新`から`OCR/モデルを確認`を実行します。初回は必要なファイルが自動で準備されます。
5. メイン画面の`翻訳`から画像、フォルダー、ZIP/CBZ・RAR/CBR、またはPDFを選び、作品名と話名を指定します。
6. 話カードの`翻訳`を押してページ範囲を選びます。初めて使う場合は`未翻訳のみ + 自動生成`が扱いやすく、文脈の一貫性をさらに高めたい場合は`2回目の翻訳（品質向上）`を有効にします。
7. 作成されたブロックを確認します。必要に応じてインペインティングで原文を消去・補正し、選択したページを完成PNGまたはレイヤーPSDとして出力します。

> アプリの表示言語とマンガの翻訳言語は別々に設定されます。画面表示を英語に変更しても、日本語 → 韓国語の翻訳設定はそのまま維持されます。

## 機能ガイド

### 取り込みとライブラリ

- 対応画像：PNG、JPG、JPEG、WEBP
- 対応アーカイブ：ZIP、CBZ、RAR、CBR
- 対応ドキュメント：PDF（各ページを順番にPNGへ変換）
- `画像を開く`では1枚、`フォルダーを開く`と`圧縮ファイルを開く`では複数の画像を自然順に並べ、1話として取り込みます。
- `作品を一括翻訳`では、フォルダー内のサブフォルダーとZIP/CBZ・RAR/CBRを複数の話候補として表示し、選択した話だけをまとめて追加できます。
- 作品と話の検索・並べ替え、名前の変更・削除、ドラッグによる話とページの並べ替え、個別ページの削除に対応しています。
- WEBPはライブラリへの追加時にPNGへ正規化されます。1つの入力ファイルは256MB以下、デコード後の画像は120MP以下である必要があります。

### 翻訳範囲とパイプライン

- 作品内の話やページをサムネイルから直接選択するほか、`すべて選択`、`未翻訳のみ`、`すべて解除`を利用できます。
- `2回目の翻訳（品質向上）`では、1回目の翻訳後に用語、キャラクター、文脈を再分析し、選択した範囲をもう一度翻訳します。品質の向上が期待できますが、処理時間とAPI使用量が増えます。
- 自動分析の範囲は`空の話のみ`、`最初からやり直す`、`現在の話のみ`から選べます。
- `自動生成`は、OCRとAIの結果をもとに新しいブロックを作成します。
- `既存ブロックを維持`は、手作業で調整した領域と書式を残し、各領域のOCR原文と翻訳文だけを更新します。ブロックがないページは自動生成で処理されます。
- ページの再翻訳、処理のキャンセル、ページの一部をドラッグして再分析する`範囲翻訳`に対応しています。
- Paddle OCRの結果とページ画像をあわせて使用します。OCRキャッシュは原文言語ごとに分けて保存され、日本語ページに日本語の根拠がほとんどない場合は不要なAI呼び出しを減らします。

### 用語、キャラクター、作品の記憶

- `AI自動分析`で用語集、キャラクター、翻訳ルール、ストーリーメモリーを作成できます。
- 用語集には原文、訳語、分類、別名、メモを保存し、項目ごとに使用するかどうかを設定できます。
- キャラクターには原語名・訳名、敬語・タメ口などの話し方、自由記述の口調指示を保存できます。
- 翻訳ルールには呼称、効果音、文体、作品ごとの注意事項を記載します。
- ストーリーメモリーは、前のページまでの出来事や文脈を以降の翻訳と2回目の翻訳で参照します。
- 画面下部のトークン予算には、記憶が占めるコンテキスト量と翻訳応答に使える余裕が表示されます。

### ブロック編集と書式

- 選択ツールでブロックを移動・サイズ変更し、ブロックツールで新しい領域をドラッグして追加し、手のひらツールで拡大表示中の画面を移動できます。
- `Ctrl+クリック`で複数のブロックを選択できます。
- 翻訳文とOCR原文、横書き/縦書き、配置、傾き、不透明度、自動フィット、文字サイズ、行間、字間、文字幅、太字、斜体、文字色、縁取りとその太さを編集できます。
- 翻訳文の一部に`**太字**`、`*斜体*`、`***太字+斜体***`のマークアップを適用できます。
- 新規ブロックの既定書式を設定し、選択したブロックの必要な属性だけを複数ブロック・現在のページ・現在の話にまとめて適用できます。
- エディターは、右側パネル、アプリ内で移動できるフローティングパネル、独立したWindowsウィンドウのいずれかで使用できます。
- 現在の話に対する編集は、最大100段階の元に戻す・やり直しに対応しています。
- 拡大・縮小・等倍表示、元画像プレビュー、ブロック・背景表示の切り替えに対応しています。
- `Ctrl+K`のコマンドパレットと`?`のショートカットヘルプを利用でき、各ショートカットは設定から変更できます。

### フォント

アプリには既存の韓国語フォントに加え、英語・日本語・中国語（簡体字）・中国語（繁体字）向けの無料フォントがそれぞれ6種類ずつ含まれています。フォント一覧では`デフォルト`が最上部に表示され、その次に現在のアプリ言語のフォントグループが表示されます。それ以外は韓国語 → 英語 → 日本語 → 簡体字 → 繁体字の順序を維持し、現在の言語グループだけが前に移動します。ユーザーが登録したフォントは最後に表示されます。

| グループ         | 収録フォント                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 英語             | Comic Neue, Kalam, Bangers, Luckiest Guy, Permanent Marker, Freckle Face                       |
| 日本語           | Yusei Magic, Mochiy Pop One, Hachi Maru Pop, Dela Gothic One, Reggae One, DotGothic16          |
| 中国語（簡体字） | ZCOOL KuaiLe, ZCOOL QingKe HuangYou, ZCOOL XiaoWei, Ma Shan Zheng, Long Cang, Liu Jian Mao Cao |
| 中国語（繁体字） | Huninn, Iansui, LXGW WenKai TC, LXGW Marker Gothic, ChenYuluoyan, Cubic 11                     |

`+ TTF/OTFフォントを追加`から、ほかのフォントを追加・削除することもできます。ユーザーフォントはデータフォルダー内の`fonts/`へコピーされ、画面プレビューとPNG／PSD出力の両方で使用されます。バンドルフォントの出典とライセンスは、[third_party/fonts](third_party/fonts/README.md)をご覧ください。

### テキスト一覧と外部校正

- 現在のページまたは話全体から、`翻訳文 + OCR`、`翻訳文のみ`、`OCRのみ`をまとめて表示できます。
- 検索結果を順番に移動し、テキストをコピーしたりTXTとして保存したりできます。
- `翻訳文のみ`のTXTを再度読み込むと、ブロックの位置とOCR原文を維持したまま、行の順序に対応する翻訳文だけが更新されます。
- CSV/TSV校正表には、`block_id`、OCR原文、翻訳文、校正状態、メモを書き出します。
- 校正表を読み込むと、同じ`block_id`を持つ翻訳文・状態・メモだけが適用され、欠落・重複・OCRの不一致がある場合は警告が表示されます。
- ページ内のテキストは、原文言語の読み方向に合わせて並べ替えられます。

### インペインティングと結果出力

- `AOT 最小`：軽さと実行しやすさを優先する処理方式
- `LaMa 省メモリ`：マンガ向けの軽量な原文消去方式
- `Flux フル`：複雑な背景での品質を優先する処理方式
- 翻訳ブロックごとのインペインティング除外、境界の拡張、現在のページまたは残りのページの自動処理に対応しています。
- マスクブラシで再度消去する範囲を指定し、カラーブラシ・スポイト・復元ブラシで小さな跡を直接補正できます。
- 補正作業でも元に戻す・やり直しを利用できます。
- 選択したページを完成PNGまたはレイヤーPSDとして出力できます。PSDでは原本背景、補正済み背景、各テキストブロックを分離し、複雑な縦書き・曲線・遠近文字は見た目を保つラスターレイヤーになります。

### 共有と読み込み

`*.mgtshare`は完成したPNGやPSDではなく、アプリで再編集できる作品パッケージです。選択した作品・話の元画像、翻訳ブロック、座標、書式、インペインティング結果を含めることができますが、設定、ログイン情報、モデル、ログは含まれません。

読み込み時は、新しい作品を作成するか、既存の作品に話を追加・置換できます。適用前のマージ画面では、話をドラッグして順序を整理できます。著作権で保護された元画像を共有する場合は、必ず配布権限を確認してください。

## 言語と設定

### アプリ言語と翻訳言語

| 区分           | 用途                                     | 対応範囲                                                      |
| -------------- | ---------------------------------------- | ------------------------------------------------------------- |
| アプリ言語     | ボタン、メニュー、状態、エラーメッセージ | 한국어、日本語、English、简体中文、繁體中文                   |
| 原文・翻訳言語 | OCRとAIが読み取り、翻訳する言語ペア      | 48種類のプリセット、`eo`や`pt-BR`などのBCP 47コードを直接入力 |

設定画面は6つのタブに分かれています。

- `一般`：アプリの表示言語
- `翻訳エンジン`：言語ペア、Gemma/Codex/API、モデル、最大出力トークン数、コンテキスト長、APIの高度なリクエスト値
- `ハードウェア`：OCRの品質・デバイス、GemmaのGPUランタイム、インペインティングモデル・バックエンド
- `既定の書式`：新規ブロックの既定の方向、配置、フォント、サイズ、間隔、色、縁取り
- `ショートカット`：表示、翻訳、編集、インペインティング、グローバルコマンドのキー割り当て
- `確認/更新`：OCR・モデルの準備状況、アプリのバージョン、更新ページ、ログフォルダー

### 翻訳エンジンの比較

| エンジン     | 長所                                                                                             | 準備するもの                                                     |
| ------------ | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| Gemma 4      | ページとモデルがPC内で処理され、準備完了後はオフラインでも使用可能                               | GGUFモデル、PCに合ったCUDA/ROCm/Vulkanランタイム、十分なRAM/VRAM |
| OpenAI Codex | 内蔵の公式Codex App Serverとアプリ専用のChatGPTログインを使用し、APIキーを保存しない             | Codexを利用できるChatGPTアカウント、インターネット接続           |
| API          | OpenAI互換のビジョンモデル、ローカルサーバー、NVIDIA NIM、Gemini互換エンドポイントなどに接続可能 | Base URL、画像入力対応モデルの名前、必要に応じてAPIキー          |

モデル系統は`速度（推奨）`がデフォルトです。モデルサイズは自動的に次のように選択されます。

- VRAM 8GBクラス：`12B`
- VRAM 16GB以上（24GB以上を含む）：`26B`
- `31B`：高速なデフォルトより優先したい場合に手動で選択
- 特殊な構成：`カスタム`

OCR品質は`最小`、`省メモリ`、`フル`の3種類です。`フル`はPP-OCRv6 Transformersのセマンティック経路を使用し、対応GPUが必要です。CPUでは`省メモリ`から始めてください。

<details>
<summary><strong>OpenAI Codexエンジンの準備</strong></summary>

Codexエンジンは、アプリに内蔵されたOpenAI公式Codex App Serverを使用します。`設定 → 翻訳エンジン → Codex`で`ChatGPTでログイン`を押すとシステムブラウザーが開き、認証情報はこのアプリ専用のデータディレクトリにのみ保存されます。システムにインストールされたCodex CLIと`~/.codex`設定は使用せず、OpenAI APIキーを入力する必要もありません。

翻訳は読み取り専用の一時Codexスレッドで実行され、完了後に削除されます。一覧にないモデルは、`Custom`にモデルIDを入力できます。

公式ガイド：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Codexの認証](https://learn.chatgpt.com/docs/auth)

</details>

<details>
<summary><strong>OpenAI互換API、NVIDIA NIM、Gemini</strong></summary>

APIエンジンは、Base URLに`/chat/completions`を付けて画像とOCRヒントを送信します。選択するモデルは画像入力に対応している必要があります。

- 一般的なOpenAI互換サーバー：`https://server.example/v1`
- NVIDIA NIM：`https://integrate.api.nvidia.com/v1`
- GeminiのOpenAI互換エンドポイント：`https://generativelanguage.googleapis.com/v1beta/openai`
- LM Studioなどのローカルサーバーで認証が不要な場合は、APIキーを空欄にできます。

モデルIDとキーは各プロバイダーの画面で確認してください。`Temperature`、`top_p`、`top_k`、`reasoning_effort`、追加のrequest body JSON、custom headers JSONも設定できます。サーバーが未知の値を拒否する場合は、まず高度な設定値を空欄にして確認してください。

環境変数で値を上書きすることもできます。

- OpenAI公式キー：`OPENAI_API_KEY`
- 互換サーバー：`MANGA_TRANSLATOR_API_BASE_URL`、`MANGA_TRANSLATOR_API_MODEL`、`MANGA_TRANSLATOR_API_KEY`

</details>

<details>
<summary><strong>NVIDIAとAMDの処理方式</strong></summary>

| 処理       | NVIDIA                        | AMD                 | ユーザーが選択する代替手段 |
| ---------- | ----------------------------- | ------------------- | -------------------------- |
| Gemma      | CUDA 12、RTX 50専用ランタイム | ROCmまたはVulkan    | より小さいモデルプリセット |
| Paddle OCR | NVIDIA CUDA                   | 対応GPUでのAMD ROCm | CPU 最小/省メモリ          |
| Flux       | NVIDIA CUDA                   | ZLUDA + AMD HIP SDK | CPU                        |

AMD版Gemmaは、GPUとドライバーに合ったROCm targetを自動で検出します。自動検出が正しくない場合、上級ユーザーは次のように指定できます。

```powershell
$env:MANGA_TRANSLATOR_AMD_ROCM_TARGET = "gfx110X"
```

AMD ZLUDAインペインティングには、[Windows向けAMD HIP SDK](https://www.amd.com/en/developer/resources/rocm-hub/hip-sdk.html)が必要です。OCRのGPU処理が失敗した場合、アプリは作業を中止してエラーを表示します。CPUで続行するには、設定でOCRデバイスをCPUへ明示的に変更してください。Gemmaは引き続きAMD GPUを使用できます。

</details>

## データの保存場所

インストール時に指定したデータフォルダーの下に、ユーザーの作業データと容量の大きいランタイムを分けて保存します。

```text
data/
  settings.json
  library/
  logs/
  fonts/
  hf-cache/
  llama.cpp/
  ocr-runtime/
  models/
  tmp/
  panel-window-bounds.json
```

- `library/`には、作品、話、ページ、ブロックのデータが保存されます。
- `fonts/`には、ユーザーが登録したTTF/OTFが保存されます。
- `hf-cache/`、`llama.cpp/`、`ocr-runtime/`、`models/`には、ダウンロードしたモデルとランタイムが保存されます。
- `logs/`には、現在の実行の`app.log`と直前の実行の`previous.log`があります。元のログにはローカルパスや作品に関する内容が含まれる場合があるため、そのまま公開しないでください。
- アプリをアンインストールするときは、作品データとモデル/OCRキャッシュを削除するかどうかを個別に選択できます。

大切な作品は、データフォルダーをバックアップするか、`*.mgtshare`として書き出してください。

## よくある質問

### 初回起動や翻訳に時間がかかりすぎます

初回起動時は、モデル・Python・OCR・インペインティングのランタイムをダウンロードし、検証する時間が含まれます。準備完了後も遅い場合は、より小さいGemmaプリセット、CPUの`省メモリ`OCR、AOT/LaMaインペインティングから試してください。複数のGPU処理やゲーム、ブラウザーが同時にVRAMを使用しないようにすることも有効です。

### Codexに接続できません

`設定 → 翻訳エンジン → Codex`で`ChatGPTでログイン`を押し、ブラウザー認証を完了してから`OCR/モデルを確認`を実行してください。Codex CLIのインストールやターミナルでの別途ログインは不要です。引き続き失敗する場合は、アプリのログで内蔵Codex App Serverの起動エラーを確認してください。OCRの準備失敗がCodexの接続問題のように見えることもあるため、結果ログでどの段階が失敗したかも確認してください。

### APIで401、403、404エラーが発生します

APIキー、Base URL、モデルIDを確認します。通常、Base URLには`/v1`までを入力し、画像入力に対応したモデルを使用する必要があります。プロバイダーが対応していない高度なリクエスト値やJSONを空欄にしてから、もう一度試してください。

### AMD GPUでのOCRに失敗します

Windows版ROCmは、対応GPUとドライバーの組み合わせに影響されやすい仕組みです。OCRデバイスだけをCPUに変更しても、Gemma翻訳は引き続きAMD GPUで実行できます。内蔵GPUの同時検出、VRAM不足、Windows TDRについてもログで確認してください。

### AMD ZLUDAインペインティングに失敗します

Windows向けAMD HIP SDKと`HIP_PATH`を確認し、アプリを再起動してください。すぐに作業を続けたい場合は、FluxのバックエンドをCPUに変更するか、AOT/LaMa方式を使用してください。

### RTX 50シリーズでOCRに失敗します

最新のNVIDIAドライバーと、アプリのRTX 50向けOCRランタイムを確認してください。GPU OCRが引き続き失敗する場合は、OCRだけをCPUの`省メモリ`に変更して翻訳を続けられます。

### 出力結果のフォントが画面表示と異なります

バンドルフォントは、画面表示とPNG／PSDの両方に含まれます。ユーザーフォントのファイルを削除した場合や、作品を別のPCで開いた場合は、そのフォントをもう一度登録してください。出力前に、文字方向、自動フィット、太さ、フォントの一括適用状態も確認してください。

## 問題を報告するとき

翻訳・分析処理が失敗した場合や、アプリで予期しないエラーが発生した場合は、`エラーを報告`ダイアログが開きます。あとから報告する場合は、`Ctrl+K`のコマンドパレットで`問題を報告`を選択してください。

ダイアログから[GitHub Issues](https://github.com/ucx0204/CarrotMangaTranslator/issues)へ報告する手順は次のとおりです。

1. エラー直前に行った操作を入力し、自動生成されたMarkdownのプレビューを確認します。
2. 共有したくない場合は、システム情報またはサニタイズ済みエラーログを報告から除外します。
3. `GitHubでIssueを作成`を選ぶと、システムブラウザーで入力済みの新規Issueが開きます。報告がURLに収まらない場合は、診断情報がクリップボードにコピーされるため、Issue本文へ貼り付けてください。
4. 公開してはいけない内容が残っていないか再確認し、GitHub上で自分で送信します。

アプリがエラー報告を自動アップロードしたり、GitHub Issueを自動送信したりすることはありません。共有用の診断情報では、APIキー、認証ヘッダー、ホームディレクトリのパス、作品テキストなどの機密になり得る値を自動的に隠しますが、すべてを確実に検出できるとは限りません。必ずプレビューを確認してください。

元の`app.log`と`previous.log`は共有用診断情報より詳細で、サニタイズされていません。追加調査のために元のログが必要な場合は、`ログフォルダーを開く`から確認し、パス、トークン、作品内容を手動で削除したコピーだけを添付してください。
