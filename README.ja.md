# Carrot Manga Translator

**OCR → 翻訳 → 原文消去 → 写植・校正 → 書き出し**を一つの画面で行うデスクトップアプリです。自分で用意した原稿を読み込み、ローカル Gemma・Codex・OpenAI 互換 API で翻訳できます。

## まずは1ページ完成させる

1. **[インストール](#install)**後、**設定 → AI → 翻訳**で原文・翻訳先の言語とエンジンを選びます。
2. **[OCR・画像設定](#setup)**を確認し、**確認/更新 → OCR/モデル確認**を実行します。
3. **[原稿を追加](#import)**から画像やフォルダーを読み込みます。
4. 話を開き、**[翻訳設定](#translate)**で1ページを選びます。最初は**翻訳のみ**で試してください。
5. **[OCR・訳文を修正](#edit)**し、**[原文消去](#erase)**と**吹き出しに合わせる**で整えます。
6. **[結果を書き出す](#export)**と完成画像を保存できます。設定が合ったら残りのページを処理します。

## インストール

| 環境              | ファイルと手順                                                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Windows 10/11     | リリースの **Setup EXE**を実行し、データフォルダーを指定します。                                                                    |
| Apple Silicon Mac | **arm64 DMG または ZIP**をダウンロードし、アプリを**アプリケーション**へ移動します。macOS 14以降が必要です。Intel Macは非対応です。 |

OSの警告が出たら、そのリリースの署名情報とチェックサムを確認してください。Macの初回起動の許可は**システム設定 → プライバシーとセキュリティ**で行えます。[署名ポリシー](CODE_SIGNING_POLICY.md)

モデルとランタイムは別途ダウンロードするため、追加の空き容量が必要です。初回準備にはインターネット接続が必要です。必要なファイルが揃えばローカル Gemma・OCR・インペインティングはローカルで動作します。Codex・外部API・Web調査には接続が必要です。

## 言語とAIの設定

**画面の表示言語**は**設定 → 一般**、**原文と翻訳先の言語**は**設定 → AI → 翻訳**で個別に指定します。

![翻訳エンジン・言語・Codexアカウント](docs/images/readme-v2712/settings-translation.png)

| エンジン           | 必要なもの                       | 選択後の確認                                                                  |
| ------------------ | -------------------------------- | ----------------------------------------------------------------------------- |
| **Gemma ローカル** | モデル容量、RAM/VRAM             | プリセットとランタイム。端末に合う小さなプリセットから試します。              |
| **Codex**          | アプリ内でChatGPTにログイン      | 利用できるモデルと推論強度。サーバー同梱のためCodex CLIの別途導入は不要です。 |
| **API**            | Base URL、モデルID、必要ならキー | OpenAI互換性と画像入力対応。互換ローカルサーバーも利用できます。              |

**AI内の各タブは別の処理を設定します。** 翻訳エンジンを変えてもOCR・消去・Codex画像処理・Web調査がすべて一緒に変わるわけではありません。

| AI内のタブ       | 設定内容                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| **翻訳**         | 言語、Gemma/Codex/API、生成上限                                                                              |
| **OCR**          | HayaiOCR/PaddleOCR、対応デバイス。検出や読み取りが悪い場合は同じページで比較します。                         |
| **画像**         | **AOT / LaMa / Flux**による消去と対応バックエンド、専用の**Codex画像モデル・推論強度**、送信画像のマスキング |
| **Web調査**      | アカウント・キー、検索結果を分析するモデル、使用上限                                                         |
| **ハードウェア** | アプリ描画GPU、ローカルAI計算GPU、検出端末の推奨値。描画GPU変更後は保存して再起動します。                    |

<details>

- **生成上限:** 出力トークン数は応答の長さ、作品情報予算は参照できる文脈量に関係します。大きくすれば必ず品質が上がるわけではありません。

## 原稿の読み込みとライブラリ

構成は**作品 → 話 → ページ → ブロック**です。作品には共通の用語・キャラクター、話にはページ、ページには原稿・翻訳ブロック・補正画像が入ります。ブロックはセリフ・ナレーション・効果音のまとまりです。

**原稿を追加**からソースを選び、プレビューで順序と除外対象を確認して、新規作品または既存作品の新しい話として追加します。複数回分は**複数話を追加**を使います。ファイルやフォルダーをドラッグしても読み込めます。

![読み込み元の選択](docs/images/readme-v2712/import.png)

| 原稿                               | 読み込み方                                        |
| ---------------------------------- | ------------------------------------------------- |
| PNG・JPEG・WebP                    | 画像または画像フォルダーを選択                    |
| ZIP・CBZ・RAR・CBR                 | 圧縮ファイルを選び内部画像を確認                  |
| PDF                                | 各ページを画像として読み込み                      |
| 複数話入りフォルダー・圧縮ファイル | 複数話の読み込みで区切りと順序を確認              |
| Webページ                          | 画像一覧を取得し、サイズで絞って必要な画像を選択  |
| `.mgtshare`                        | **作業を読み込む**で編集作業を復元。[共有](#data) |

ライブラリ検索で作品・話を探し、ページ一覧で処理状態と順序を確認します。破損・非対応ファイルの除外結果も確認してください。サイトのログインやアクセス制限で取得できない場合は、自分で用意したファイルを使用します。

## 翻訳・再開・再翻訳

話を開いて**翻訳設定**または`T`を押します。作品内の話・ページを選び、**未翻訳のみ**で残りを絞り込めます。

![翻訳範囲と写植・原文消去の設定](docs/images/readme-v2712/translate.png)

| 選択肢                  | 動作                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------ |
| **高速1回**             | 各ページを1回翻訳し、簡潔な直近文脈を参照します。                                          |
| **累積コンテキスト**    | 場面・用語・人物情報を蓄積します。詳細・バランス・必須用語のみから記録範囲を選びます。     |
| **自動生成**            | テキスト領域を再検出します。                                                               |
| **既存ブロックを維持**  | 領域と書式を残してテキストを更新します。ブロックのないページでは自動生成します。           |
| **自然な改行**          | ブロックに合わせて訳文そのものに改行を入れます。手動改行を残したい場合は注意してください。 |
| **AI文字サイズ調整**    | 原文の文字サイズを推定します。                                                             |
| **フォント自動調整**    | 原文に合う**韓国語フォント**をブロックごとに適用します。サイズ調整とは別です。             |
| **翻訳のみ / 原文消去** | 翻訳だけで終了するか、消去まで続けるかを指定します。                                       |
| **吹き出しに合わせる**  | 消去後に吹き出し内部へ訳文を配置します。                                                   |
| **Codexで消去**         | 利用可能な条件でCodex画像処理を使います。[画像設定](#setup)も確認してください。            |

よく使う組み合わせは次回の既定値として保存できます。`Shift+T`で残りのページを再開します。進捗と失敗理由を確認し、完了分を無条件にやり直さず未完了の範囲を選びます。

**再翻訳では手動修正や既存結果が置き換わることがあり、作業画面の元に戻す履歴には入りません。** 残したい編集は先に[作業を書き出す](#data)で保存してください。処理中ページの編集は制限されますが、ロックされていない別ページは編集できます。話全体を変更する操作は、その話の処理状態に応じて制限されます。

## 作業画面の使い方

左は**ライブラリ・ページ**、中央は**原稿**、右は**ページのブロック・選択ブロックの編集**です。パネルを畳むと原稿を広く表示できます。原稿の文字または一覧項目を選んで編集します。

| 操作                   | 方法                                                                |
| ---------------------- | ------------------------------------------------------------------- |
| ページ移動             | サムネイル、`PageUp` / `PageDown`                                   |
| 原稿の移動             | 手のひらツール`H`または`3`でドラッグ                                |
| 拡大・縮小             | `Ctrl+ホイール`、倍率操作。全体・幅・高さに合わせる、実寸も選択可能 |
| 原稿と比較             | `O`で原稿表示を切り替え                                             |
| 訳文表示               | `V`でブロック、`Shift+B`で編集用背景・枠を切り替え                  |
| ブロック追加           | `W`または`2`で領域をドラッグ                                        |
| 選択・移動・サイズ変更 | `S`または`1`、ブロックとハンドルをドラッグ                          |
| 複数ブロック           | 複数選択、`Ctrl+A`で現在ページの全選択                              |
| 読み順                 | 一覧の上下ボタン、`Ctrl+Alt+↑/↓`、座標順並べ替え                    |

選択色や編集枠は完成画像と区別してください。拡大表示とページ全体の両方で改行とバランスを確認します。

## セリフと写植を整える

### テキスト：まずOCRを確認

ブロックの**テキスト**タブで原文と訳文を比較します。名前・数字・記号の誤読は原文から直し、必要な領域を再翻訳します。役割・話者・校正状態・メモは一括編集や校正にも使います。

![選択ブロックのテキスト編集](docs/images/readme-v2712/editor-text.png)

訳文の一部を選択すると、その文字だけに太字・斜体・フォント・サイズ・色・不透明度・背景・縁取り・光彩を設定できます。未選択時は今後入力する文字に適用されるか表示を確認してください。**コード**表示で書式表現を直接編集できます。**書式をすべてリセット**すると文中の部分書式が消えます。

### 配置：吹き出しに収める

| 調整                  | 用途                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------- |
| 位置・サイズ・回転    | ブロックを移動・変形。回転リセットは`Ctrl+Shift+T`。                                      |
| 横/縦・整列・折り返し | 原稿と吹き出しに合わせます。手動改行と自動折り返しは別です。                              |
| 吹き出し合わせ        | 内側に合わせて配置。多角形や拡張・削減ブラシで形を編集でき、解除するとOCR領域に戻ります。 |
| 曲線・遠近・ワープ    | 曲がったセリフや効果音をハンドルで調整し、プレビューで確認します。                        |

### 書式：文字の形と間隔

**書式**タブでフォント・サイズ・太字・斜体・整列・色・縁取り・光彩・行間・字間・文字幅・不透明度を調整します。一部分だけ違う場合は、その部分の書式も確認します。

**一括適用**では選択・ページ・話の範囲と書式グループを指定します。色だけをコピーする際に文字サイズまで変えないよう、項目を確認してください。[配置](docs/images/readme-v2712/editor-layout.png) · [書式](docs/images/readme-v2712/editor-format.png)

## フォント・書式・ブロックの再利用

| 機能                   | 保存内容             | 使い方                                                                                     |
| ---------------------- | -------------------- | ------------------------------------------------------------------------------------------ |
| **既定の書式**         | 新規ブロックの初期値 | 設定 → 既定の書式。既存ブロックは別途適用します。                                          |
| **書式プリセット**     | 選んだ書式グループ   | 現在の書式から作成し、名前と項目を指定。クイック書式に固定し`Alt+1`～`Alt+0`へ割り当て可能 |
| **ブロックライブラリ** | 再利用する文と書式   | ブロックメニューから保存。名前・原文・訳文で検索し現在ページへ挿入                         |
| **フォント管理**       | 登録フォントと表示順 | TTF/OTF登録、お気に入り、非表示、並べ替え、既定フォント指定                                |

プリセットは名前変更・グループ整理・現在書式で上書きできます。ライブラリ内のブロックは内容も編集できます。別PCでフォントが見つからない場合は同じフォントを登録するか代替を選びます。翻訳時の自動フォント調整とプリセット保存は別機能です。

[既定の書式](docs/images/readme-v2712/settings-format.png)

Codex ImageGenの効果音も**ブロックライブラリ**へ保存できます。画像・マスク・フォントの太さを保ち、別ページで再利用できます。選択したテキスト・画像ブロックは`Ctrl+C` / `Ctrl+V`でページ・話・作品の間でコピーできます。

## 原文消去と手動補正

**自動消去 → 消し残しの補正 → 原稿比較**の順で進めます。自動消去はブロックの原文領域から背景を復元します。残したい文字はブロックメニューで**自動消去から除外**します。

![補正ツールと原稿](docs/images/readme-v2712/retouch.png)

| ツール                               | 動作                                                                   |
| ------------------------------------ | ---------------------------------------------------------------------- |
| **自動消去** / `I`                   | ページを選び設定モデルで消去。後続の吹き出し合わせも選択可能           |
| **マスク** / `J`                     | 消す領域を塗り、適用して背景を復元                                     |
| **ブラシ** / `B`                     | 選択色で塗る。平坦な背景の小さな跡に便利                               |
| **矩形** / `R`、**楕円** / `E`       | ドラッグした形を選択色で覆う                                           |
| **消しゴム** / `X`、**矩形消しゴム** | 領域を**原稿のピクセルへ復元**。消去マスクを消すツールではありません。 |
| **色抽出** / `P`                     | 原稿から描画色を取得                                                   |

ブラシ・矩形・楕円では**`Alt+左クリック`で色抽出**できます。描画ツールの`Alt+右ドラッグ`は半径調整です。ブラシを直線にするには`Shift`ドラッグを使います。対応するツール状態では`Space`でマスクを適用できます。

矩形・楕円・矩形復元には、明暗どちらの原稿でも見える白黒二重線の固定十字カーソルを使います。誤操作は元に戻す、原稿ピクセルを戻すには消しゴムを使います。[自動消去画面](docs/images/readme-v2712/erase.png)

## 効果音を確認して翻訳する

大きな効果音はフォントの置き換えだけでは筆致や迫力を失いがちです。**Codex ImageGen**で文字画像を翻訳し、セリフは編集可能なテキストとして残せます。

| 日本語の原稿                                                                              | 韓国語のセリフ＋効果音画像                                                                             |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| <img src="docs/images/readme-v2712/comparison-before.png" alt="日本語の原稿" width="430"> | <img src="docs/images/readme-v2712/comparison-after.png" alt="韓国語のセリフ＋効果音画像" width="430"> |

大きな「ドン」を筆文字の「쾅」に変更しました。セリフは原文を消した位置にテキストブロックを配置しています。比較にはCodex内蔵imagegenで用意した素材と、アプリの実際の文字描画処理を使用しました。[制作方法](docs/images/readme-v2712/README.md)

HayaiOCRの効果音候補はセリフとは別に確認できます。**効果音翻訳**を開き、ページごとに候補を含める/除外します。絵の誤検出は除外し、見落としは領域を追加・修正してください。

![効果音候補と翻訳方法](docs/images/readme-v2712/sfx.png)

1. 認識された原文と領域を確認します。
2. 編集可能な**テキスト**か**Codex画像**を選びます。画像には専用のCodex画像設定を使います。
3. 画像方式は訳文を先に確認し、**全ページ確定後に生成**します。画像になる前に表現を整えます。
4. 原稿と比較します。テキストは通常ブロックとして、生成文字は画像編集・復元機能で調整します。

単独領域の翻訳は原文を残します。消去は効果音全体の翻訳オプションで選択します。**初期化**で削除・除外候補を再表示でき、領域修正と訳文は維持されます。

画像処理の再開時、マスキングと効果音が重なるページは**訳文を保存したまま画像処理を保留**します。他ページは続行します。マスキングを修正して再開すると未完了画像を処理します。[マスキング](#redaction)

<a id="redaction"></a>

## 送信画像の一部を隠す

**設定 → AI → 画像 → 送信画像のマスキング**で有効にします。対応するAI画像処理で**送信するコピー**を隠すもので、原稿ファイルを塗る機能ではありません。

ページ・話・作品単位の**マスキング準備**で領域を確認・修正します。自動判定は自分で確認してください。翻訳・生成対象の文字まで隠すと処理できないため、重なりを調整します。原文消去とは用途が異なります。

画像を隠しても、リクエスト内のOCRテキストや作品文脈がすべて除去されるわけではありません。利用エンジンと[プライバシーポリシー](docs/privacy-policy.md)で送信内容を確認してください。

<a id="context"></a>

## 用語・記憶で名前と口調を揃える

右側の**用語/記憶**を開きます。同じ作品の複数話で共通情報を維持する機能です。

![用語集と作品の文脈](docs/images/readme-v2712/context-glossary.png)

| タブ                 | 記録する内容                           | サンプル原稿の例                             |
| -------------------- | -------------------------------------- | -------------------------------------------- |
| **用語集**           | 原文・訳語、別名、分類、メモ、有効状態 | `侍従長 → 시종장`                            |
| **キャラクター**     | 名前、別名、口調、人物メモ             | セラフィナ：落ち着いた敬語で残酷な命令を出す |
| **翻訳規則**         | 敬称、効果音処理、基本の調子           | 敬称維持、効果音翻訳                         |
| **ストーリーメモリ** | ページごとの場面要約・視覚情報         | 冷めた紅茶を理由に処刑を命じ、宮廷が静まる   |

手動入力か**AI用語/記憶**の分析結果を確認して整えます。翻訳で蓄積された情報も編集できます。重複した名前・別名を整理して保存します。[人物](docs/images/readme-v2712/context-characters.png) · [規則](docs/images/readme-v2712/context-rules.png) · [物語](docs/images/readme-v2712/context-memory.png)

<details>
<summary>Web調査・提案の確認・文脈予算</summary>

**Web調査**は作品名・エンジン・範囲を確認して外部情報を補います。調査用タイトルはライブラリ名とは別です。Codex調査とTavily検索＋LLM分析ではアカウント・キー・上限が違うため、**設定 → AI → Web調査**を確認します。

提案された用語・人物・規則を出典と既存内容と比較し、必要なものだけ適用します。検索結果は誤りや別作品の情報を含むことがあります。外部資料のない自作サンプルは手入力で構いません。

情報が増えたら予算表示を確認し、必要な内容を優先します。保存競合時は他の変更を確認して最新状態を開き直します。**用語・記憶の全初期化**は作品の用語集・人物・全話の物語記憶を削除するため、通常の整理の代わりには使わないでください。

</details>

<a id="batch"></a>

## 文と書式の一括編集

`Ctrl+H`で開き、**範囲 → 条件 → 操作 → 変更前後の確認 → 適用**と進めます。現在ページで確認してから話全体に広げると間違いを減らせます。

![条件・操作と原稿上の変更前後](docs/images/readme-v2712/batch.png)

原文・訳文だけでなく役割・話者・校正状態などで絞れます。**すべて一致**と**いずれか一致**を区別してください。**全吹き出し**は範囲内の全ブロックを対象とします。置換・書式や項目変更・部分強調を実行順に組み立てます。

### 例：セラフィナだけを丁寧な表現にする

1. **話者 = セラフィナ**、**訳文に`처형했습니다`を含む**の両方を条件にします。
2. `처형했습니다`を、より改まった`처형하였습니다`に置換します。
3. 置換後の`처형하였습니다`だけを太字にします。
4. 侍従のセリフが変わらないことを確認して適用します。

話者条件には正しい話者の割り当てが必要です。IDは作品ごとに異なるためサンプルIDをそのまま流用しないでください。

<details>
<summary>ほかの用途と規則の保存</summary>

- **三点リーダー・空白:** 初期規則で`...`を`…`へ、連続空白を一つへ置換します。
- **効果音書式:** 効果音の役割だけに太さ・サイズ・縁取りを設定します。
- **校正マーク:** 空の訳文や特定表現を探して校正状態・メモを変更します。
- **正規表現:** 通常検索で足りない場合に使います。大文字小文字と全置換も確認します。
- **結果の除外:** 条件に合っても変更したくない項目は除外。原稿上の前後比較と適用数を確認します。
- **再利用:** 名前を付けてYAMLに保存します。複数規則を順番に実行するシーケンスでは、前段の結果が次段の入力になります。
- **競合:** プレビュー後に変わったブロックは上書きせずスキップします。最新状態で再計算してください。直前の一括編集は元に戻せます。

</details>

<a id="review"></a>

## セリフをまとめて読む・校正する

`G`で**テキスト一覧**を開き、OCRと訳文の両方または片方を表示して検索できます。ページ見出しから原稿へ移動し、ブロックを選んで変更した書式項目だけをまとめて適用することもできます。

![OCRと訳文の一覧](docs/images/readme-v2712/gather.png)

| 形式             | 対応方法                       | 注意点                                                      |
| ---------------- | ------------------------------ | ----------------------------------------------------------- |
| コピー / TXT保存 | 現在の表示内容                 | ページ見出しの有無を選択                                    |
| TXT読み込み      | **訳文のみ**で保存した行の順序 | 並べ替えると対応がずれます。警告と件数を確認                |
| CSV / TSV校正表  | `block_id`                     | 訳文・校正状態・メモのみ反映しOCRは変更しません。ID列を保持 |

外部表計算ソフトでは校正表を使うと対応を維持しやすくなります。元の書き出しを保存し、不明ID・重複・欠落などの警告を確認してから反映します。

<a id="export"></a>

## 完成画像とPSDを書き出す

**結果を書き出す**または`Ctrl+E`で話・ページを選びます。事前確認に未翻訳・失敗・後処理未完了があれば、そのページへ戻って確認します。

![出力範囲・形式・保存方法](docs/images/readme-v2712/export.png)

| 出力                             | 用途と設定                                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **原稿形式 / PNG / JPEG / WebP** | 完成画像を合成。JPEG/WebP品質、元ファイル名・下位フォルダーの維持を指定                                                                                |
| **文字なし**                     | 訳文を合成せず消去済み背景を保存。消去結果が必要                                                                                                       |
| **レイヤーPSD**                  | 原稿・消去背景・ブロック文字を分離。対応する文字は編集可能、複雑な縦書き・曲線・遠近・部分書式などは見た目を保つラスターレイヤーになる場合があります。 |

新しい日時付きフォルダーか指定先への直接保存を選び、同名ファイルの**置換 / スキップ / 中止**を確認します。画像出力と[作業共有](#data)は異なります。PSDもアプリの編集状態を完全復元するバックアップではありません。[PSD画面](docs/images/readme-v2712/export-psd.png)

<a id="autosave"></a>

## 編集結果を自動保存する

**設定 → 結果の自動保存**で作品・話の接続先と出力形式を管理します。編集に合わせて外部の結果フォルダーを更新したい場合に使います。接続先と状態を確認し、失敗・待機項目は状態表示から再処理します。

![作品ごとの結果自動保存](docs/images/readme-v2712/settings-results.png)

`result`は完成画像、`originals`は復元用原稿、`inpainted`は消去画像、`mask`は消去領域です。アプリの編集データ保存とは別機能です。接続を切る・形式を変える前に保存先を確認し、キャッシュのように削除しないでください。

<a id="data"></a>

## 共有・バックアップ・プライバシー

**作業を書き出す**で作品と話を選び`.mgtshare`へ保存します。別PCの**作業を読み込む**で新規作品を作るか、既存作品へ話を追加・置換できます。最終一覧と順序を確認して適用します。

| 作業ファイルに含む                             | 別途準備するもの                                                                                |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 原稿画像、ブロック・読み順・書式、消去結果など | アプリ設定、ChatGPTログイン/APIキー、AI/OCRモデル・ランタイム、ログ。必要フォントも移行先で確認 |

環境全体を残すにはアプリを終了して**データフォルダーをバックアップ**します。`library`は原稿と編集データであり、削除可能なキャッシュではありません。設定・フォント・ログ・モデルキャッシュと区別し、原稿と出力も保管します。macOSの既定値は`~/Library/Application Support/manga-gemma-translator`です。

外部エンジンには処理に必要な画像・文字・文脈が送られる場合があります。ログにもパスや原稿の一部が入るため共有前に確認してください。エラー報告は自動送信されません。[プライバシー](docs/privacy-policy.md) · [セキュリティ](SECURITY.md)

<a id="troubleshooting"></a>

## 困ったとき

| 症状                       | 最初に確認すること                                                  |
| -------------------------- | ------------------------------------------------------------------- |
| 翻訳が始まらない           | ページ選択 → 言語・エンジン → ログイン/キー/モデル → OCR/モデル確認 |
| 初回が遅い                 | ダウンロード・検証状況。準備後に代表1ページで比較                   |
| メモリ不足・GPUエラー      | 小さいGemma、推奨端末設定、CPU OCR、軽い消去モデルを個別に試す      |
| OCRの結合・分割が不適切    | 原文言語、HayaiOCR/PaddleOCR比較。修正後は既存ブロック維持で再翻訳  |
| 名前や口調が揺れる         | 用語集・人物・累積文脈、既訳には話者条件の一括編集                  |
| 文字がはみ出す・小さすぎる | 領域・方向・改行・サイズ・文字幅、部分書式、吹き出し合わせ          |
| 消去で絵が壊れる           | 元に戻す/原稿復元、除外ブロックとマスク範囲、別モデル               |
| 効果音画像が保留           | マスキングの重なりを直して画像処理を再開                            |
| 保存・一括適用が競合       | 最新状態を開き直して比較し、他の変更を上書きせず反映                |
| Codex接続失敗              | アプリ内ログイン・モデル一覧、ログ内の同梱サーバーエラー            |
| API 401/403/404            | キー・URL・モデル・画像対応、非対応パラメーターの削除               |
| 出力フォントが違う         | フォント不足・登録状態、PSDラスタライズ対象か確認                   |

再現する場合は**設定 → エラー報告**を確認し、[Issue](https://github.com/ucx0204/CarrotMangaTranslator/issues)にバージョン・OS・エンジン・手順・期待結果と実際の結果を書いてください。キー・個人パス・原稿内容は共有前に確認します。
