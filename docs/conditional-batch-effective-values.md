# 일괄 편집의 표시값 판정과 크기 적용

2026-09-05 수정 기록.

## 판정 계약

조건은 편집기에 표시되는 말풍선 속성을 비교한다. `fontSizePx`의 저장값은 자동 맞춤의
기준값일 수 있으므로 렌더러가 실제 캔버스와 서식 패널의 자연 페이지 크기 계산을
엔진에 전달한다. 글꼴 로드가 끝나기 전에는 미리보기와 적용을 활성화하지 않는다.
페이지별 원문 크기 fallback도 같은 계산을 사용하며 모델·OCR 알고리즘은 변경하지 않는다.

- 글자 크기와 그 크기로 계산되는 자동 외곽선 두께는 실제 페이지 px를 사용한다.
- 생략된 자간·장평·회전·불투명도·줄바꿈·외곽선·색·그림자·광채 속성은 기존
  프로덕션 기본값/정규화 계약을 사용한다. 분석 신뢰도나 검수 메타데이터가 없는 경우는
  계속 미지정으로 취급한다.
- 말풍선 비율은 실제 너비/높이다. 정규화 좌표와 픽셀 좌표로 저장한 동일한 영역은
  같은 비율로 판정한다.
- 미리보기의 변경 전/후 표시도 같은 reader를 사용한다. 충돌 검사는 저장값과 자동
  맞춤·배치 메타데이터까지 별도로 비교한다.
- 말풍선 기본 서식과 번역문 안의 부분 서식은 기존처럼 별도 조건/작업이다.

## 적용 계약

- `setFields`에서 글자 크기를 지정하면 원문 크기 맞춤을 해제하고 수동 크기로 고정한다.
  같은 작업에서 자동 맞춤을 명시했다면 그 값을 따르며 필드 순서에 영향을 받지 않는다.
- 크기 지정 없이 자동 맞춤만 끄면 현재 표시 크기를 보존한다.
- 크기 프리셋도 원문 크기 맞춤을 해제한다. 프리셋의 자동 맞춤 기본값/명시값은 기존
  프리셋 계약을 유지한다.
- 숫자가 같아도 원문 맞춤 해제 또는 자동 배치 방향 해제는 실제 변경이다.
- 선택·페이지·화 범위, 연속 실행, 결과 제외, 충돌 건너뛰기는 동일 엔진을 사용한다.
  각 단계와 실제 적용 시점에 최신 값을 다시 판정한다.
- 저장 규칙의 YAML 스키마는 바뀌지 않았다. 보관함을 일괄 마이그레이션하지 않는다.

## 회귀 검증

### 2026-09-12 화자별 글꼴 적용

일괄 편집에서 범위를 고른 뒤 **대상 조건 → 화자 → 같음**을 선택한다. 화자 이름을
검색해 고르고 **작업 → 속성 바꾸기 → 글꼴**에서 적용할 글꼴을 선택한다. 미리보기의
대상을 확인한 뒤 적용한다. 다른 화자는 별도 규칙으로 저장해 같은 방식으로 적용할 수 있다.

`speakerId`는 대사와 작품의 `characters[].id`를 연결하는 내부 값이다. 화면에서는
번역 이름을 표시하고 표시 이름·원문 이름·별칭으로 검색한다. 인물 정보와 현재 화에
연결된 화자를 함께 나열하며 대사 개수도 표시한다. 이름이 같은 인물은 ID로 구분하고,
인물 정보가 없어진 기존 ID도 보존한다. 인물 등록만으로 기존 대사에 화자가 자동 배정되지는
않는다. 화자 미지정 대사는 **비교 → 비어 있음**으로 찾을 수 있다.

새 화자 조건은 정확히 같은 ID를 비교한다. 이전 규칙의 포함·패턴 비교는 자동 변경하지
않으며, 이름으로 고르려면 비교를 **같음** 또는 **다름**으로 바꾼다. 속성 바꾸기의 화자
지정에도 같은 검색 목록을 사용한다. YAML 저장 형식과 실제 판정·적용 엔진은 유지한다.

`conditionalBatchSpeakers.test.tsx`는 별칭 검색, ID 접두사가 같은 다른 화자의 제외,
실제 글꼴 적용, 미등록 ID·동명이인·그룹 조건·기존 비교·지정 해제를 검증한다.
`conditionalBatchGlossaryReadiness.test.tsx`는 작품 변경과 늦은 조회 응답에서도 화자
목록이 섞이지 않는지 함께 검증한다. 실제 편집기와 검색 목록을 1600×980, 1240×760,
620×760에서 캡처해 외부 스크롤·잘림·겹침을 확인했다.

새 화자 UI 파일 두 개의 커버리지 기준은 `.tmp/speaker-coverage/coverage-summary.json`
(SHA-256 `bd866a039000bbf6a92fc61b3ed8c42b48fcc515455789f9a21d3032add10830`)의
실측값으로 등록했다. 기존 파일의 기준은 낮추지 않았다.

### 글자 크기와 표시값

`conditionalBatchTypography.test.ts`는 저장값과 표시값의 차이, 동일 숫자에서 자동 맞춤
해제, 프리셋, 자동 맞춤 값의 순서, 표시 크기 고정, 충돌과 연속 실행/제외를 검증한다.
`conditionalBatchFieldValues.test.ts`는 기본 서식 20종과 자동 외곽선, 좌표 단위의 동등성을
검증한다. 기존 일괄 편집·서식·캔버스 글꼴 준비 테스트도 함께 실행한다.

실제 화면 검증은 4화 35쪽/152개 블록의 **보관함 복사본**으로 진행했다. 사용자가
수정한 현재 값을 과거 일괄 편집 결과로 간주하지 않았다. 재현을 위해 복사본의
`008.jpg` 한 블록과 `009.jpg` 두 블록에만 원문 자동 맞춤 상태를 복원했다.
원본 보관함 파일에는 이 복원이나 QA 적용을 저장하지 않았다.

실제 번들 글꼴을 불러온 Chromium에서 재현 크기는 13px, 21px, 23px였다. 저장 기준값으로는
대상 0개, 표시값 기준으로는 대상 3개였다. 세 항목을 25px로 적용한 뒤 작은 항목은
0개였고, 그 외 25px 이상 수동 크기 34개는 유지됐다. 넓은 1600×980과 좁은 1240×760
화면에서 실제 production 일괄 편집 컴포넌트를 캡처하고 외부 스크롤·잘림·겹침을 확인했다.
임시 QA 엔트리와 캡처 이미지는 확인 후 제거했다.
