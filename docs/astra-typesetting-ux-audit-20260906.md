# Codex delegation audit — 2026-09-06

This document describes the current worktree implementation after the earlier v0.5 experiments. Earlier reports that describe automatic geometry repair or repeated quality retries are historical, not the current execution policy.

## Execution contract

- A saved Astra delegation request remains enabled when the account disconnects. AI entry points become unavailable; brush, mask editing, restore and history remain available. The main process checks eligibility again. Disconnection never selects Flux or another local model.
- Full-page translation, dragged regions, page retranslations, selected-block/page/chapter erasure, drawn-mask erasure, balloon fitting and the SFX review launcher all reach their Codex adapters. Hardware/model checks omit local OCR/Flux preparation when delegated.
- Source text, translations, family grouping, font choice, size and line breaks use Astra. Local raster operations apply the returned geometry and measure actual rendering. Font boldness stays an expression of a family, not a separate preset font.
- Source reading also returns bounded optional terminology and character memory. Existing grounded merge rules and manually authored entries remain authoritative. Provisional context is available to subsequent pages; only accepted full-page commits persist memory. Region/SFX jobs do not overwrite chapter memory.
- Region output and erasure are independent. Original erasure OFF remains OFF even with the saved delegation mode. Region commits retain revision checks and undo history. Image reads use file bytes so long Windows paths do not depend on nativeImage path decoding.

## First result and errors

There is one erasure proposal/preview, one background inspection and one layout/render review per actual region batch. There is no automatic content-repair loop. A valid but imperfect first result stays visible with review notes. Transport capacity delays remain explicit, and are not quality retries.

Generated SFX must contain a real image layer. An invalid generation now fails explicitly instead of appearing as generic font lettering. The generator is asked for a solid chroma matte chosen away from the requested fill/outline colors. Local separation estimates the returned matte from border corners, removes color spill and preserves white outlines. Real-alpha results are also accepted. An unrecognizable matte is an error, not a retry or a font substitution.

## Progress and editing

Both progress surfaces use JobProgressReadout. Structured events preserve stage, detail, one-based page and stage completion counts. Whole-chapter font comparison is indeterminate; stage counts are never presented as overall translation completion. Only completed persistence advances saved-page counts.

The font editor uses the original page alongside the selected font, regular/bold specimens and a multiline purpose field. Page/pan/zoom state survives font and purpose edits. The existing searchable/favorite/custom-font selector is reused, bounded to available portal space. Presets retain the existing format and ten-font maximum.

A narrow settings contract serializes preference updates with other settings writes. Drafts debounce and flush at close, preset switch and start; failed saves retain input and expose retry. Execution snapshots the selected preset. Presets can be copied, renamed, deleted and repaired when a font is missing.
