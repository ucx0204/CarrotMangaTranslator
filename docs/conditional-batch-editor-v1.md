# 일관 편집 v1 사용·검증 가이드

작성일: 2026-08-30  
브랜치: `codex/beginner-batch-rules-research`

## 들어가는 곳

1. 작품과 화를 연다.
2. 왼쪽 사이드바의 **일관 편집**을 누르거나 `Ctrl+H`를 누른다.
3. 기존 편집 화면 위에 뜨는 큰 모달에서 왼쪽 규칙과 오른쪽 실제 페이지를 확인한다.

화가 열려 있지 않거나 번역·인페인팅 같은 작업이 진행 중이면 진입 버튼은 비활성화된다.

기존 텍스트 모아보기의 검색·치환 탭과 별도 치환 엔진은 제거했다. 조건 없는 검색·치환은 이 화면에서 **모든 말풍선**을 선택해 사용하며, 별도의 간단 모드는 두지 않는다. 조건 유무와 관계없이 미리보기, 결과 제외, 적용, 실행 취소와 YAML 저장은 같은 흐름을 사용한다.

## v1에서 정확히 되는 것

### 적용 범위

- 현재 페이지
- 현재 화 전체

현재 페이지 범위는 범위를 선택한 시점의 페이지 한 장에 고정된다. 현재 화 전체에서 이전·다음 결과를 누르면 결과가 있는 페이지로 이동한다.

### 조건

- 검사할 데이터: 번역문, 원문
- 비교 방법: 포함, 정확히 같음, 비어 있음, 비어 있지 않음
- 여러 조건: 모두 충족(AND), 하나라도 충족(OR)
- 조건 없는 명시적 모드: 모든 말풍선
- 조건은 최대 10개

빈 조건이 실수로 모든 블록을 선택하는 일은 없다. 모든 블록을 바꾸려면 경고가 붙은 **모든 말풍선**을 직접 선택해야 한다.

### 작업

- 대상: 번역문, 원문, 원문과 번역문
- 검색 방식: 일반 문자, 정규식
- 대소문자 구분 여부
- 한 말풍선 안에서 첫 번째 일치만 바꾸기 또는 모든 일치 바꾸기
- 정규식 캡처 그룹을 `$1`, `$2` 형식으로 치환
- 바꿀 글자를 비워 일치 문자열 삭제

v1 작업은 정확히 1개다. 일반 문자 모드에서는 `$&`, `$1` 같은 치환 토큰도 일반 문자로 처리한다. 잘못된 정규식과 빈 검색어는 미리보기·저장·적용을 막는다.

### 미리보기와 적용

- 입력할 때마다 실제 프로덕션 원고 캔버스가 다시 계산된다.
- 변경 전/변경 후를 전환할 수 있다.
- 현재 페이지의 적용 후보가 원고 위에서 강조된다.
- 이전/다음 결과로 전체 후보를 순서대로 확인한다.
- 결과 목록에서 항목별 체크를 꺼 이번 적용에서 제외한다.
- 조건에는 맞지만 치환 결과가 같은 블록은 `변화 없음`으로 따로 센다.
- 원문만 바뀌는 결과는 목록에서 원문 전후를 보여 주고, 원고 미리보기의 번역문은 그대로 둔다.
- 실제 변경은 한 번의 작업 기록으로 묶여 **실행 취소** 한 번으로 되돌린다.
- 미리보기 뒤 다른 경로에서 텍스트가 바뀐 항목은 덮어쓰지 않고 충돌로 건너뛴다.

결과 목록은 성능을 위해 앞의 100개만 그리지만 이전/다음 버튼은 전체 결과를 순회한다.

### YAML 저장

- 앱 데이터 폴더의 `batch-edit-schemes.yaml`에 저장한다.
- 스키마 버전은 1이다.
- 규칙은 최대 100개, 파일은 최대 512 KiB다.
- 저장은 임시 파일을 완전히 쓴 뒤 교체하는 방식이다.
- 기존 YAML이 깨졌으면 저장으로 덮어쓰지 않고 오류를 보여 준다.
- 알 수 없는 필드, 중복 ID, 숨겨진 두 번째 작업, 잘못된 자료형은 거부한다.

예시:

```yaml
schemaVersion: 1
schemes:
  - id: 7ed43ed3-d0e9-489d-92e8-97ed6408ca17
    name: 말줄임표 통일
    description: 번역문의 점 세 개를 한 글자 말줄임표로 바꿉니다.
    match:
      mode: all
      conditions:
        - id: ellipsis-condition
          field: translatedText
          operator: contains
          value: "..."
    actions:
      - id: ellipsis-action
        type: replaceText
        target: translatedText
        searchMode: literal
        caseSensitive: true
        find: "..."
        replace: "…"
        allOccurrences: true
```

## 아직 안 되는 것

- 선택한 말풍선만 범위로 쓰기
- 번역문 이외의 글꼴, 크기, 색, 외곽선, 정렬, 방향, 위치 변경
- 숫자 비교, 색 비교, OCR 신뢰도 같은 분석값 조건
- `포함하지 않음`, `같지 않음`
- 괄호가 있는 중첩 AND/OR 그룹, NOT, IF/ELSE
- 여러 작업을 순서대로 실행
- 규칙 자동 실행, 예약 실행, 폴더 감시
- YAML 직접 편집 화면, 가져오기·내보내기 버튼
- 조건별 통과/실패 이유를 원고 위에 표시
- 재실행(redo) 전용 버튼

## 직접 써 볼 때 우선 확인할 항목

### 1. 가장 안전한 기본 흐름

1. `...`이 들어간 번역문이 있는 페이지를 연다.
2. 일관 편집에 들어간다.
3. 기본 예제의 범위를 **현재 페이지**로 둔다.
4. 오른쪽에서 **변경 전/변경 후**를 번갈아 누른다.
5. 예상한 말풍선만 테두리로 강조되는지 본다.
6. 적용한 뒤 **닫기**를 눌러 일반 편집 화면으로 돌아가 실제 텍스트를 확인한다.
7. 다시 들어가 실행 취소를 눌러 원래 `...`로 돌아오는지 확인한다.

### 2. 한 말풍선에 같은 글자가 여러 번 있을 때

예: `음... 그래...`

- **모든 일치 항목 바꾸기** 켬: `음… 그래…`
- 끔: `음… 그래...`

### 3. 결과 제외

1. 결과가 2개 이상인 규칙을 만든다.
2. 결과 목록에서 가운데 항목의 체크를 끈다.
3. 오른쪽 변경 후 화면에서 그 말풍선만 원래 글로 남는지 확인한다.
4. 적용 뒤에도 제외한 항목만 그대로인지 확인한다.

### 4. 현재 페이지와 현재 화 전체

서로 다른 두 페이지에 같은 찾을 글자를 준비한다.

- 현재 페이지: 지금 페이지의 결과만 센다.
- 현재 화 전체: 두 페이지 결과를 모두 센다.
- 이전/다음: 페이지 경계를 넘어가며 해당 원고를 보여 준다.
- 현재 페이지로 다시 바꾸면 그때 화면에 보이는 페이지 한 장으로 범위가 잡힌다.

### 5. 조건 조합

다음처럼 원문과 번역문을 함께 사용해 본다.

- 조건 1: 원문이 `!?`를 포함
- 조건 2: 번역문이 비어 있지 않음
- 모두 충족: 두 조건을 둘 다 만족하는 블록만 선택
- 하나라도 충족: 둘 중 하나만 맞아도 선택

### 6. 삭제 작업

찾을 글자에 불필요한 접두사나 기호를 넣고 바꿀 글자를 완전히 비운다. 변경 후 미리보기에서 그 글자만 없어지는지 확인한다.

### 7. YAML 저장과 재사용

1. 규칙 이름과 설명을 바꾼다.
2. **YAML에 저장**을 누른다.
3. 새 규칙을 연 뒤 저장한 규칙을 다시 고른다.
4. 조건과 작업이 그대로 복원되는지 확인한다.
5. 같은 저장 규칙을 수정하고 다시 저장했을 때 복제되지 않고 갱신되는지 확인한다.
6. 삭제 버튼으로 지운 뒤 목록에서 사라지는지 확인한다.

### 8. 위험 경계

- 찾을 글자를 비우면 경고가 나타나고 적용 버튼이 비활성화되는지
- 일반 조건의 마지막 조건은 삭제할 수 없는지
- **모든 말풍선**을 고르면 경고가 분명한지
- 결과 체크를 전부 끄면 적용 버튼이 비활성화되는지
- 적용 뒤 다른 수정이 끼어든 오래된 미리보기가 그 수정을 덮어쓰지 않는지

### 9. 창 크기와 긴 글

- 넓은 창: 왼쪽 규칙 패널과 오른쪽 원고가 동시에 보이는지
- 좁은 창: 규칙이 위, 미리보기가 아래로 쌓이고 전체 화면을 세로 스크롤할 수 있는지
- 아주 긴 페이지명·규칙명·번역문: 버튼이나 입력칸을 밀어내지 않고 말줄임/줄바꿈되는지
- 100개가 넘는 결과: 목록 제한 안내가 보이고 이전/다음으로 101번째 이후도 갈 수 있는지

## 피드백을 받을 때 특히 알고 싶은 것

1. `현재 페이지 / 현재 화 전체`라는 범위가 충분한가, 선택한 말풍선 범위가 먼저 필요한가?
2. `모두 맞을 때 / 하나라도 맞을 때 / 모든 말풍선` 문구가 바로 이해되는가?
3. 결과 제외가 왼쪽 목록에 있는 편이 편한가, 원고의 말풍선을 직접 눌러 제외하고 싶은가?
4. 변경 전/후 토글만으로 충분한가, 누르고 있는 동안만 원본을 보는 방식도 필요한가?
5. 다음 작업으로 선택 범위와 글꼴·크기·색 같은 서식 일괄 적용 중 무엇이 더 급한가?
6. YAML 저장은 충분히 자연스러운가, 파일 가져오기·내보내기가 먼저 필요한가?
