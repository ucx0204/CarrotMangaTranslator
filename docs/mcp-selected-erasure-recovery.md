# MCP 선택 제거 한 건의 복구

범위: 같은 MCP 실행 세션에서 완료된 **블록 하나의 원문 제거**에 대한 복구 가능 여부 조회, 실행 취소, 다시 실행. 로컬 모델을 재로딩하거나 OCR·번역·제거를 다시 실행하지 않는다. 기존 앱의 `InpaintingRevisionStore`, 페이지 인계/점유, 보관함 저장 트랜잭션을 사용한다.

## 도구

| 도구                          | 권한                            | 입력                             |
| ----------------------------- | ------------------------------- | -------------------------------- |
| `carrot_get_erasure_recovery` | `carrot.read`                   | `jobId`                          |
| `carrot_undo_erasure`         | `carrot.read`, `carrot.process` | `jobId`, `revision`, `requestId` |
| `carrot_redo_erasure`         | `carrot.read`, `carrot.process` | `jobId`, `revision`, `requestId` |

`jobId`는 `carrot_run_page_erasure`에 `blockId`를 지정해 실행한 작업의 ID다. 그 연결이 소유한 작업만 사용할 수 있다. 현재 버전은 조회 응답의 `revision`이며, 새 동작마다 새로운 UUID `requestId`를 사용한다. 원시 히스토리 ID나 파일 경로를 입력하지 않는다.

## 사용 순서

1. 선택 제거 작업이 `completed`인지 먼저 확인한다.
2. `carrot_get_erasure_recovery`에서 `canUndo: true`와 현재 `revision`을 받는다.
3. 새 requestId로 `carrot_undo_erasure`를 호출한다.
4. 다시 조회해 `canRedo: true`와 새 revision을 받는다.
5. 다른 새 requestId로 `carrot_redo_erasure`를 호출한다.

예시 지시: "방금 선택한 블록의 원문 제거를 되돌릴 수 있는지 확인하고, 가능하면 실행 취소해. 나중에 다시 적용할 수 있는지도 확인해. 모델은 다시 실행하지 마."

조회는 참고 상태다. 실제 실행 시 페이지를 점유하고 버전과 권한을 다시 검사하므로, 조회 후 사용자 편집이나 히스토리 해제가 발생하면 거부될 수 있다.

## 반환 상태와 제한

- `applied`: 제거 결과 상태이며 undo 가능.
- `undone`: 제거 전 상태이며 redo 가능.
- `conflict`: 이후 페이지가 변경됨. 변경을 병합하거나 덮어쓰지 않는다.
- `unavailable`: 세션 기록 없음, 파일 누락, 지원하지 않는 작업, 완료되지 않은 작업 등. `reason`을 확인한다.

페이지 전체 제거, 여러 페이지 제거, 실패/취소/부분 완료/모델 정리 실패 작업, 이미지 외의 블록/배치를 바꾼 히스토리는 이번 기능의 복구 대상이 아니다. 원본과 이전/다음 결과 이미지·마스크가 필요한 만큼 남아 있어야 한다.

이후 사용자가 문구·서식·위치 등을 수정했다면 **그 변경을 지키기 위해 복구를 거부**한다. 현재 기능은 후속 수동 편집과 제거만 선택적으로 병합하는 기능이 아니다.

기록 연결과 동작 영수증은 MCP 세션에만 유지된다. 앱/MCP 재시작 또는 앱에서 히스토리를 해제하면 조회가 unavailable이 될 수 있다. 영구 작업 기록이 남아 있어도 복구 가능성을 보장하지 않는다. 세션에는 최대 512개 연결과 512개 복구 동작 영수증을 보관한다. 영수증 한도에 도달하면 오래된 동작을 지우고 재실행하지 않고 새 동작을 거부한다.

## 중복 요청

네트워크 재전송에는 원래 입력 전체와 requestId를 그대로 사용한다. 정확한 재전송은 `already_applied`, `pagesChanged: 0`을 반환하며 다시 실행하지 않는다. undo 이후 redo를 했더라도 예전 undo의 재전송이 또 undo를 실행하지 않는다.

재전송 응답의 revision은 그때 동작의 기록이다. 현재 상태는 반드시 다시 조회한다. 같은 requestId에 반대 방향이나 다른 revision을 넣으면 거부한다. 실패 영수증도 유지하므로 원인을 해결한 새 작업에는 새 requestId를 사용한다.

## 보호와 전달

사용자 편집 인계와 페이지 점유를 기존 앱 경로로 처리하고, 저장 직전에도 권한·중단·페이지 버전을 재확인한다. 다른 연결은 조회/재시도 영수증을 가져올 수 없다. 정리된 세션의 대기 동작은 나중에 저장하지 않는다.

세 도구의 응답은 메타데이터뿐이다. 원문·번역문 전체, 로컬 경로, 원시 히스토리 ID, 이미지·다운로드 URL·파일 첨부를 자동 반환하지 않는다. 시각 확인이 필요하면 렌더링 미리보기를 따로 요청한다.

## 검증 경계

실제 보관함과 OAuth HTTP 테스트는 권한, 페이지 점유, 변경 전후 상태, 중복 요청, 충돌, 저장 직전 철회를 확인한다. 네이티브 시험은 선택 제거 전후 이미지 바이트, undo/redo, 원본·다른 블록 보존, 추가 모델 획득이 없음을 검사한다. 제거 추론만 결정적인 시험 구현으로 대체하며, 사용자 원고와 실제 GPU 모델 품질을 시험했다는 뜻은 아니다.

최종 실행 결과와 커밋은 별도의 closeout 기록에 남긴다. 도구 정의와 실행 앱 버전이 다르면 앱의 정상 재시작과 연결의 도구 목록 갱신이 필요하며 인증 파일 초기화는 필요하지 않다.
