# 원문 전체 교체와 바깥 feather · 사용자 승인 개발 결과

2026-09-06 사용자는 넓은 교체 영역과 바깥 feather 비교를 보고
“이정도면 합격임. 계속 진행해봐”라고 했다. 국소 시각 품질의 기준으로 채택한다.
이는 전체 번역 파이프라인 승격이나 새 화 일반화 검증 완료를 뜻하지 않는다.

실험은 `.tmp/astra-typesetting-research/user-requested-mask-feather-001`부터
`004`까지다. discovery-005의 コト, ザッ…에 대해 이미 저장된 ImageGen 원시
배경과 변환을 재사용했다. 새 ImageGen 호출은 0회이며, 거부 상태나 앱 저장
배경을 바꾸지 않았다. 실제 제품 후보 1회와 별개로 **출력을 바꾼 개발 실험
4회**를 모두 계산한다. 같은 화에서 추가 파라미터 탐색을 계속하지 않는다.

| 실험 | 완전 교체 영역                | 바깥 feather |
| ---- | ----------------------------- | ------------ |
| 001  | 기존 글자 마스크 + 3px        | 3px          |
| 002  | 기존 글자 마스크 + 6px        | 4px          |
| 003  | 글자 전체의 외접 사각형 + 3px | 4px          |

각 실험의 네이티브 비교 PNG를 직접 확인했다. 001–003에서는 원래 흰 외곽선의
작은 잔여가 남았고, 004에서는 문제의 뾰족한 잔여가 제거되어 옷 선의 연결과
경계가 자연스러워졌다. 원래 마스크 아래 7px에 있던 잔여를 feather만으로
희미하게 만드는 대신 완전 교체 범위에 포함한 것이 핵심이다. core는 생성
픽셀 100%, 그 바깥만 smoothstep으로 원본에 섞는다. 두 예제 모두 지원 범위
밖 픽셀 변화 0, core의 생성 픽셀 불일치 0, 보호 영역 중첩 0을 확인했다.

004의 `before-after-2.png`는 001과 004의 실제 국소 합성 결과 비교다.
원시 생성안을 그대로 붙인 그림이나 앱의 저장 배경으로 표시하지 않는다.
각 입력/결과 해시와 매개변수는 각 디렉터리의 plan/result/receipt에 있다.
001/002의 선언에는 당시 producer 해시가 없었으므로 소급해 있다고 주장하지 않는다.

## 초기 검증 계획 · 아래 구현 기록으로 갱신

같은 매개변수를 바꾸지 않고 필수 회귀인 discovery-004의 큰 ギロ에 전이해 본다.
이는 알려진 회귀 입력이며 새 확인 화나 최초 잠금 転生悪女 6번이 아니다.
단어 사각형은 글자 사이 그림까지 바꾸므로 8px을 모든 해상도에 일괄 적용하지
않는다. 원문 외곽선까지 포함하는 교체 core, 충분한 생성 문맥, 보호 대상,
실제 합성 미리보기와 그림 보존을 함께 평가해야 한다.

제품 후보에서는 원시 배경 생성과 국소 접합 수정을 분리하는 방법을 검토한다。
원시 배경이 쓸 만하면 마스크/feather 수정은 동일한 생성 결과를 재사용한다.
기존 binary permission을 alpha처럼 해석하지 않고 명시적 합성 계약을 둔다.
복원 범위와 이웃 재처리 범위에도 확장된 지원 영역이 포함되어야 한다.
검수에는 원본/원시 생성/실제 접합/지원 영역을 보여 주어 빠진 흰 외곽선을
그림 정합 실패와 구별하게 한다. 단순히 모든 기존 임계값을 낮추지 않는다.

진행 중인 discovery-005/candidate-001의 source/out/폰트는 실제 저장 결과
감사가 끝날 때까지 동결한다. 다음 구현과 실제 제품 검증에서는 사용자에게
배경 제거와 번역된 전경을 구분하여 중간 이미지도 공유한다. 큰 ギロ의 원문
제거, 자연스러운 그림, 한글 식자, 편집 가능한 저장 결과는 아직 완료되지 않았다.

## v0.4.6–0.4.7 실제 구현과 검증

discovery-005 전체 실패 결과를 감사한 뒤 동결을 해제했다. 실제 제품 1회와
출력을 바꾼 국소 개발 4회를 합해 이 화를 5회에서 종료한다. 기존 생성안을
고정된 8px core/4px feather로 큰 ギロ에 전이한 개발 005도 별도 기록했다.

production `codexTypesettingBlend`는 실제 glyph mask의 전체 외접 범위를 채우고
유클리드 거리로 core를 확장한 뒤 그 바깥에만 smoothstep alpha를 적용한다.
시작값은 native page width/100을 반올림해 2–16px로 제한한 core와 그 절반의
feather다. 836/844px 페이지에서는 8/4px이다. 모든 해상도의 최적값으로 입증된
수치는 아니다. 보호된 keep 픽셀과 겹치는 모든 alpha support는 거절한다.
실패 복원과 이웃 영향 계산도 확장한 support를 포함한다. 기존 binary mask를
alpha처럼 재해석하지 않고 명시적인 alpha 인자를 추가했으며 parity를 검증했다.

**검수 권위 변경을 명시한다.** 기존 정합 알고리즘과 임계값은 그대로 계산하지만,
해당 숫자만으로 합성을 최종 기각하지 않는다. 충분한 원본 문맥 표본, 유효한 생성
coverage와 opacity를 통과한 제안을 실제 합성 검수용으로 staging한다. Astra는
원본, 원시 생성, 실제 접합, alpha mask를 보고 배경을 승인해야 한다. 기술적
coverage 실패는 시각 판단으로 무시할 수 없다. 초기+2회 배경 보정 한도는 같다.
새 기준은 실제 seam과 그림 보존에 관한 사용자 승인에 따른 후보이며, 이전 숫자
gate를 통과했다고 소급하거나 이 변경을 단순 로그 추가라고 주장하지 않는다.

검수에서 geometry만 수정하고 원시 배경은 쓸 만하다고 하면 같은 job의 immutable
raw proposal을 다시 쓴다. 수정 support가 원래 crop 안에 있을 때만 가능하고,
새 실제 접합을 별도 revision/hash로 검수한다. 원시 생성 자체가 나쁘거나 crop을
벗어나면 새 생성이 필요하다. 보호된 unreadable ID에 대한 모델 관찰은 raw audit에
보존하되 active repair로 처리하지 않는다. 임의 ID나 keep geometry 수정은 거절한다.

v0.4.6은 `.tmp/astra-v046-check-05.log`, v0.4.7은
`.tmp/astra-v047-check-02.log`에서 각각 26 gate를 통과했다. 큰 ギロ의 실제 배경
검수, 찌릿 생성/독립 재판독/완성본 검수, 저장·다시 열기·편집·출력은
`astra-typesetting-required-effects.md`와 해당 self-contained 회귀 보고서가 근거다.

## v0.4.8 사용자 선택과 실험 고정 조건

사용자는 효과음 표현을 번역 실행 모달에서 생성형/폰트로 선택하되, **현재 연구
실험에서는 효과음을 전부 생성형으로** 하라고 지정했다. 기본값은 생성형이다.
기존 role=sound 판독 계약을 사용하며 의미 역할과 글자 크기·서체 복잡도를 구분한다.
선택한 방식은 chapter plan에 기록하고 모든 식자/재시도에 적용한다. 실패를 폰트나
원문 보존으로 돌려 생성형 성공으로 세지 않는다. 폰트 모드도 원문 제거를 수행하고
전경만 편집형 텍스트가 된다. 일반 대사의 기존 편집형 우선 정책은 유지한다.

이것은 사용자 요구 변경을 포함한 새 후보 묶음이다. 새 화 실험의 request와
candidate contract에는 반드시 `sfxRendering: "image"`를 명시한다.
