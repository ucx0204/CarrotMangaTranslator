> 후속 사용자 판정: confirmation-014를 본 사용자가 C23의 안정성을 C18보다 높게 평가하고
> 승격을 명시적으로 승인했다. 아래 C23 기각 기록은 당시의 판정으로 보존한다. C23의
> 로컬 앱 통합·검증을 완료했으며 근거는 `font-chapter-c23-handoff.md`에 기록했다.
> 이후 B는 C23 통합 완료 커밋이다. 재훈련은 그 master 커밋에서 만든 새 워크트리에서 한다.

아래 실험 시작 당시 제품은 사용자 승인 C18.1이었다. 최신 승격은 위 C23 인계를 따른다.
2026-09-07 W01~W06 피드백은 발견용 참고로 남긴다.
평가 페이지에 font ID 예외를 심거나 학습 라벨로 재사용하지 않는다. 일반체 과장, 그룹 분열,
붓체 누락, 손글씨 오선택, 크기·줄바꿈을 함께 평가한다.

## 첫 원인 진단 및 사전 등록

S20 기존 검증 242영역에서 원문 픽셀을 바꾸지 않고 사방에 최소 축 길이의 20%만큼
배경 여백을 추가했다. 서체 유형 116개, 굵기 84개가 바뀌었다. 극성 반전은 0개였다.
이 수치는 여백 민감도이며 기존 약한 검증 라벨의 정답률이 아니다.

가설: S20의 전체 bbox 크기에서 계산한 이웃 영역 크기와 전체 이미지 축소가 빈 여백에
끌려가 원문 획이 같은데도 서로 다른 글씨로 읽는다.

C19 / S21 후보 1의 fingerprint:
`s20-region-bags / foreground-union-canonical-frame / identical-1800-step-fit / original-S17-work-split`.

- 모델 입력에서 Otsu 전경 전체의 외접 범위를 기준으로 여백을 정규화한다. 작은 연결 요소나
  끊긴 획은 제거하지 않는다. 그 뒤 기존 9-view 구성과 82,143-parameter CPU 모델을 유지한다.
- S20과 같은 학습 자료·작품 분할·seed·1800 step을 사용한다. confirmation-012나 W01~W06은
  학습·임계값 설정에 넣지 않는다. 전처리 변화 때문에 새 모델을 처음부터 한 번 학습한다.
- 원문 묶음 S6, C18 그룹별 투표/한글 대응, 크기 추정, 번역·지움·기하를 고정한다.
  근거 없는 brush 분류를 단순 해제하거나 다른 글씨까지 몽토리로 바꾸지 않는다.
- 기존 S18의 연결 요소 선택/정규화와 다르다. 모든 전경의 상대 배치·끊긴 획을 보존하며
  내용이 같은 원문에서 여백만 바꾼 반사실 검사를 먼저 통과해야 한다.

사전 통과 기준: 여백에 의한 유형/굵기 변동이 각각 기존의 절반 미만으로 감소하고,
기존 검증의 유형 및 굵기 정확도가 각각 3%p 넘게 악화하지 않아야 실제 화 렌더로 진행한다.
이 검사만으로 승격하지 않는다. 새 화 전체 A/B/C를 직접 보고 새 심각한 손글씨·강조 소실,
그룹 불일치·과한 굵기·overflow가 생기면 기각한다. 통과하면 현재 C18과 고정 회귀,
다음 미사용 화를 확인한 뒤 실제 앱 통합·검사·커밋한다.

산출물: 별도 LAB의 `artifacts/font-palette-lab/system-reset-005/`.
연구011은 고유 검색 200질의, 50묶음을 실제 수행했다. 실제 수행 receipt와 제목/발췌/본문
열람 범위를 따로 기록하며 이전 턴 연구를 새 조사로 세지 않는다.

## C23 종료: 원문 증거 복구의 부분 개선과 회귀

C23은 기존 검증 글자가 **0개인 영역만** 대상으로 했다. median 3×3 / dark <64는 줄 위치를

기존 유효 글자를 버렸던 S11a 실패를 반복하지 않았다. 새 글자의 문자열 일치가 서체 묶음의

후속 재사용 시 메타데이터 정정과 기존 바이트 보존 검사를 먼저 하고, 기존 증거는 덮어쓰지 않는다.

현재 source recovery와 source grouping의 결합 자체가 새 오류를 일으켰다. 기존 판정의
잘못된 그룹을 새 관측으로 통째로 다시 묶고 평균낼 때 다른 문장까지 변한다. 다음 후보는
임곗값만 낮추거나 특정 W06 문장을 제외하는 방향이 아니다. **원문 묶음의 형태/강도
충돌을 검증하는 단계**와 **선택한 한국어 native 서체의 실제 굵기가 맞는지 확인하는 단계**를
분리해야 한다. 일반체·둥근체·손글씨·붓체·강조·문장부호·크기/배치를 모두 보호 기준에
유지한다. 이 평가 이미지와 사용자 피드백은 새 학습 라벨로 사용하지 않는다.

## 사용자 추가 평가와 013/P008의 선택 원인

- P001: 좌우 서체가 다름. C23에서도 미해결이다.
- P004: 전체적으로 괜찮지만 얇은 쪽이 더 어울림. 단순히 굵기를 올린 결과를 개선으로 세지 않는다.
- P003 상단: 일반 고딕보다 둥근 형태. 주아가 다소 굵을 수 있으나 당장은 보류해도 된다는 지시다.
- P008: 원문의 의도적인 굵은 강조. 신라문화체 또는 굵은 궁서가 맞는다는 평가다. 일반 인쇄체의
  굵기 차이로만 적었던 판단을 수정한다. 특정 페이지 강제 규칙으로 구현하지 않았다.

현재 `assign-coherent-source-palette.py`는 학습 근거가 부족한 medium_brush/heavy_brush
확률을 후보 선택에서 0으로 만든다. 신라문화체는 별도 decorative_serif 경로에만 남지만
그 최고 확률이 .75 미만이면 ordinary_serif로 내린다. 013/P008 실제 묶음은 장식 명조
확률 .3733, heavy 확률 .4882다. 각각 .75와 .70 조건을 못 넘어 리디바탕 400으로 결정됐다.
즉 폰트 파일 미설치 문제가 아니라 **불충분한 유형/굵기 근거와 선택 제한의 결합**이다.
이 한 묶음에 맞춰 임곗값을 내리거나 붓체 차단을 일괄 해제하지 않는다. 붓체 학습 지원과
보통 대사 오남용을 함께 검증해야 한다. 원문 캐시의 P000007이 실제 원문 P008이라는
identity 연결을 확인했고, 숫자 ID를 페이지 번호로 가정하지 않았다.

## 조사 011 실행/열람 범위

고유 검색 질의 200개, 실제 검색 50묶음과 원시 결과 URL 1,899개를 기록하고 각 결과 파일의
SHA-256을 다시 검사했다. 이는 1,899개 논문을 읽었다는 뜻이 아니다. 관련성·1차 출처 여부도
전부 보증하지 않는다. 전문을 읽은 논문 수는 0이며 아래는 실제 초록/관련 절 열람 범위다.

- [De-rendering Stylized Texts](https://arxiv.org/abs/2110.01890): 초록. 글꼴, 효과, 배경을 분리하는 문제 설정에 참고했다.
- [DeepFont](https://arxiv.org/abs/1507.03196): 초록. 합성/실제 도메인 차이의 근거이며 실패한 합성 실험을 그대로 반복하는 근거는 아니다.
- [Morisawa 일본어 조판](https://www.morisawa.co.jp/culture/japanese-typesetting/09/): 관련 본문. 한자·가나 혼식과 본문/제목 표현 구분에 참고했다.
- [Making Convolutional Networks Shift-Invariant Again](https://proceedings.mlr.press/v97/zhang19a.html): 초록/방법 요약. C22의 근거였지만 실제 로컬 실험은 기각됐다.

정확한 실행·열람 기록은 `system-reset-005/research011-execution-receipt.json`과
`research011-reading-scope.json`에 있다. 논문 가설이나 검색 수를 실제 출력의 실패보다
앞세우지 않는다. 다음 작업은 이 메모, C23 판정과 기존 실패 지도를 먼저 읽고 시작한다.
