# 백그라운드 작업 UX 일관성 감사

> 기준일: 2026-08-30
> 범위: 오래 걸리는 준비·가져오기·내보내기·설치·연구 작업과 그동안의 앱 잠금
> 관련 기준선: [`ui-ux-consistency-audit-2026-08.md`](ui-ux-consistency-audit-2026-08.md)의 UX-02

## 적용 원칙

작업 시간이 파일 크기·네트워크·모델 실행에 따라 달라진다면 설정/선택 모달을 진행 화면으로 재사용하지 않는다. 사용자의 선택을 받은 뒤 모달을 닫고 작업 센터에서 상태와 취소를 제공한다. 앱 전체가 아니라 실제로 충돌하는 동작만 잠근다.

예외는 다음과 같다.

- 운영체제 파일 선택기와 사용자의 결정을 기다리는 확인창은 모달을 유지한다.
- 이름 변경, 설정 파일 저장처럼 짧고 원자적인 저장은 해당 표면의 로컬 busy 상태를 유지할 수 있다.
- 이미 커밋된 작업의 후처리가 실패했을 때 소비된 입력 모달을 다시 열지 않는다. 결과 새로고침/자동 이동 실패로 따로 알린다.
- 취소 요청과 취소 완료를 구분한다. 실제 리소스 정리가 끝날 때까지 `취소 후 정리하는 중`으로 표시한다.

## 이번에 반영한 범위

| 흐름                         | 이전 문제                                                 | 반영한 동작                                                                                                |
| ---------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 이미지·폴더·ZIP/RAR·PDF 준비 | 큰 원본은 모달이 나오기 전 무반응처럼 보임                | 파일 선택 직후 작업 센터에 읽기/변환/검사 단계를 표시하고 취소 제공                                        |
| `보관함에 추가`              | 모달과 전역 overlay가 작업이 끝날 때까지 앱을 사실상 잠금 | 제출 즉시 모달을 닫고 작업 센터에서 복사/마무리 상태 표시                                                  |
| 실행 중 상호작용             | 하나의 `busy`가 탐색·편집까지 광범위하게 차단             | 번역·인페인팅 실행과 다른 장기 작업만 차단하고, 화/페이지 이동·검색·설정·폴더 열기·현재 페이지 편집은 허용 |
| 보관함 동시 변경             | 렌더러 비활성화만으로 충돌을 막음                         | 메인 프로세스에서도 가져오기 커밋 중 이름 변경·삭제·순서 변경을 거부                                       |
| 취소/실패                    | 입력한 작품명·화 선택·자동 저장 옵션을 잃을 수 있음       | 커밋 전 취소/실패면 모달을 정확한 draft와 안내문으로 복원                                                  |
| 커밋 후 후처리 실패          | 성공한 가져오기를 실패처럼 재시도할 위험                  | 소비된 preview를 폐기하고 목록 새로고침/현재 편집 저장 실패만 별도 상태로 보고                             |

작업 센터의 공개 상태는 원본 경로·내부 예외를 포함하지 않는 구조화 이벤트다. 현재 단계, 원본 종류, 보관함 변경 여부, 취소 가능 여부, 정확한 진행 총량, 사용자 작업 대기 여부와 제한된 실패 코드만 renderer로 전달한다. 자유 형식 상태 문구와 설치 로그는 재시작 기록에 저장하지 않는다.

페이지마다 반복되는 진행 이벤트는 상태 기록에 새 행으로 쌓지 않는다. 번역·OCR은 기존 진행 그룹 안에서 현재 행을 교체하고, 원문/그린 영역 지우기와 페이지 이미지 출력도 작업 시작부터 완료까지 각각 한 행만 갱신한다. 인터넷 조사는 전용 진행 카드가 열려 있는 동안 일반 상태 기록을 숨기며, app operation은 operation id별 현재 상태만 교체한다. 최종 완료·부분 완료·실패는 최근 작업 요약에 한 번만 남는다.

상태 기록은 사용자가 직접 지우거나 앱을 종료하기 전까지 renderer 세션에 유지한다. 새 번역을 시작하거나 다른 화를 열었다는 이유로 기존 기록을 초기화하지 않는다. OCR 준비·배치·페이지 분석은 화마다 하나의 OCR 행으로 압축하되, 번역 진행과 글자·폰트 맞춤은 서로 다른 행으로 남겨 두 단계를 모두 확인할 수 있게 한다. 화에 귀속되는 기록에는 `· 1화`처럼 화 제목을 표시하고, 화 제목에 마우스를 올리거나 키보드 포커스를 주면 앱 툴팁으로 작품 제목을 보여 준다.

## 검증 기준

모든 흐름은 `선택 → 모달 종료 → 작업 센터 진행 → 충돌 동작만 잠금 → 취소/실패 복원` 경계를 공유한다. 결과 화면이 필요한 작업만 기존 결과 화면을 열고, 완료 안내용 버튼이나 링크를 새로 붙이지 않는다. 작업 센터는 넓은 창과 좁은 창에서 실제 production 컴포넌트로 캡처하고, IPC lifecycle·draft 복원·native runner 진행률·revision 잠금·기록 sanitization을 회귀 테스트로 고정한다.
