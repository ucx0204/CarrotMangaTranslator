# 원문 크롭을 참고한 한국어 효과음 — 2026-09-06

사용자는 배경 복원을 현재 수준에서 고정하고 일본어 효과음의 느낌을 한국어로
재생성하는 데 집중하라고 방향을 바꿨다. 공개한 원문/배경/한국어 합성 예시에
“너가 만든 예시 저거 괜찮네”라고 답했다. 이 피드백은 아래 예시의 시각적 기준에
대한 승인이다. 전체 화 자동 번역이나 새로운 작품에 대한 일반화 승격은 아니다.

## 실제 예시와 관찰

`.tmp/astra-typesetting-research/sfx-source-conditioned-001`에 입력 크롭, 모든 프롬프트,
실패를 포함한 생성 원본과 비교 결과를 보존했다. 원문은 discovery-006의 사라나
16.2화이며, 잠근 기존 20장 중 6번은 다시 사용하지 않았다.

| 원문   | 한국어 | 최종 생성 파일        | 직접 확인한 특징                                     |
| ------ | ------ | --------------------- | ---------------------------------------------------- |
| ビクッ | 움찔   | `09-generated-v2.png` | 강약 있는 검은 획과 흰 테두리, 세로 흐름             |
| ニコ   | 방긋   | `06-generated-v2.png` | 둥근 마커 획, 작은 흰 테두리; 원문보다 가늘고 조밀함 |
| パァ   | 화아   | `11-generated-v3.png` | 흰 획 내부와 검은 외곽선, 큰 첫 글자와 작은 뒷글자   |
| フワッ | 사르르 | `02-generated-v3.png` | 뾰족하고 비어 있는 획, 아래로 작아지는 글자 배치     |

원문 크기와 3배 확대를 모두 직접 봤다. `comparison-v2/report.html`과 각
`*-native.png`, `*-3x.png`는 왼쪽 원문, 가운데 고정 배경, 오른쪽 한국어 합성이다.
합성은 실제 앱 `createPageExportRenderSession`을 사용했다. 네 효과음의 한국어
이미지는 원문 bbox에 놓고 회전은 0으로 두었으며 글자 내부 기울기는 생성 이미지에
포함했다. 실제 앱의 자동 배치 결과를 사용한 전체 화 평가와 구별한다.

배경 파일 SHA-256은
`957969373c33198bd8f08c2df46e7e8bcd923cd939930e6e32766da627702777`이다.
새 배경 생성은 0회다. 전경은 `foreground-page.png`, 합성은
`composited-page.png`로 별도 보존했다. 사용자가 이미 허용한 배경 결함을 이 실험에서
다시 최적화하지 않았다.

최초 생성 4회와 보정 6회, 총 **내장 ImageGen 10회**를 사용했다. 4개 효과음의
1차 생성, 2차 보정, 2개 남은 외곽선 효과음의 3차 보정으로 구분한다. 호출별 토큰
사용량은 도구가 제공하지 않아 미상이며 0으로 기록하지 않는다. 수동 프롬프트를
사용한 국소 개발 실험으로, 사전 봉인된 자동 후보 시험이나 무작위 일반화 평가가 아니다.

최초 움찔/방긋, 화아 2차와 사르르 2차는 체크무늬가 실제로 그려진 불투명 출력이었다.
이 파일들은 합격이나 투명 레이어로 세지 않았다. 배경 제거도 ImageGen으로 수행했고,
스크립트로 가짜 투명 배경을 숨기지 않았다. 최종 선택 4개는 실제 alpha가 있으며
원래 크기 합성을 확인했다. 화아 최초 출력의 잘못된 글자 형태와 외곽선 두 종류의
축소 후 지나치게 가는 선을 보정했다. 한 번의 생성으로 모두 성공했다는 근거는 없다.

## 앱 연결

`src/main/pipeline/codexTypesettingLettering.ts`는 종전 ImageGen 호출의 이미지 인자가
빈 배열이었다. 서체군 설명만으로 원문 스타일을 전달하고 있었다.

v0.4.9 후보는 기존 `sourceRegionCrops`를 그대로 사용해 **원본 imagePath**에서 효과음
문맥 크롭을 만든다. 생성할 때 원문 참고 이미지 1장, 해당 원문/방향/좌표 설명, 실제
배치 크기, 가족 서체 설명, 굵기/색/외곽선 계획과 보정 지시를 전달한다. 원문 획 모양,
비어 있는 획과 채운 획, 테두리 비율, 글자별 크기 차이와 읽을 수 있는 한글 형태를
보도록 명시했다. 같은 페이지의 크롭은 최초 필요한 시점에 한 번 만들고, 재사용할 수
있는 기존 전경만 있는 경우 원본을 다시 읽거나 생성하지 않는다.

불투명 출력 거부, 실제 전경/배경 분리와 이미지 문구 바인딩, 후속 독립 재판독은 기존
계약을 유지한다. 폰트로 조용히 대체하는 실험 경로는 만들지 않았다. 번역 모달의
생성형/폰트 선택은 v0.4.8에서 이미 구현 및 넓은/좁은 실제 UI 검증을 마쳤다. 이번
변경은 렌더러 UI를 바꾸지 않았다.

회귀 테스트는 지워진 배경과 이동한 renderBbox가 있어도 원래 원문 위치의 크롭을
전달하는지, 실제 이미지 입력이 있는지, 투명 PNG bytes를 그대로 유지하는지,
재사용/강조 변경/불투명 출력/취소 계약을 확인한다. 전체 검사 로그는
`.tmp/astra-sfx-reference-check-02.log`에 남긴다. 첫 검사는 함수 길이 lint로 실패했고,
이미지 검증/PNG 변환을 같은 파일의 함수로 분리해 상한을 유지했다.

수정 후 전체 `npm run check`의 26개 검사가 **150.41초에 모두 통과**했다.
테스트는 **5,427개 통과, 10개 건너뜀**이며 typecheck/lint/coverage/build,
실제 PageArtwork 픽셀 parity와 image protocol smoke도 포함한다. 예시 품질의
사용자 승인과 이 코드 검증 결과를 구별하며 자동 일반화 승격으로 기록하지 않는다.

## 범위와 다음 검증

기존 discovery-006 candidate-001은 사용자의 효과음 집중 지시에 맞춰 중단했다.
중단 직전 30개 원천 모듈과 1,752개 런타임/폰트/의존 파일이 봉인한 상태와 같음을
확인했다. 원문·배경·중간 결과를 보존했고 미완료 자동 실행을 전체 화 성공/실패율로
바꾸지 않았다. 실제 소유 Electron과 그 자식 프로세스만 중지했다. 중단 중 호출의
원격 완료와 사용량은 미상이다. 실험 원장에 cancelled 및 사유를 기록했고 이 화는
사용한 화로 계속 취급한다.

현재 자동 프롬프트 연결은 예시와 같은 품질을 무조건 보장한다는 뜻이 아니다. 이후
검증은 원문 참고 이미지를 주는 실제 자동 호출의 스타일/문자 정확도/투명도/원래 크기
가독성을 함께 보고, 현재 예시 수준을 기준으로 다른 화에 적용한다. 최종 승격은 연구
playbook의 새 화 확인과 실제 앱 저장/편집/재열기/내보내기 검증을 따른다.

## 가려진 효과음과 수동 보정 — 후속 설계, 아직 구현하지 않음

사용자는 말풍선/인물/기타 물체에 일부 가려진 효과음 처리와, 자동 결과가 깔끔하지
않을 때 원형·사각형 붓으로 지우거나 복구하는 방식을 제안했다. 현재 전경 저장
계약에는 `dataUrl`과 문구 바인딩만 있고 별도 가림 마스크는 없다. 기존 원형 붓과
사각 복원 도구는 페이지 배경을 수정하므로 생성 효과음의 일부를 숨기는 도구로
그대로 간주하면 안 된다.

입력 크롭이 잘못되어 글자가 잘린 경우에는 문맥 크롭을 넓혀 다시 판독한다. 실제
말풍선/인물 뒤로 가려진 경우에는 그 전후 관계를 유지한다. 배경 복원 단계부터
앞에 놓인 말풍선 테두리와 인물을 보존하고, 한국어 효과음 전경을 만든 뒤 물체의
가림 영역으로 전경만 감춘다. bbox만으로 물체의 곡선 경계나 일부 획 가림을 표현할
수 없다. 원문 자체가 가려져 판독할 수 없는 부분은 문맥 확인/검토 대상으로 남기며
임의로 정확한 원문을 복원했다고 취급하지 않는다.

수동 도구는 원형/사각형 붓, 크기, 경계 부드러움, 숨기기/복구, 실행 취소/다시 실행과
전체 초기화를 제공하는 비파괴 전경 마스크로 설계한다. 생성된 원래 RGBA를 보존하고
마스크만 수정해야 사용자가 지웠던 한국어 획을 나중에 복구할 수 있다. 복구는 그
전경에 원래 있던 픽셀을 되살리는 것이며 처음부터 생성되지 않은 획을 만들어내는
기능은 아니다. 배경/인물 복원은 기존 페이지 복구 도구의 책임으로 구별한다.

물체 가림은 페이지에 고정된 경계이고, 사용자가 효과음 자체에 칠한 보정은 효과음의
좌표에 속한다. 효과음을 이동/확대/회전했을 때 두 마스크의 의미가 섞이지 않도록
구분해야 한다. 실제 구현의 완료 기준에는 저장/재열기, 확대/회전, PNG/PSD 출력,
undo/redo에서 같은 결과를 유지하는 테스트와 실제 production UI 검증을 포함한다.
