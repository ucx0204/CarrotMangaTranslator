# 수동 가리기 초안 저장

이 문서는 수동 가리기 초안의 저장 형식과 복구 경계를 설명한다. 전체 수정 진행 상황은 `redaction-review-repair.md`와 작업 브랜치의 실제 커밋을 기준으로 확인한다. 이 문서가 전체 CI 성공이나 모든 검토 항목의 완료를 의미하지는 않는다.

## 저장 항목

데이터 루트의 `manual-redaction-workspaces.json`은 버전 2 인덱스다. 페이지 경로별 초안, 작업 범위별 보기 위치, 공통 도구 설정과 프리셋을 `manual-redaction-drafts` 안의 SHA-256 이름 객체로 참조한다. 페이지 마스크와 확인 상태는 페이지 객체가 소유한다. 원본 이미지는 이 저장소에서 수정하지 않는다.

작업공간을 열 때는 해당 페이지와 보기 상태만 읽는다. 저장할 때는 변경한 페이지 객체와 필요한 공통 항목만 기록한다. 인덱스의 전체 쓰기 번호와 별개로, 충돌 검사는 세션이 실제로 관찰한 페이지·보기·설정의 값에 대해 수행한다. 다른 페이지를 수정한 세션 때문에 무조건 저장을 거부하거나, 충돌을 피하려고 다른 세션의 최신 내용을 몰래 기준으로 삼지 않는다.

## 저장 완료 경계

새 객체를 기록하고 파일 동기화를 마친 뒤 인덱스를 원자적으로 교체한다. 인덱스 교체 전에 실패하면 이전 인덱스와 이미 저장 완료한 내용이 유지된다. 생성됐지만 인덱스에 연결되지 않은 객체는 새 저장본으로 취급하지 않는다.

참조된 객체가 없거나 해시가 맞지 않으면 오류다. 이를 비어 있는 새 초안으로 초기화하지 않는다. 파일과 객체 폴더의 심볼릭 링크를 따라가지 않으며, 객체 참조는 검증된 해시 이름만 허용한다. 객체와 인덱스 각각에 크기 제한을 둔다.

같은 데이터 루트의 읽기·쓰기·정리는 하나의 순서로 실행한다. 다른 루트의 저장 작업까지 하나의 전역 대기열에 묶지는 않는다.

## 이전 초안

버전 1 파일을 여는 것만으로 저장 형식을 바꾸지 않는다. 최초로 저장에 성공할 때 모든 기존 페이지를 이전하고, 원래 파일의 바이트를 `legacy-<SHA-256>.json` 백업으로 남긴다. 과거 보류 상태는 가림을 지우거나 확인 처리하지 않고 미확인으로 읽는다.

이전 형식으로 되돌리는 UI는 제공하지 않는다. 형식 복구나 역마이그레이션을 구현할 때에는 인덱스뿐 아니라 참조 객체와 원래 백업을 함께 보존해야 한다.

## 정리 정책

인덱스 저장이 완료된 뒤에만 사설 객체 폴더를 정리한다. 현재 인덱스가 참조하지 않고 24시간 이상 지난 해시 객체와 이 기능이 만든 임시 파일만 후보가 된다. 한 번에 삭제하는 수를 제한하고 반복 실행을 지연한다.

현재 페이지의 가림·확인 상태, 원본, 이전 형식 백업, 알 수 없는 파일과 심볼릭 링크는 정리하지 않는다. 보기 위치는 최대 1,024개 범위를 보관하는 캐시이며, 보기 위치가 만료돼도 페이지 가림이나 확인 결과가 삭제되지는 않는다. 오래된 정리 후보를 지우는 데 실패해도 이미 완료된 저장을 실패로 되돌리지 않고 진단을 남긴다.

## 전송과의 구분

초안 저장은 전송 승인이 아니다. 실제 작업 재개는 사용자의 명시적인 확인과 저장된 페이지 스냅샷 검증을 거쳐야 한다. 미리보기 로딩, 자동 저장, 초안 마이그레이션 또는 파일 정리가 외부 작업을 시작해서는 안 된다.

## 재개 시 확인할 항목

F12a는 기존 디스크 검증 형식 분리, F12b는 분할 저장과 원자적 인덱스 연결, F12c는 저장 후 사설 객체 정리다. 각 단계의 코드와 검증 기록은 별도 커밋에 있다. 추가 수정은 현재 브랜치의 최신 코드를 기준으로 수행하고 과거 전체 파일 스냅샷을 덮어씌우지 않는다. 전체 저장소 검사 결과와 아직 남은 검토 항목은 별도로 확인한다.
