# 영역번역 기본 인페인팅 문맥 복원

2026-09-09. 설치된 v2.6.1의 영역번역 → 원문 지우기 → 기본에서 글자가 남거나 단색 면이 생기는 문제.

## 원인과 수정

`prepareRegionArtwork`는 설정된 Flux·LaMa·AOT를 실제로 호출했지만, OCR용으로 잘린 작은 이미지를
인페인팅 입력으로도 사용했다. Flux의 기존 주변 문맥 창이 이 이미지 경계에서 잘려 배경 복원에
필요한 주변 픽셀을 받지 못했다. 설치본의 `008.jpg`에서는 60×108픽셀 입력에서 일본어가 남았고,
다른 화의 `003.jpg`에서는 55×104픽셀 영역이 단색으로 변했다. 화면 표시만의 문제가 아니라
저장된 인페인팅 PNG에서도 확인됐다.

기본 제거 경로는 작업 디렉터리에 원본 페이지의 PNG 문맥을 만들고, 기존 좌표 변환 함수로
이번에 번역한 블록만 페이지 좌표에 배치한다. 공용 인페인팅 엔진은 기존 마스크·주변 문맥·크기
제한을 그대로 사용한다. 생성 결과에서 사용자 선택 영역만 가져와 현재 페이지에 합성하므로
선택 영역 밖의 기존 편집은 보존된다. OCR 입력과 번역 좌표, Codex 제거 경로는 유지한다.

모델 자체, 프롬프트, 추론 횟수, 전역 마스크 알고리즘은 변경하지 않았다. 파일명이나 작품별
분기도 없다. 원본·보관함을 수정하지 않고 별도 임시 디렉터리에서 실제 모델을 검증했다.

## 검증

- 설치본에 남은 두 실패 크롭과 당시 인식 결과를 사용해 프로덕션 `prepareRegionArtwork`부터
  실제 Flux CUDA 런타임까지 실행했다. 두 결과 모두 원문이 지워지고 주변 배경이 이어지는 것을
  직접 확인했다. 첫 사례의 모델 입력은 기존 60×108 크롭 대신 주변 문맥을 포함한 416×448이었다.
- 두 번 모두 Flux 풀로드, 4단계, 강도 1을 유지했으며 추가 생성 재시도는 없었다.
  참고 문맥을 포함한 경로의 실행 시간은 각각 약 3.7초, 3.4초였다. 일반 성능 보장은 아니다.
- 회귀 테스트는 실제 마스크 생성·엔진 호출·PNG 저장·선택 영역 합성을 실행한다. Electron 이미지
  어댑터와 외부 모델 프로세스만 대체한다. 세 로컬 모델 선택, 주변 문맥, 선택 밖 보존, 페이지
  가장자리·전체 선택, 원본 크기 불일치, 무변경·실패 처리, 엔진 해제, Codex 결과 호환을 검사한다.
- 최종 `npm run check`: 26개 단계 통과. 735개 테스트 파일에서 6,284개 통과, 2개 건너뜀,
  실패 0개. 타입 검사·린트·커버리지·빌드·페이지 이미지 동일성·이미지 프로토콜 검증을 포함한다.
