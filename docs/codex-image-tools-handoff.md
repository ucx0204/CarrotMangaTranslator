# Codex 보조 이미지 도구 통합

## 2026-09-12 짧은 한글 효과음의 문자 구조

저장된 `두근`·`탁` 생성물은 번역 문자열이 정확한데도 받침이나 초성 획이 빠지고
일본어 골격이 섞였다. 알파 합성 전의 원시 생성 이미지부터 실패했으므로 번역문
손상이나 matte 제거 문제가 아니다. 원문 crop의 `region.sourceText`를 `target=`로
표기하고, 원문의 appearance·stroke construction·proportions를 우선시키던 입력
계약을 수정했다. 이는 확인된 프롬프트 충돌이며 이미지 모델의 내부 원인까지
입증했다는 뜻은 아니다.

확정한 번역문을 문자와 내부 구조의 유일한 기준으로 삼고, 한글이 포함되면 그
문구에서 추출한 음절 순서를 전달해 초성·중성·받침을 완성된 한 음절 안에 유지하도록
했다. 원문의 색조·질감·외곽선·필압·기울기·크기 차이는 계속 따르되, 글자 묶음의
배치와 원문 개별 획의 모사를 구분한다. 원문에만 있는 글자·탁점·늘임 기호가
장식 획으로 남지 않도록 명시했다. 스타일 묶음의 첫 결과도 질감 기준으로만 쓰며
그 결과의 잘못된 자형을 다음 문구에 복사하지 않도록 했다. 원문 표기는
`sourceText=`로 바로잡았다.

단어별 예외나 길이 기준은 없다. 음절 안내에는 NFC를 사용하지만 실제 렌더링할
확정 문자열은 변경하지 않는다. 원문 crop bytes·마스크·입력 이미지 수·모델·해상도
예산·배치·알파 합성·재사용·취소 처리는 유지했다. 추가 이미지 생성/검수 반복,
폰트 견본 입력, 새 의존성은 도입하지 않았다.

실제 보관함의 같은 입력으로 production `generateLetteringLayers`와 Codex App Server를
호출했다. 저장된 Astra/low 설정과 원본 가리기 승인을 사용하고, 결과는 별도
`.tmp/short-hangul-0912`에 남겼다. 기존 `library`·원본·출력물은 수정하지 않았다.

- 수정 전 짧은 효과음 5회(`두근` 2회, `탁` 2회, `탓` 1회)에서 자형 실패를 재현했다.
  첫 `두근` 요청은 과거 실패 요청과 프롬프트 bytes까지 같았다. crop 표기만 고친
  별도 2회도 실패해, 표기 수정만으로 충분하다고 판단하지 않았다.
- 최종 코드의 `accepted-*`는 9개 생성 결과다. `두근`, `탓`, `끼익`, `뭉클` 2개,
  스타일 묶음의 `탁`→`탓`, 복잡한 표지는 완성된 한글을 확인했다. 독립 `탁` 1개는
  초성 자형 실패가 남았고, `뭉클` 2개 중 1개에는 원문의 늘임 획이 남았다.
  엄격하게 두 결함을 모두 세면 7/9개가 통과했다. 이것은 작은 수동 관찰 표본이며
  일반 성공률이나 완전 해결의 근거로 쓰지 않는다.
- 사용자는 남은 `탁` 실패를 확인한 뒤 추가 과적합을 피하고 현재 수정을 앱에
  적용하도록 지시했다. 추가 단어별 보정이나 생성 실험 없이 이 버전을 반영했다.
- 표지는 원시 생성과 실제 `createPageExportRenderSession` 전체 페이지 합성에서
  색상·명조 계열 획·크기 위계·기울어진 부제를 확인했다. 기존 리본 바탕에 대한 작은
  부제의 위치 차이는 수정 전에도 보여 배치까지 완벽하거나 픽셀 동일하다고 주장하지
  않는다. 문장형은 앞선 후보에서 실제 생성했고 최종 코드는 문자열 계약 테스트로
  확인했다.

첫 후보의 `뭉클` 늘임 획 실패와, 장식 보존 문장을 넓혔다가 표지 리본 바탕까지
중복 생성된 후속 후보도 보존했다. 그 장식 보존 문장은 최종 코드에서 제외했다.
`fixed-*`·`holdout-fixed-*`는 초기 후보, `final-*`는 폐기한 후속 후보이며 최종 결과는
`accepted-*`이다. 실행 도중 중단한 초기 launcher의 미완료 요청은 판정 표본에서
제외했다. 성공 이미지를 고르기 위한 숨은 재시도나 실패물 덮어쓰기는 없었다.

검증 근거는 `.tmp/short-hangul-0912/audit.json`의 요청·입력/출력 SHA-256·모델·횟수,
`accepted-gallery.png`의 최종 효과음 전체, `cover-composite-accepted`의 수정 전/후
실제 표지 합성이다. `두근`·`탁`·`탓`·표지의 전후 원문 입력 해시와 모델/추론 설정이
같다. `check-accepted.log`에서 `npm run check` 26개 gate가 모두 통과했다
(788개 테스트 파일, 6,595개 통과·4개 skip). 타입 검사·lint·build·기존 페이지 artwork
pixel parity·이미지 프로토콜 smoke를 포함한다. 렌더러 UI는 변경하지 않았다.

## 2026-09-12 SFX 일괄 번역문 확인

Hayai의 저장된 SFX 후보에서 Codex 이미지 작업을 선택하면 모든 대상 페이지의 번역을
먼저 모은 뒤 `SoundEffectTextReviewModal`에서 확인한다. 왼쪽 페이지 목록, 중앙 원본과
편집 가능한 영역, 오른쪽 원문·번역문 목록을 함께 표시한다. 기존 영역/붓/제외/복구/
스타일 연결 도구를 재사용하며 페이지 전환에도 편집 상태를 유지한다. 좁은 창에서는
페이지 목록을 가로로 놓고 이미지 아래에 편집 목록을 배치한다.

전체 확정은 새 `confirmSoundEffectTextReview` IPC 한 번으로 전달한다. 메인에서
session·전체 페이지 집합·원본 영역·추가 영역의 부모를 모두 검증한 뒤에만 생성으로
넘어간다. 기존 영역 번역의 검증 로직은 application service로 옮기고 같은 회귀 테스트로
동작을 확인했다. 확인된 판독을 이미지 도구에 전달하므로 후속 계획이 사용자의 문구나
영역을 바꾸지 않는다. 수정한 영역도 원본 가리기와의 겹침을 다시 검사한다.

추가 영역은 기존 `ResolvedSoundEffectBlock.additionalBlocks` 저장 계약을 사용한다.
이미지 실패 시 확인한 문구·영역·추가 블록과 완료된 원문 제거를 보존하며, 다음 페이지도
확인한 텍스트를 저장한다. 생성 요청은 실패 뒤 반복하지 않는다. 검토 취소나 늦은 생성
응답은 확인하지 않은 결과를 저장하지 않는다. 전체 확정 후 생성 중에 취소하면 확인한
번역문·영역은 보존하며 추가 이미지 요청은 멈춘다.
검토에서 제외한 원본 후보는 번역 블록을 만들지 않고 SFX 후보 목록에 남긴다.

내장 Codex는 `0.154.0`이다. 재로그인 후 실제 Astra 번역과 시험 이미지 생성이 성공했다.
[공식 Codex 이미지 안내](https://learn.chatgpt.com/codex/image-generation)는 내장 이미지
모델을 GPT Image 2로 명시한다. [GPT Image 2.5 Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)는
API 모델로 존재하지만 현재 앱의 ChatGPT 로그인/App Server 경로에서 2.5를 지정하는
지원 계약은 확인되지 않아 별도 모델 선택지를 추가하지 않았다. Astra는 도구를 지시하는
추론 모델이며 이미지 모델과 구분한다.

최종 검증에서 전체 26개 게이트가 통과했다. 테스트는 788개 파일에서 6,583개 통과,
4개 skip이며 타입·린트·커버리지 기준·빌드·페이지 픽셀 parity·이미지 프로토콜 smoke를
포함한다. 실제 SFX·설정·화자 선택 화면의 넓은/좁은 캡처를 확인했고 임시 QA 엔트리와
캡처는 제거했다. 전체 검사 로그는 `.tmp/sfx-speaker-final-check-r5.log`, 커버리지 증거는
`.tmp/sfx-speaker-final-coverage-0912.json`
(SHA-256 `2fa6eabc7f3f865c71b6afc325ec8a2a19fcf5dbcf8bfb77f82ced94338cd4f4`)이다.

## 2026-09-08 제거 참고 정보와 바탕 복원 지시 보완

50화 001.jpg의 저장된 입력·계획·ImageGen 원본 응답을 비교했다. 계획 단계에는 작은 부속 글자와 독립적인 장식 바탕의 모양 정보가 있었지만 제거 요청은 이를 받지 않았다. 기존의 포괄적인 장식 배경 제거 지시는 글자가 올라간 연속적인 면까지 없애도록 해석되었다. 합성이 지운 내용으로 오인하지 않도록 원본 생성 응답과 합성 결과를 분리해 확인했다.

확정된 `sourceText`, `styleDescription`, `sourceBbox`를 제거 엔진의 참고 계약으로 전달한다. 선택 크롭에서 원본 페이지 문맥으로 확장할 때와 다시 생성 타일로 잘라낼 때 native 좌표를 함께 변환한다. 자기 작업창에 속하는 판독만 전달하며 경계에 일부 걸친 이웃 영역을 새 제거 대상으로 안내하지 않는다. 실제 수정 권한은 기존 허용·제외 마스크가 계속 소유한다.

작은 부속 글자·분리된 획·문장부호를 함께 확인하고, 글자 외곽을 따라가는 받침과 글자가 올라간 독립적인 그래픽 면을 구분하도록 공통 지시를 정리했다. 후자는 기존 채움·경계·질감을 이어 복원한다. 작품명·특정 글자·색상별 예외는 없다. 별도 확대 참고 이미지는 구도·비율을 혼동할 가능성이 있어 실험 후 제품 변경에서 제외했다. 영역 모드의 원본/마스크 2장, 붓 모드의 기존 3장, 생성 1회, +10% 크기 요청과 정렬·차이·톤·feather·적용 거부 기준은 유지한다.

실제 앱이 저장한 50화의 제거 입력 3개와 기존 무작위 표본의 질감 말풍선 입력 1개를 production `createCodexInpaintingEngine`과 승인된 전송 경로로 재생했다. 앱에 저장된 Astra/high 설정을 읽기만 했으며 같은 입력을 구성별 1회씩 처리했다. 별도 세부 이미지 실험은 2/4 적용, 나머지는 구도·비율 검사에서 거부됐다(`.tmp/erasure-reference-smoke-0908`). 그 실험을 제외한 최종 구성은 4/4 적용됐고 작은 부속 글자 두 곳·장식 면의 채움·별도 말풍선 질감을 직접 확인했다(`.tmp/erasure-reference-compact-0908/results.json`). 각 실행은 1회 요청이며 허용 범위 바깥 변경은 모두 0픽셀이다. 저장된 세 작업은 서로 독립 재생했으므로 한 페이지 전체를 순차 실행한 결과나 일반 성공률로 해석하지 않는다. 미세한 색 잔여물은 남고, 실패한 실험도 보존한다.

native 문맥 좌표 이동, 겹친 이웃 판독의 제외, 원본 마스크 권한, 추가 이미지가 없는 요청 계약을 회귀로 확인했다. 최종 `npm run check`는 26개 단계와 721개 파일의 테스트 5,913개(2개 skipped), 기존 coverage floor, 빌드, artwork parity, 이미지 protocol smoke까지 통과했다. 로그는 `.tmp/erasure-reference-final-check.log`다. 사용자 앱은 재시작하지 않았다.

## 2026-09-08 영역·붓·스타일 그룹 후속 수정

번역문 확인 창은 기존 Modal, CheckboxField, SegmentedControl과 SFX의 공용 8방향 선택 핸들을 사용한다. 선택 영역을 원형/사각 붓으로 칠하면 실제 칠한 모양을 작업 범위로 사용하고 사각형은 그 모양의 바깥 경계만 표시한다. 제외/복원 붓은 원본 보호와 생성 참고 범위에 적용하며 완성된 글자 레이어를 잘라내지 않는다. 영역 추가·삭제·그룹 변경·붓·이동/크기 변경은 실행 취소/복구에 포함한다. 텍스트 입력의 기본 실행 취소는 가로채지 않는다.

제외/복원 붓은 선택한 영역에 귀속되고 이동·크기 변경·실행 취소 때도 함께 유지된다. 배경 제거에는 영역별 허용 범위의 합집합을 사용하고, 생성 참고 crop에는 해당 영역의 마스크만 적용한다. 겹친 영역의 선택된 본문을 다시 클릭하면 뒤쪽 영역으로 순환하며 실제 드래그나 핸들 조절은 순환하지 않는다.

큰 선택은 생성 전에 한 번 시각적으로 계획한다. 기존 번역문을 글자 단위로 보존하며 독립적으로 배치할 묶음만 분리한다. 사용자는 영역을 수정하고, 선택한 영역과 같은 스타일로 만들 다른 영역을 번호·번역문 체크박스로 연결하거나 분리할 수 있다. 숫자 그룹 드롭다운은 제거했다. 같은 그룹은 첫 결과를 고정 참고로 순차 생성하고 독립 그룹은 최대 두 개씩 처리한다. SFX에서 이미 확인된 영역은 ID·문구·배치를 유지하고 스타일 그룹만 공유한다. 완료된 글자마다 실제 페이지 렌더러로 중간 결과를 갱신한다.

가로로 긴 입력에서 발생한 레터박스는 반환 이미지의 강제 변형으로 복구하지 않는다. 선택 크롭이 3:1을 넘으면 원본 페이지의 실제 주변 픽셀로 생성 입력 문맥을 확장하고 선택 밖은 보호한다. 전체 원본 자체가 길면 기존 native context tile 계약으로 입력을 나눈다. 전경 글자는 생성 전에 필요한 투명 여백과 실제 배치 좌표를 함께 계획한다. 크기 요청은 원본 대비 +10%와 도구의 지원 범위를 함께 고려한다. 도구가 실제 반환 크기를 반드시 지킨다고 보장하지 않는다. 원본 가리기 승인·fingerprint·취소·합성 품질 검사는 유지한다.

실제 42화 001.jpg의 983×300 선택에서 원본 문맥을 사용한 제거 1회, 영역 계획 1회, 네 영역 글자 생성 4회를 실행했다. 작업별 원본·입력·출력·계획은 `.tmp/codex-aspect-native-smoke-0908-native-page`와 `.tmp/codex-planned-lettering-smoke-0908-app-paths`에 있다. 보호한 회차 번호의 픽셀은 동일하며 최종 합성을 직접 확인했다. 보호 입력은 새로 만든 명시적 시험 가이드이고 과거 사용자의 붓질을 복원한 것은 아니다. 앞선 타일 실험의 이음매/미변경 실패도 별도 디렉터리에 보존했다. 생성 결과를 선별 재시도로 교체하지 않았다.

## 원문 제거와 스타일 보존

Codex 영역 제거에서는 선택 경계를 허용 범위로 전달하고 모델이 그 안의 글자와 글자에 종속된 받침을 찾아 지우되 독립적인 그래픽 면의 채움은 이어 복원한다. Koharu 글자 분할이 컬러 제목 일부를 놓쳐 남겼던 문제 때문에 Codex 경로는 그 분할을 필수 입력으로 쓰지 않는다. 완성된 생성 배경을 기존 정렬 경로로 맞춘 뒤 여러 크기로 평활화한 RGB 차이, 주변 톤 보정, 바깥 feather로 합성한다. 허용 범위 바깥 원본은 보존한다. 수동 붓은 칠한 중심부를 반드시 복원하고 설정된 바깥 feather까지만 혼합하며 실제 변경 픽셀을 마스크로 저장한다. 기존 Flux 알고리즘과 자산은 유지했다.

초기 16.1화 9.jpg의 Koharu CPU 마스크 검증만으로 제거 품질을 주장하지 않는다. 후속 컬러 제목·무작위 표본과 Luna/Terra 비교의 성공·실패 기록은 [배경 복원 실험](codex-repair-research-20260908.md)에 있다. 생성 모델이 그림을 삭제한 것과 글자 삭제를 픽셀 차이만으로 완전히 구분하지 못한다. 첫 무작위 표본에서 손 윤곽 손실이 있었고 실패로 남겼다.

효과음 생성에는 정확한 원문 bbox crop을 제공하고, 그 전체 캔버스를 결과 캔버스에 대응시킨다. 원문의 글자 묶음·흐름·빈 간격·크기 차이·색조·표면 질감을 기준으로 전달하며 기본 검정 붓글씨로 통일하지 않는다. 특정 작품/물체/일본어·한국어 사례를 예외로 넣지 않는다. 사용자 확정 문자열은 다시 번역하지 않는다. 추가 검수/재생성 반복을 넣지 않았다. 출력 해상도 요청은 사용자 변경 지시에 따라 원래 도착 crop의 각 변 1.1배이며 도구 최소 지원 크기를 존중한다.

## Windows Codex 프로세스와 경로

실제 바이너리가 존재해도 262자 이상의 작업 폴더에서 Windows 프로세스 생성이 `ENOENT`로 실패했다. 같은 바이너리의 짧은 작업 폴더에서는 초기화와 ChatGPT 계정 읽기가 성공했다. 프로세스와 턴은 앱이 소유한 짧은 임시 폴더를 사용하고 출력 저장 위치와 분리한다. 반환된 이미지 파일은 해당 작업 폴더의 lexical/realpath 경계와 크기를 검증해 읽는다. 종료 뒤 자신의 임시 폴더만 정리한다.

`ENOTCONN`은 자식 프로세스뿐 아니라 stdin/stdout/stderr에서 발생한다. 공통 프로세스 오류 관찰자를 Codex·JSON-lines·Flux 설치·가져오기·타일 병합에 연결하고, CJS 런타임 전송/변환 경로에서도 스트림 오류를 처리한다. 종료 중 두 번째 오류도 미처리 예외로 앱 전체를 종료하지 않으며 요청과 대기를 실패/취소로 마무리한다. 원래 실패 원인을 조용한 재시도로 감추지 않는다.

## 영역 번역의 가리기 이미지 읽기

실패한 선택 영역 파일의 절대 경로는 260자였다. 같은 실제 PNG에서 Electron `createFromPath`는 빈 이미지를 반환했고 `readFile` → `createFromBuffer`는 488×192로 정상 디코딩했다. 가리기 사본 생성은 기존 `loadImageForRegionCrop` gateway의 경로/바이트/WEBP 변환 계약을 사용한다. 승인한 mask와 원본 fingerprint/크기를 계속 검증하고, 작업 취소 신호도 이 디코더에 전달한다. 가리지 않은 원본을 대신 전송하는 경로는 없다.

실제 저장된 가리기 입력으로 원본과 선택 영역을 재생해 검사했다. 960×1378 원본의 가리기 영역 45,837픽셀만 흰색으로 바뀌고 나머지 픽셀은 같았다. 260자 경로의 488×192 크롭도 정상 처리되었다. 원본 파일 bytes와 저장된 가리기 입력은 수정하지 않았고 임시 전송 사본만 정리했다.

## 단일 페이지 폰트 오류 수정

`No frozen pixel cutoff`는 반복 글자 비교가 12쌍 미만일 때 기준값이 없는 정상적인 입력을 오류로 처리하던 버그였다. 기준값이 없으면 추가 문맥 복구·그 기준값을 쓰는 묶기만 생략한다. strict OCR 검증 결과와 후속 S5/S20/C23 선택은 유지한다. 임의 기준값이나 이전 폰트로의 조용한 대체는 없다. 변경한 런타임 소스의 SHA를 manifest에 함께 갱신했고 학습 자산은 변경하지 않았다.

- 실패한 실제 입력: 자체 비교 4쌍, 검증 글자 46개. 수정된 단계가 46개를 보존했고 CPU 후속 경로가 8개 영역의 고유 선택 8개를 반환했다. 새 OCR/LLM/ImageGen 요청 없이 저장된 실패 입력을 별도 임시 출력에 재생했다.
- 정상 입력 parity: 70영역 분석 JSON 일치, 570개 glyph의 디코딩 픽셀 일치. Python/Pillow 환경에 따른 PNG 인코딩 bytes 차이는 픽셀 차이로 세지 않았다.
- Python 회귀: 근거 없는 추가 글자 승인 금지, 기준값 null 보존, 기존 C23 복구 보존 검증. 번역 단계 오류는 작업 센터/알림에 실제 오류 원인을 전달하며 아직 실행하지 않은 인페인팅 실패 문구로 덮지 않는다.

실제 production component QA는 4K, 좁은 창, 200%에 대응하는 CSS viewport에서 수행한다. 최종 테스트/빌드 기록은 커밋 검증 결과와 Check workflow가 권위다. 사용자 library와 원본·출력·가리기 저장값은 정리하지 않는다.

## 모델 선택 안내와 마무리 검증

이미지 도구 설명은 Astra를 강력 권장한다. Astra 이외 이미지 모델을 선택하면 공용 경고 상자를 표시하며, 로그아웃해 컨트롤이 비활성화돼도 선택값과 안내를 유지한다. 일반 번역 엔진 선택에는 이 경고를 표시하지 않는다. Astra로 다시 선택하면 경고가 사라진다. 제품 모델 목록은 Astra/Sol을 유지하고 Luna/Terra는 연구 기록으로만 남긴다.

실제 SettingsModal을 가져온 격리 QA에서 Astra/Sol을 1600×980, 1240×760으로 확인했다. 공용 컨트롤 너비를 유지하고 경고는 전체 행을 차지한다. 바깥 스크롤·텍스트 잘림·버튼 겹침은 없으며 작은 창에서는 기존 모달 본문만 스크롤한다. 모델 전환·로그아웃/로그인 회귀를 포함한 Codex 설정 테스트 19개가 통과했다. 사용자 앱은 재시작하거나 다시 로드하지 않았다.
