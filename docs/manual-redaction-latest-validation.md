# 수동 가리기 검사 간소화

브랜치: `feat/manual-redaction-workspace-20260910`
검증 소스: `5c05e5d44f0de16c7e2f207e81c425ca9916cb79`
Windows Actions: `34549352990` — `Manual redaction checks`, 최종 결과 `success`

## 사용자 요청에 따른 변경

- `6448e4f`: 자동 브라우저 캡처 11개 상태와 관련 스크립트를 삭제했다. 사용이 끝난 별도 감사/통합/의존성 워크플로도 제거했다.
- `5c05e5d`: 가리기 DOM 검사는 기존 21개에서 단순 동작 3개만 남겼다. 화면 열기/다음 페이지, 현재 페이지 확인, 추가 체크박스 없는 선택 확인과 명시적 작업 재개를 검사한다.
- 해상도/언어/툴팁/세부 포커스/대량 선택 UI 시나리오는 자동 검사하지 않는다. 기존 공용 `qa:ui` 도구는 수동 확인용으로 남긴다.
- 새 가리기 화면 컴포넌트와 UI 훅의 파일별 정밀 커버리지 비율 강제는 해제한다. 전체 커버리지 수집/전역 기준/파일 목록 검증, 기존 파일의 기준, 순수 상태/마스크/저장/전송 로직의 기준은 유지한다. 검사 로그에 UI smoke-only 파일 수를 표시한다.
- UI로 반복하던 상태 전환의 핵심은 작은 순수 함수 검사로 확인한다. 원본 보호, 저장 실패/충돌, 전송 승인 검사는 제거하지 않는다.
- 브랜치 Actions는 기존 `npm run check`를 한 번만 실행한다. 별도 집중 검사와 전체 빌드를 중복 실행하지 않고 화면 캡처도 실행하지 않는다.

## 최종 검증

Windows의 완전한 checkout에서 `npm run check`가 통과했고, 검사 결과 보존과 후처리까지 포함한 Actions 전체 결과가 `success`인 것을 확인했다. 검사한 커밋은 위 `5c05e5d`이며 이 결과 기록은 문서만 변경한다.

로컬 Node 22에서는 단순 UI/키보드/상태/초안/캐시 21개와 커버리지 정책 fixture 25개, 타입 검사와 집중 ESLint가 통과했다. 로컬 source-only 자료에서 실행하지 못했던 실제 Git 이력 기반 파일 목록 검사도 최종 Windows 전체 검사에 포함되어 통과했다.

## 중단 후 재개 기준

이 문서와 현재 원격 HEAD가 최신 기준이다. 과거 문서의 자동 캡처 필수 또는 Actions 대기 중 표시는 과거 상태다. 삭제한 UI 시나리오나 임시 워크플로를 복원하지 않는다. 이번 작업은 테스트/CI 간소화이며 제품 UI 코드는 변경하지 않았다. 기존 화면 개선과 사용자 원본/보관함/출력물은 보존한다. 원래 계획의 사전 편집 앱 진입점은 별도 작업으로 남으며, 이번 CI 성공을 그 기능의 구현 완료로 표현하지 않는다.
