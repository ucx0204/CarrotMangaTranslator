# 노트북 CPU 지연 로그와 기본값 수정

사용자가 제공한 `app (8).log`의 2026-09-08 기록을 한정해 확인했다. 기존 전수 감사의 39건/읽기 범위 집계에는 이 추가 요청을 섞지 않는다.

## 확인된 실행 경로

- 번역 엔진은 로컬 Gemma가 아닌 Gemini API였다. 26페이지 API 요청 구간은 14:11:00부터 14:13:50까지 약 2분 50초다. 설정 로그에 Gemma 관련 값도 있지만 해당 번역에서 Gemma가 실행됐다는 증거는 아니다.
- 텍스트 영역 검출의 DirectML 어댑터 탐색에서 PowerShell `Add-Type`이 임시 출력 파일 경로 오류로 실패했다. 검출기는 CPU로 전환했다. 정확히 어떤 사용자 경로가 잘못됐는지는 경로가 삭제된 로그로 확정할 수 없다.
- LaMa Manga는 AMD ZLUDA를 시도했으나 HIP SDK를 찾지 못해 CPU로 전환했다. 이 실패는 위 DirectML 검출기 오류와 별개의 경로다.
- 완료된 실제 LaMa 요청 13개의 CPU 처리 시간 합계는 약 57.9분, 중앙값은 약 159초, 최댓값은 약 21.7분이다. 최초 128px 준비 검사는 제외했다. CPU 모델, 메모리 점유, 절전/발열 상태가 없어 사양 부족 하나만을 원인으로 단정할 수 없다.
- 26페이지 번역과 글꼴 처리에는 완료 기록이 있다. 로그는 원문 지우기 13페이지 완료 후 14페이지 시작에서 끝나며, 전체 지우기 완료는 기록되지 않았다.

## 반영한 변경

1. CPU 인페인팅 경로의 **신규 기본값과 하드웨어 권장값**을 AOT로 변경했다. 지원 GPU 경로는 유지한다. 저장된 LaMa/FLUX와 PaddleOCR 선택은 로드 시 덮어쓰지 않으며, OCR의 신규 기본값은 HayaiOCR다.
2. DirectML 탐색용 PowerShell에 쓰기 가능한 전용 임시 폴더를 제공한다. 상속된 임시 경로가 사용 불가능하면 사용자 임시 폴더 후보를 확인하고, Windows 환경변수 이름의 대소문자 중복을 제거한다. 프로세스 전체 환경은 바꾸지 않는다. 성공·실패 후 해당 탐색 폴더만 정리한다.

LaMa의 해상도나 출력 품질은 이 변경에서 낮추지 않았다. HIP SDK를 자동 설치하거나 저장 모델을 작업 도중 AOT로 바꾸지 않았다.

## 검증

- DirectML 경계 테스트 4건: 없는/파일인 임시 경로, 동시 탐색 폴더 분리, CUDA 장치 지정 보존, 성공·실패 정리. 수정 전 4건 실패, 수정 후 통과.
- 임시 폴더 후보가 모두 쓰기 불가능할 때 컴파일러를 시작하지 않고 원인들을 보존하는 실패 경로도 추가 검증했다. 현재 DirectML 테스트는 5건이며, 해당 소스의 줄/함수 커버리지는 100%, 분기는 87.5%다. 종전 커버리지 기준을 낮추지 않았다.
- 실제 Windows PowerShell을 실행한 별도 재현: TMP/TEMP가 파일을 가리키면 수정 전 Add-Type 실패, 수정 후 같은 조건에서 GPU 어댑터 탐색 성공. 이는 개발 PC에서 경로 오류 복구를 검증한 결과이며 문제 노트북에서 GPU 가속이 가능하다는 보장은 아니다.
- 기본값·저장/복원·GPU 분기·기존 OCR 호환성을 포함한 9개 파일 136개 테스트 통과. 저장된 LaMa와 FLUX 및 Paddle 설정의 bytes가 읽기로 변경되지 않는 것을 확인했다.
- 실제 HardwareSettingsPanel과 OCR/인페인팅 섹션을 사용해 1440×1000, 640×850에서 AOT/Hayai 상태를 캡처하고 직접 확인했다. 잘림·겹침·외부 가로 스크롤이 없었다. 임시 QA 엔트리와 캡처는 제거했다.
- 최종 `npm run check` 26단계 통과: 테스트 6,175건 통과/기존 2건 제외, 기존 커버리지 기준, 빌드, 실제 화면/출력 픽셀 동일성, 긴 경로 이미지 로딩 스모크 포함.

## 번역문 미표시: 미확정 후속

제공된 로그에는 번역문 표시 상태와 개별 블록 렌더링 상태가 없다. 현재 코드는 원문 지우기 작업 중이라는 이유로 번역문을 숨기지 않는다. 사용자에게 T 아이콘의 **번역문 표시**(기본 단축키 V)를 확인하도록 요청했으며 답변을 기다리는 상태다.

표시가 켜져 있는데도 재현되면 해당 페이지의 이미지 준비 ID, 원본 비교 상태, 글꼴 준비 상태, 블록 위치/글자 투명도를 순서대로 확인한다. 지금 로그만으로 특정 표시 버그를 확정하거나 번역 데이터/표시 설정을 강제로 바꾸지 않는다.
