# MCP: 기존 블록 하나의 원문 재판독

## 범위

`carrot_run_block_ocr`는 기존 블록 하나의 현재 원문 영역을 앱의 로컬 OCR로
다시 읽는다. 블록/원문/번역/좌표/서식/제거 이미지/마스크는 저장하지 않는다.
판독과 적용은 별도 요청이다. 여러 블록/페이지 배치, 번역, 자동 영역 수정,
효과음 이미지 생성, 유료 모델 대체 실행은 이번 범위에 없다.

## 사용 순서

1. `carrot_get_page_blocks`로 화 ID, 페이지 ID, 블록 ID와 현재 revision을 읽는다.
2. `carrot_run_block_ocr`에 `chapterId`, `pageId`, `blockId`, `revision`,
   새 UUID인 `requestId`를 보낸다. 좌표를 다시 보내지 않는다.
3. 반환된 `jobId`로 `carrot_get_job`을 몇 초 간격으로 조회한다.
   접수 응답은 완료가 아니다. `status: completed`와 결과를 확인한다.
4. `result.blockOcr.previousSourceText`, `recognizedText`, `differs`,
   `regions`, `warnings`를 비교한다. 원본 픽셀 기준 `sourceRect`와 실제로
   추출한 정수 픽셀 `cropRect`, `sourceCropSha256`도 제공한다.
5. 적용을 지시한 경우에만 기존 `carrot_update_page_blocks`를 호출한다.
   `result.revision`을 사용하고, 선택한 블록의 `fields.sourceText`만 보낸다.
6. 다시 블록을 읽어 원문만 바뀌었는지 확인한다. 시험 원문을 복원하려면
   현재 revision과 이전 `sourceText`를 사용해 별도 편집으로 저장한다.

예를 들어 다음 요청을 서로 구분한다.

> 이 블록을 앱 OCR로 다시 읽고 기존 원문과 비교해줘. 아직 저장하지 마.

> 확인한 판독 결과로 원문만 고쳐줘. 번역과 위치, 서식은 그대로 둬.

사용자가 처음부터 재판독과 적용을 함께 지시한 경우 두 단계를 이어갈 수 있다.
단, 빈 결과나 충돌을 기존 원문 삭제/강제 덮어쓰기로 해결하지 않는다.
외부 AI가 직접 이미지를 읽는 기존 경로도 유지되며 로컬 OCR은 필수가 아니다.

## 판독 결과의 의미

- 입력은 원본 페이지다. 제거 결과나 번역문이 합성된 렌더링을 읽지 않는다.
- 소수 원문 좌표는 유지하고, 포함하는 픽셀 범위만 floor/ceil로 계산한다.
- OCR 임시 입력과 출력은 요청마다 고유하다. 페이지 OCR 캐시를 재사용하지 않는다.
- 여러 검출 영역은 원본 페이지 좌표로 돌려준다. 새 블록을 추가하거나 기존
  블록을 분할/병합하지 않는다. 결합 문구는 앱의 기존 crop 읽기 순서 규칙을 쓴다.
  `readingOrder: app-crop-heuristic`는 완벽한 읽기 순서를 보증한다는 뜻이 아니다.
- 빈 결과는 `noTextDetected: true`와 `no_text_keep_existing` 경고로 알린다.
  기존 원문은 그대로 남는다.
- 원문/결합 문구는 각각 최대 20,000자, 영역은 최대 100개다. 영역별 문구의
  합계도 20,000자 이하다. 초과/잘못된 결과를 조용히 잘라 성공으로 반환하지 않는다.
- 출처/번역/마스크 등 기존 증거가 새 판독과 일치하는지 검토해야 한다.
  경고는 재번역, 제거, 폰트 분석, 기억 갱신을 실행하지 않는다.
- 신뢰도 점수를 만들어내지 않는다. 판독 정확도와 번역 품질을 확정하지 않는다.

## 권한, 점유, 수명

판독 시작에는 읽기와 처리 권한이 필요하다. 이미지 전송/텍스트 편집 권한은
판독 자체에 필요하지 않다. 원문 적용은 기존 편집 도구의 승인 범위를 따른다.
작업 소유권은 기존 승인 연결에 묶이고 다른 연결의 jobId는 조회할 수 없다.

기존 앱의 페이지 인계와 model-runtime 점유를 사용한다. 판독 및 실제 런타임
정리 완료까지 대상 페이지를 점유하고, 이후 비교 대기 중에는 모델이나 페이지를
계속 점유하지 않는다. 적용할 때는 다시 점유하고 판독 당시 revision을 검증한다.
취소는 이미 실행 중인 프로세스의 실제 정리와 별개이며, 정리가 끝나기 전에
다음 로컬 모델을 시작하지 않는다. 실패한 정리를 성공으로 숨기지 않는다.

같은 requestId는 완전히 동일한 입력의 통신 재시도에만 사용한다. 기존 작업의
접수/결과를 반환하며 OCR을 다시 실행하지 않는다. 다른 블록/영역 버전으로 다시
판독하려면 새 requestId를 사용한다. 실패/취소/중단 작업의 명시적 재시도는
기존 `carrot_retry_job`을 쓰며 선택 블록과 원래 revision을 유지한다.

작업 메타데이터는 기존 7일 저널에 남지만 원문과 판독 증거는 저널에 저장하지
않는다. MCP/app 재시작 후 `observationExpired: true`인 기록에는 `blockOcr`가
없다. 완료된 작업을 재시도해서 증거를 몰래 재생성하지 않고 새 판독을 요청한다.
일반 작업 응답에 이미지, 다운로드 URL, 파일 첨부를 붙이지 않는다.

## 개발 검증

`tests/mcpBlockOcr.test.ts`: 영역/소수 좌표/입력 한도, 무변경 판독, 빈 결과,
중복 ID, 오래된 revision, 취소/철회, 기존 원문 편집과 명시적 복원.

`tests/mcpBlockOcrAdapter.test.ts`: 실제 PNG 픽셀 crop, 원본 파일 선택,
고유 임시 경로, 모델 정리 대기/실패, 원본 교체 감지, 실제 executor 점유 연결.

`tests/mcpBlockOcrHttp.test.ts`: OAuth/권한/소유자 경계, 접수/완료 구분,
반복 요청, 명시적 재시도, 일시적 텍스트 증거와 영구 메타데이터 분리,
점유 중 편집 대기 및 요청 종료/취소 후 무변경.

`scripts/mcp-native-block-ocr.cjs`: 기존 Electron 네이티브 시험에 연결된다.
실제 crop/저장/렌더러를 사용하며 OCR 추론 경계만 시험용 구현이다.
실모델 정확도나 실제 채팅 도구 호출 성공과는 구분해 기록한다.

전체 검사와 네이티브/실연결의 최종 결과는 완료 기록에 별도로 남긴다.
