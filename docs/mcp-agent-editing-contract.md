# MCP: AI가 세부 편집을 책임지는 계약

## 사용자 의도

사용자는 보통 블록 ID, 픽셀 좌표, 읽기 순서, 분할 방법을 지정하지 않는다.
"이 부분 마음에 안 들어", "이런 방식 쓰지 마", "이 이름 전부 고쳐"처럼
결과와 선호를 대략 말한다. AI가 앱의 원본·현재 렌더링·블록·문맥을 읽고,
문제와 수정 대상을 판단해서 정밀한 도구 인자를 작성해야 한다.
정확한 도구 입력은 기계 간 계약이지 사람에게 입력시키는 편집 양식이 아니다.

목표는 도구 호출 한 번의 성공이 아니라 관찰 → 판단 → 제한된 수정 →
실제 결과 확인 → 필요하면 재수정 또는 복구의 반복이다. 자연어를 처리하는
주체는 연결된 AI이며, MCP 서버는 기존 앱 기능과 저장 경계를 제공한다.
명령 이름만 추가했다고 자율적인 판단 기능까지 구현됐다고 주장하지 않는다.

## AI의 작업 순서

1. 사용자가 말한 작품·화·페이지와 관련된 현재 자료를 조회한다. 이미지 전송은
   기존 승인 범위 안에서만 한다. 원본과 렌더링의 픽셀 좌표계를 혼동하지 않는다.
2. 기존 원문·번역·영역·서식·읽기 순서를 대조한다. 가장 작고 복구 가능한
   수정 범위를 선택하며, 관련 없는 원고를 함께 고치지 않는다.
3. AI가 블록 ID·영역·문구 배분·서식 기준·순서를 결정해 변경안을 만든다.
   사용자가 이미 해당 편집을 요청했다면 변경안 확인은 AI의 검수 단계이며,
   매번 같은 사람의 승인을 다시 요구하는 단계로 만들지 않는다.
4. 작품이나 대상이 식별되지 않거나, 요청과 다르게 원고를 대량 삭제·재생성할
   위험이 있으면 필요한 범위만 질문한다. "마음에 안 든다"를 보관함 전체 변경,
   유료 호출 또는 기존 보호 설정 해제의 승인으로 해석하지 않는다.
5. 적용 직전에 기존 페이지 점유·권한·revision을 다시 확인한다. 오래된
   제안에 최신 revision만 대입해 강제로 저장하지 않는다.
6. 저장 후 새 블록 목록과 실제 앱 렌더링을 읽어 결과를 검사한다. 저장 성공과
   사용자 요구 충족을 구분한다. 필요한 추가 수정은 새로운 상태에서 계획한다.
7. 오류나 품질 저하가 확인되면 안전하게 되돌리거나 수정한다. 자동 반복은
   횟수·대상·비용을 제한하고 진전이 없으면 원인과 남은 문제를 보고한다.

## 첫 구조 편집 묶음의 경계

- 같은 페이지의 일반 블록 1개를 2개로 분할, 인접한 2개를 1개로 병합,
  블록 1개 삭제를 각각 독립적으로 호출할 수 있게 한다.
- AI가 원본 픽셀 영역·번역 표시 영역·결과 문구를 작성한다. 미리보기는
  변경 전후와 실제 ID 대응, 읽기 순서, 텍스트 손실·표현 변경 경고를 제공한다.
- 추가·삭제·순서 변경을 여러 번 저장하지 않고 기존 앱 트랜잭션에서 한 번에
  반영한다. 지정하지 않은 블록·원본·제거 이미지·마스크 파일은 보존한다.
- 블록 삭제와 원본 이미지의 글자 제거는 다르다. 생성 글자나 특수 배치의
  참조를 안전하게 이관할 수 없으면 적용 전에 설명하고 거부한다.
- 같은 세션에서 구조 변경의 복구 가능 여부·Undo·Redo를 제공한다.
  원문 제거 복구 기록과 구조 복구 기록을 혼동하지 않는다.
- 중복 요청은 새 ID·새 저장을 만들지 않는다. 반대 작업 이후 과거 요청이
  재전송돼도 현재 상태를 뒤집지 않는다. 후속 사용자 편집과의 자동 병합은 제외한다.
- 검토 대기 중에는 페이지를 잠그지 않는다. 실제 변경 동안에는 UI와 저장
  경계에서 충돌 편집을 막는다. OCR·번역·인페인팅 모델은 실행하지 않는다.
- 상태·미리보기·복구 조회에는 파일을 자동 첨부하지 않는다. 실제 이미지
  확인은 기존 렌더링/확대 도구를 명시적으로 사용한다.

## 후속 일괄 편집

특정 글자·말투·폰트가 싫다는 피드백을 AI가 검색과 조건 선택으로 찾아 수정하는
기능은 중요하다. 그 기능 이전에도 블록을 페이지별로 조회해 같은 작업을 할 수
있어야 한다. 검색은 대상 발견, 변경 계획은 범위 확정, 실제 편집은 저장으로
분리한다. 이 문서는 대규모 변경 실행기나 새 모델 큐를 추가하지 않는다.

로컬 모델은 한 번에 하나의 작업만 실행하고, 같은 모델의 확정된 작업을 순차
처리한 뒤 실제 해제를 확인해야 한다. 모델 없는 편집은 페이지·공유 자원 충돌이
없을 때만 제한적으로 함께 처리한다. 기존 Tailscale·인증 저장·승인 정책은 유지한다.

새 구조 편집 계약과 순수 정책 두 파일을 추가하려던 GitHub 요청은 실행 전에
도구 검사에서 거부됐다. 반환된 tree/commit SHA가 없으며 새 구조 편집 기능은
적용·등록·검증되지 않았다. 이 문서는 사용자 의도와 재개 기준만 기록한다.
같은 차단 요청을 다른 수단으로 실행한 것으로 보고하지 않는다.

당근 MCP 기능 조회는 성공했으나 Remote Desktop Commander는 `4090desktop`을
오프라인으로 반환했고 ping도 연결된 장치가 없다고 응답했다. PC 파일·로컬 Git·
실행 중인 앱은 수정하지 않았다. 별도 환경의 Git clone도 DNS 해석 실패로
완료되지 않았으므로 로컬 테스트를 실행했다고 표시하지 않는다.

재개 시 먼저 실제 저장소 HEAD와 연결 상태를 확인한다. 위 계약대로 기존 앱
삭제·읽기 순서·저장 동작의 characterization test를 고정한 다음, 구조 편집의
미리보기·원자적 적용·복구를 연결한다. 같은 브랜치에서 자주 커밋한다.
