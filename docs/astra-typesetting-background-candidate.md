# 실제 제거 배경을 먼저 검수하는 후보 준비

현재 source는 `astra-typesetting-v0.4.5-candidate`이며 discovery-005의 첫 제품
실험을 실행 중이다. 아직 일반화 확인이나 승격을 뜻하지 않는다. 필수 큰 ギロ
효과음은 여전히 실패 상태다.

## 변경한 처리 순서

화 전체 원문 판독·번역, 제거 외곽, 서체 묶음과 실제 폰트 견본은 유지한다.
그다음 각 페이지의 원문 제거를 먼저 수행한다. Astra에 원본 문맥 크롭, 실제
저장 배경의 같은 위치 크롭, 전체 원본 해상도 배경 뷰, 생성된 원시 패치를
구분해서 제공한다. 크롭 라벨에는 페이지 크기, 픽셀 원점과 실제 페이지 끝을
명시한다. 원시 패치가 깨끗해도 정합 실패를 무시하고 적용할 수 없다.

검수는 실제 PNG bytes의 SHA-256과 시도 번호를 확인한다. 12개 대상씩 나누되
같은 불변 배경을 보며, 응답에서 다른 묶음/keep 대상이나 중복 수정을 허용하지
않는다. 검수 중 저장 파일이 바뀌어도 실패한다. 마스크 수정은 해당 원본 문맥의
정규화 좌표이며 기존 `refineCodexSourceRegion`을 통해 적용한다. 수정 응답 자체는
미검증이다. 다음 제거 결과를 실제로 보기 전에는 통과할 수 없다.

앞선 조사 문서의 도구 내 생성 구상 대신 **생성과 검수 모델 호출을 분리**했다.
기존 app-server 검수 turn의 12분 제한 안에서 여러 ImageGen 작업을 기다리게
하지 않기 위해서다. 기존 `preview_erasure`는 초기 외곽 계획에 그대로 사용한다.
새 배경 단계는 별도 실제 결과를 보여 주는 모델 turn으로 진행하며, 동적 도구가
마스크를 즉시 재합성한다고 주장하지 않는다. 거부된 원시 패치를 강제로 붙이거나
정합 임계값을 완화하지 않았다.

배경은 초기 결과와 최대 두 번 보정한다. 이전 제거 사각형을 먼저 복원하고,
이전/수정된 제거 사각형과 연결된 이웃도 함께 다시 처리한다. 아직 전경이 없는
단계이므로 미래 번역 배치 사각형을 이 연결 계산에 넣지 않는다. 최종 시도의
수정도 실제로 다시 보지 못했으면 실패다. 예산을 넘는 생성은 하지 않는다.

배경이 실패한 대상은 식자·효과음 생성 요청에서 제외되지만 **품질 분모에서는
제외되지 않는다**. 판독한 일본어, 번역, 서체 그룹을 가진 숨겨진 편집 가능한
검토 블록으로 저장한다. 판독 불가 영역으로 바꾸거나 번역 성공으로 표시하지
않는다. 성공한 별도 대상은 식자와 독립 전경 재판독을 계속한다. 최종 합성 검수에서
뒤늦게 배경 결함이 발견되면 해당 출력은 복원·실패 처리한다. 이 경우 같은 페이지의
미해결 식자 문제도 남을 수 있으며, 예산을 숨겨 늘리는 재시도를 하지 않는다.

## 선행 수정과 검증의 구분

v0.4.4 준비 수정은 `correctness-preparation-v044/verified.json`에 파일 해시와
전체 26개 검사 통과를 기록했다. 투명 전경의 불투명 검수 표현, source bbox 여백의
거짓 충돌, 궁서체/몽토리 정적 weight 선언 수정이다. 실제 프로덕션 컴포넌트의
넓은/좁은 화면과 일반/굵게 차이도 확인했다. 이는 새 배경 방식의 효과가 아니다.

새 제어 흐름 및 실제 PNG 검수 계약은 단위/통합 테스트로 검증한다. 별도 합성
글자 사전 검증은 실제 Astra 요청으로 한쪽의 잔여 원문과 다른 쪽의 제거를
구분하는지 확인한다. 작은 합성 글자의 성공은 복잡한 망점 효과음 성공이 아니다.
다음 제품 실험은 봉인한 미사용 한 화이며, 퇴역한 discovery-004를 새 일반화
표본으로 재사용하지 않는다. 최초 잠금 6번은 1/10으로 유지한다.

토큰·시간 절약은 실제 새 화 결과가 있어야 비교할 수 있다. 현재는 비용 절약률을
주장하지 않는다. ImageGen 사용량이 없으면 unknown이며 0 토큰으로 계산하지 않는다.
원시 출력, 저장 배경, 독립 전경, 최종 네이티브 출력과 실패 대상을 모두 보고한다.

## 사전 검증 결과

준비 버전은 전체 26개 검사·빌드·실제 artwork parity를 통과했다.
`.tmp/astra-v045-check-02.log`에 156.22초의 전체 실행 결과가 있다.
`background-stage-preflight-v045/result.json`은 실제 Astra high 1회,
누적 6,163 토큰, ImageGen 0회의 검증이다. 원래 글자 두 개 중 첫 번째만 제거한
불변 PNG에서 두 번째 `日`만 실패로 지적했다. 실제 저장 배경의 해시·번호
확인과 원본 파일 보존도 통과했다. 두 입력 PNG를 직접 확인했다.

사용자에게는 이후 실제 만화의 원본·제거안·실제 저장 배경·번역 합성 결과를
중간중간 이미지로 공유한다. 설명이나 내부 보고서만으로 대신하지 않는다.

## 제품 실험과 완료 결과

discovery-005/candidate-001은 2026-09-06T02:35:02.839Z에 시작했다.
trial은 `76427c4e-7057-465f-94ed-44952c0722d1`이며 runtime·폰트·의존 파일
1,750개를 봉인했다. 입력은 미사용 작품의 제8.2화 전체를 연결한 836×16,464
JPEG 한 장이고 원본 해상도 11개 뷰로 처리한다. 선택 후 긴 이미지라는 이유로
다시 뽑지 않았다. 첫 원본 뷰를 후보 봉인 전에 직접 보고 공유했으므로 discovery이며
확인 표본으로 주장하지 않는다. 실행과 실제 저장 결과 감사가 끝나기 전에는
봉인한 source/out/폰트를 바꾸지 않는다.

실제 종료는 2026-09-06T04:18:42.274Z, 1시간 43분 39초다. 두 번째 배경
검수 응답이 알려진 판독 보류 9곳을 미해결로 보고하자 활성 ID만 허용하는
검증기가 예외를 냈다. 중복 수정이나 존재하지 않는 ID는 없었다. 30회 Astra의
누적 토큰 979,154개와 57회 ImageGen 요청 영수증을 보존했다. 생성 사용량은
모두 unknown이다. 최종 저장본은 블록/제거 배경 없이 원본을 보존하며 전체
RGBA 차이가 0이다. 181곳의 번역 성공은 0이며 검토 블록 0을 통과로 세지 않는다.

실제 중간 배경 11개 네이티브 뷰를 직접 봤다. 일반 말풍선은 대체로 제거됐지만
효과음과 그림 위 서술 등 많은 원문이 남았다. 생성 배경 57개 중 기존 정합
검사 통과는 5개이며 이것도 품질 gold가 아니다. 마스크 밖 변경은 0이다.
`candidate-001/completed-output-audit/evidence.json`, `direct-audit.json`,
`cost-receipt-audit.json`, `report.html`에 실제 저장 상태와 진단을 구분했다.
감사 완료 때까지 1,750개 runtime 파일을 다시 대조했다. 다음 후보에서 알려진
보류 관찰과 활성 수정 대상을 분리하고 사용자 승인 feather 기법을 연결한다.

동일 runtime으로 원본 전체를 렌더링한 네이티브 출력은 836×16,464를 유지하며
원본 디코딩 픽셀과 차이가 0이다. 이는 긴 이미지의 렌더링 경로 검사이며 원문 제거나
번역 품질의 성공 증거가 아니다. `candidate-001/native-source-parity/result.json`에
실제 출력 해시와 변경 픽셀 수를 기록했다.

초기 제거 범위 검수 중 `part-4:r10`의 `ドキーン…`은 revision 2에서 빈 제거
범위로 남았다. 원문과 첫 마스크를 사용자에게 이미지로 보여 주고 미해결임을
명시했다. 다른 효과음의 범위가 만들어졌다는 사실을 이 대상의 성공으로 대체하지
않는다. 각 완료된 묶음의 실제 emitted PNG를 네이티브 보드로 보존하며 final 응답의
revision/SHA와 맞는 미리보기만 감사한다. 보드는 제거 계획 단계이며 생성 배경이나
최종 번역본으로 표시하지 않는다.
