# 배경 복원과 식자의 분리 검증 — 네 번째 전환

현재 v0.4.3의 14쪽 실험은 동결 상태로 계속한다. 새 제품 후보를 실행하거나
거부된 패치를 적용하지 않았다. 이 문서는 다음 미사용 화에서 검증할 방향이며
구현 완료·승격·품질 통과를 뜻하지 않는다.

## 이번 관찰이 요구하는 변화

3쪽의 옷 위 カチャ와 얼굴 위 パアァァァ는 제거 대상으로 잡혔다. 생성 원본은
일본어를 지웠지만 망점·주름·머리카락까지 바뀌어 실제 정합 검사에 탈락했다.
그 상태에서 한글 효과음을 생성하고 배치하니, 사용자가 올린 두 캡처처럼 원문
위에 한글이 겹친다. 같은 마스크와 문맥에 실패 사유 문장만 더해 재생성하는
현재 흐름은 이 반복을 해결하지 못했다. 숫자 임계값을 완화하는 새 실험은 하지 않았다.

다른 실패도 분리해야 한다. 첫 쪽은 실제 제거/전경이 keep 픽셀을 침범하지
않는데 source bbox 여백만으로 실패한다. 궁서체·몽토리의 보통/굵게 견본은
실제 픽셀이 같다. 4쪽의 읽히는 효과음은 투명 PNG 재판독에서 빈 문자열이
된다. 마지막 문제는 같은 이미지의 흰 matte와 원래 RGBA를 각각 보낸 실제
Astra high 두 호출로 재현했다. 이런 오류를 생성 품질 부족으로 묶으면 재시도
횟수와 비용 판단까지 잘못된다.

## 조사 근거와 적용 한계

`research-transition-004/query-ledger.json`에 200개 고유 질의와 50개 원시
검색 응답의 해시를 봉인했다. 앞선 600개 질의와 정규화한 완전 중복은 없다.
이는 논문 200개를 읽었거나 적용 가능한 방법을 200개 찾았다는 뜻이 아니다.
검색에 섞인 의료·영상·3D·학습 전용 방법을 이 앱의 성능 근거로 쓰지 않는다.
선택한 원문 조회는 `primary-read-001.json`, `primary-read-002.json`에 있다.
일부 CVF PDF는 403으로 읽지 못해 연구자/기관의 공개 초록을 확인했다.

- [MIRA](https://arxiv.org/abs/2511.21087)는 시각 피드백에 따라 다음 편집을
  선택하는 반복 구조를 다루지만 별도 도구 사용 데이터와 학습을 사용한다.
  여기서 가져오는 것은 실패 이미지를 실제로 다시 보는 실험 가설이다.
  그 논문의 성능이나 학습 효과를 Astra에 그대로 적용했다고 하지 않는다.
- [Zoom-to-Inpaint](https://research.google/pubs/zoom-to-inpaint-image-inpainting-with-high-frequency-details/)는
  고해상도 복원·정제·다운샘플과 학습을 결합한다. 작은 크롭을 단순 확대하면
  내장 ImageGen의 선/망점 위상이 보존된다는 근거가 아니다. 생성 문맥과 실제
  붙이는 해상도를 독립적으로 기록해야 한다.
- [Manga Restoration](https://ttwong12.github.io/papers/mangarestore/mangarestore.html)은
  망점의 리샘플링/aliasing과 복원 가능한 무늬를 구분한다. 현재 결과가 비슷한
  회색이라는 이유만으로 원래 망점 경계와 연결된다고 판정할 수 없다. 해당
  학습 모델을 설치하거나 원문 망점을 전부 새 무늬로 교체하지 않는다.
- [TransFill](https://arxiv.org/abs/2103.15982)은 다른 참고 사진의 여러 기하
  변환과 학습된 픽셀 보정·융합을 사용한다. 작은 비강체 정렬을 무조건 허용할
  근거가 아니다. 직접 변형을 도입하려면 접힘, 윤곽 이동, 대응점 없는 제거
  영역, 반복 망점의 모호함을 별도 검증해야 하므로 다음 첫 후보에서는 보류한다.
- [BPM](https://arxiv.org/abs/2506.13827)은 변경할 영역과 보존할 영역의 판정을
  나눈다. 우리도 원문 제거 완수와 원본 보존을 서로 다른 지표로 기록한다.
  원문을 복원한 fallback은 보호 동작 성공일 수 있지만 번역 품질 성공은 아니다.

## 다음 메커니즘의 범위

주요 가설은 **실제 제거 배경을 먼저 보고 확정한 뒤 식자한다**는 것이다.
현재의 `제거 계획 → 생성 → 식자 → 전체 검수`에 묶인 실패를 분리한다.

1. 화 전체 판독/번역 및 원문 서체 묶음은 유지한다. 원문 위치, 제거 허용 영역,
   생성 문맥, 번역 배치 공간은 서로 다른 값으로 취급한다.
2. Codex에게 원본과 실제 제거 배경을 보여 주는 실행형 도구를 준다. 실패한
   생성 이미지와 실제 국소 합성 결과도 함께 보되, 거부된 정합을 성공으로
   우회할 수 없게 한다. 문맥 크롭에는 원본 페이지 크기·픽셀 원점·실제 페이지
   가장자리 여부를 명시한다. 마스크 수정은 실제 결과 번호/해시에 묶는다.
3. 배경의 잔여 획, 말풍선/그림 손상, 망점·선 경계를 먼저 판정한다. 초깃값과
   최대 두 번 보정 예산을 명시하고, 실패 영역은 원문과 검토 표시를 유지한다.
   배경 실패 위에 한글 효과음을 생성하는 호출은 생략한다. 성공한 별도 영역은
   계속 처리한다. 초기 결과/실패 영역을 몰래 출력 분모에서 빼지 않는다.
4. 배경이 확인된 영역을 식자하고, 실제 출력과 독립 재판독으로 검수한다.
   검수용 RGBA는 검정/흰색/혼합 글자가 보이는 명시적인 불투명 표현을 사용한다.
   원래 투명 asset은 보존한다. 기대 문자열은 재판독 이미지와 프롬프트에서 제외한다.

여러 인접 효과음에 더 넓은 문맥을 함께 주는 방법은 유망한 **별도 비교 후보**다.
초기 배경 단계 분리와 한꺼번에 섞어 효과를 주장하지 않는다. 결합한다면 대상별
예산과 실패 복원 연결 관계, 공동 생성에 따른 간섭을 새 사전 계약에 적어야 한다.

## 선행 수정과 평가

현재 화의 실제 저장본/레이어 보고를 끝낸 뒤 source bbox 거짓 충돌, 투명 전경
재판독, 정적 서체 weight 선언을 재현 테스트와 실제 렌더로 고친다. 이것들은
명확한 공학적 결함이며 새 배경 메커니즘의 품질 향상으로 섞어 집계하지 않는다.
정적 서체 수정은 추후 폰트 팔레트 워크트리와 공유 계약이 충돌하지 않도록 한다.

discovery-004는 보고 완료 뒤 퇴역하고 다음 후보는 봉인한 미사용 한 화에서
실행한다. 기존 6번은 1/10 상태를 유지하며 자동 재실행하지 않는다. 원문 전체,
고정 제거 배경, 독립 전경, 실제 최종 출력과 검토 상태를 나란히 직접 확인한다.
사용 가능한 UI·저장/재열기·편집·출력 검증과 다른 작품의 미사용 화 두 개 확인
전에는 승격하지 않는다. 논문, 도구 사전 검증, 부분 보존 어느 것도 이를 대신하지 않는다.
