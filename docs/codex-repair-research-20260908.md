# Codex 배경 복원 합성 실험

## 계약

- 목표: 생성 배경을 원본에 정렬한 뒤, 미세한 차이는 무시하고 실제 제거로 바뀐 부분만 합성한다. 자동 글자 분할의 누락을 제거 성공으로 오인하지 않는다.
- 실제 경로: 앱의 Codex 원문 제거 엔진 및 영역 번역/그린 영역 지우기 경로. 번역 엔진, 프롬프트, 추론 강도, 이미지 크기 요청, 합성을 시험용으로 바꾸지 않는다.
- 고정: 원본 읽기 전용. 숨은 생성 재시도 없음. 첫 표본은 Astra/low. 결과는 새 출력에만 저장한다. 수동 붓은 칠한 중심부를 복원하고 설정된 바깥쪽 feather까지만 혼합한다. 한 번의 생성 결과를 버리고 더 좋은 재시도로 교체하지 않는다.
- 표본: 사용자가 지정한 Tachidesk mangas에서 한국어 제외, 파일 중복 없는 무작위 10장. seed/inventory/입력 SHA를 먼저 저장한다. 첫 10장에 중요한 회귀가 없으면 새 10장으로 진행한다. 컬러 제목 발견 사례는 fresh 검증에 세지 않는다.
- 경로 배분: 영역만 지정하는 제거와 붓으로 가이드하는 제거를 모두 실제 제품 함수로 실행한다. 사람이 고른 영역/붓 좌표는 생성 전 봉인한다.
- 평가: 모든 결과의 원문 잔존, 비문자 그림 손실, 경계/망점/위치 흔들림, 지정 외 변경, 실패·취소·데이터 보존을 직접 확인한다. 수치는 의미적 정확성의 대체물이 아니다.
- 증거: 모든 입력/설정/출력/실패/소요시간과 self-contained HTML 비교 보고서. 결론은 promote/reject/ambiguous. 애매한 후보를 완료품으로 홍보하지 않는다.

## 발견 사례와 기각 기록

1. 1.jpg 컬러 제목: 기존 Koharu crop 검출에서 제목 왼쪽/위쪽이 마스크에 없었다. 실제 생성 배경에도 해당 원문이 남았다. 마스크 일부의 변화로 블록 전체를 완료 처리한 것은 품질 증명이 아니다.
2. 로컬 진단: 일반 crop, 여백 추가, 회색조, 채도 평탄화로 분할을 비교했다. 어느 것도 전체 제목을 충분히 검출하지 못했다. 제품 파라미터로 승격하지 않았다.
3. 투명 복원 조각 요청: 1회 생성했지만 투명 픽셀이 0개인 전체 배경(2062×763)이 반환됐다. 글자는 제거됐으나 RGBA 조각 계약에는 실패했다.
4. 단색 matte 복원 조각 요청: 1회 생성, 여백/조각 배치가 어긋나 기각했다. 자동 재요청 경로로 제품에 넣지 않는다.
5. 전체 배경의 정렬+차이 추출 발견 시험: 기존 registration을 재사용하고 여러 크기로 평활화한 RGB 차이, 작은 확장과 feather를 적용했다. 제목은 제거됐지만 일부 망점/경계도 선택됐다. 사용자가 납득할 수준으로 평가했으나 컬러 사례만으로 승격하지 말고 무작위 10+10장 검증을 요구했다. 현재 임시 고정 임계값은 검증된 제품값이 아니다.

## 한계

생성 모델이 비문자 물체를 실제로 삭제한 결과와 글자 삭제는 픽셀 차이만으로 완벽히 구별할 수 없다. 정렬 신뢰도와 변화 영역을 보고하고 붓/복구 도구를 유지한다. 생성 모델 출력의 의미적 오류를 합성 성공 검사로 숨기지 않는다.

## 첫 10장과 사용자 수용 기준

`.tmp/codex-repair-round1/sample.json`의 고정 표본 10장은 각각 생성 1회로 실행했다. 모든 원본 SHA는 유지됐다. 전송 완료 10건을 시각적 성공 10건으로 해석하지 않는다.

- 영역 1·3·7·9: 글자가 제거됐다. 3·9의 경계/톤 차이는 같은 생성 원본을 다시 합성해 비교했다. 추가 생성은 없었다.
- 영역 5: 잘못 선택한 비문자 동작선/손 주변을 모델이 삭제했다. 실패로 남기며 다른 표본으로 대체하지 않는다.
- 붓 2·4·6·8·10: 일부 글자 끝/작은 찌꺼기가 남았다. 지정 범위 밖의 원문과 중심부 차이 필터 누락을 구분해 기록했다. 후속 구현은 칠한 중심부를 차이 임계값과 무관하게 복원하고, 바깥쪽 feather 범위까지 모델 입력/합성에 반영한다.

톤 보정은 보호된 주변 문맥에서 밝기 구간별 RGB 차이를 추정하며, 검정/흰색 끝점은 유지한다. 바깥쪽 feather는 기존 거리 변환을 재사용한다. 생성 이미지 전체를 무조건 덮어쓰지 않는다.

컬러 제목의 문자와 일체인 바탕 장식까지 제거하는 새 요청은 사용자 지시 이후 1회 실행했다. `.tmp/codex-repair-title-decoration/0`에 원본, 생성 출력과 합성 결과를 보존했다. 사용자는 톤+feather 결과에 대해 “완전 무결은 바라지도 않으니깐 저정도면 합격임”으로 수용했다. 추가 미세 조정 대신 다음 표본으로 진행한다.

## 사용자 지시로 축소한 Luna 시험

두 번째 최초 무작위 10장에 이전 한국어 번역 export 4장이 섞여 있었다. 생성 전 발견했다. 최초 목록은 `.tmp/codex-repair-round2/initial-draw-invalid-translated-exports.json`에 보존했다. 사용자는 새 페이지로 채우지 말고 그 4장만 제외하도록 지시했다.

`.tmp/codex-luna-sfx-six`는 최초 번호 1·3·5·6·7·8을 유지한다. 8번에는 일본어 효과음이 없어 생성 없이 제외한다. 나머지 5장은 효과음 판독/번역 1회, 원문 제거 1회, 한국어 글자 생성 1회를 실행한다. 모델은 사용자가 지정한 `gpt-5.6-luna`, 추론은 `xhigh`다. 앱 모델 선택기 승격 전 시험이므로 생산 클라이언트에 모델을 명시하며, 제품 계정·기본 설정은 변경하지 않는다.

생성 크기는 사용자 지시대로 두 작업 공통 요청에서 원본 크롭의 1.2배에서 1.1배로 변경했다. 도구 최소 크기를 강제로 낮출 수 있다고 주장하지 않는다. 요청 크기, 실제 출력, 사용량, 시간을 기록한다. 판독은 생산 SFX 프롬프트와 전체 문맥/대상 크롭 작성 함수를 사용한다. 페이지 스케줄러·자동 재판독은 시험에 포함하지 않는다. 생성·합성·투명 글자·최종 렌더는 생산 함수를 호출한다.

추가적인 크롭 정책/결과 캐시 최적화는 사용자가 원하지 않아 이번 변경에 추가하지 않는다. 각 대상은 기존 결과 재사용 없이 새로 실행한다. 일반 SFX 판독 프롬프트의 고정 번역 예시도 제거하고 문맥·음의 강도·반복을 보존하는 일반 지침만 유지했다.

### Luna 첫 결과

- 5장 모두 제거 1회 + 글자 생성 1회를 반환했다. 원본 SHA는 모두 유지됐다. 최종 비교는 `.tmp/codex-luna-sfx-six/index.html`과 `review.json`에 있다.
- 영역 3·5·6은 시각적으로 글자를 제거하고 배경을 복원했다. 검정 채움/흰 테두리, 흰 채움/검정 테두리, 가는 외곽선 등 서로 다른 원문 표현으로 한국어 글자가 생성됐다.
- 붓 1·7은 실험자가 그린 가이드가 일부 획을 놓쳤다. 원문 조각이 남았으며 이 두 결과를 제거 합격으로 세지 않는다. 입력 오류를 Luna 자체의 제거 능력으로 단정하지 않는다.
- 판독은 별도 한계가 있다. 1번 웃음 표현의 오독, 5번 첫 글자 あ→ま, 6번 ダンッ→ガタガタ 등이 관찰됐다. 사람이 정답을 넣어 이미지 결과를 교체하지 않았다. 따라서 이미지 보조 도구 가능성과 Luna의 일본어 판독 성능을 분리해 판단한다. 제품 모델 선택기는 아직 Luna를 해금하지 않았다.
- 보고된 Codex 토큰은 95,995, 순차 실행 시간 합은 752.7초다. 이미지 도구 내부 비용을 확정한 수치가 아니며, 서로 다른 표본/추론 조건의 Astra 결과로 절감률을 주장하지 않는다.
- 실험용 최종 렌더 연결에서 `file:` URL과 누락한 일반 블록 기본 필드 때문에 오류가 났다. 앱의 허용된 PNG data URL과 기본 필드를 사용해 저장된 결과를 다시 렌더했다. 생성 이미지·문구·마스크를 바꾸거나 재생성하지 않았다. 최초 오류와 복구 기록을 각각 보존했다.
- 1.1배의 부동소수점 계산에서 100px을 111px로 올리는 오차를 발견해 제품은 `(size * 11) / 10` 이후 올림하도록 수정했다. 최초 요청 기록은 그대로 보존했다.
- 사용자의 후속 의견에 따라 판독/의미 해석을 분리하는 일반 지시 후보를 같은 입력에서 비교하려 했으나 첫 응답을 수 분간 받지 못해 실험 프로세스를 중단했다. 후보와 취소 사유는 `reading-contract-v3`에 남겼고 제품에는 승격하지 않았다. 추가 이미지 생성은 없다. 취소된 요청의 원격 사용량은 반환되지 않았다.
- 당시 관련 57개 테스트와 Electron 컴파일을 통과했다. 이후 삭제된 파일의 coverage 범위를 정리하고 실제 오류/취소/가리기 회귀 검증을 추가해 전체 `check` 26개 게이트를 통과했다(5,824개 테스트 통과, 플랫폼별 2개 제외). 기존 파일의 coverage 하한은 낮추지 않았다. 범위·근거 변경은 `production-cleanup-scenario-ledger.md`에 기록했다.

### Terra 동일 영역 비교

사용자 요청으로 Luna 표본 중 영역 지정 3·5·6번을 `gpt-5.6-terra` / `xhigh`로 실행했다. 원본 SHA, 선택 좌표, 생산 함수와 해상도 +10% 요청을 유지했다. 붓 가이드가 불완전했던 1·7번은 제외했다. 판독·제거·글자 생성은 각각 1회, 총 9회 모델 요청과 6회 이미지 생성이며 재시도는 없다. 원본 SHA는 모두 유지됐다.

- 3번: 제거는 깔끔하지만 ペコッ으로 보이는 원문을 ズンッ → 쿵으로 읽었다. 생성 글자가 원래 배치보다 크고 중앙에 뭉쳤다. Luna의 판독이 더 나았으며 Terra의 판독/배치는 실패로 기록한다.
- 5번: あ 계열 감탄사를 あああっ → 아아앗으로 읽어 Luna의 첫 글자 오독보다 나았다. 흰 채움·검정 테두리·글자 크기 차이를 유지하고 바닥을 복원했다.
- 6번: ダンッ으로 보이는 원문을 ゴンッ → 쿵으로 읽었다. 한국어는 Luna의 덜컹덜컹보다 장면에 가까워 보이지만 원문 판독은 여전히 틀렸다. 제거와 외곽선 질감은 괜찮으며 원래 분산 배치보다 중앙에 모였다.

보고된 Codex 토큰은 Terra 29,923 / 같은 세 장의 Luna 51,420, 순차 시간 합은 327.941초 / 424.440초였다. 각각 1회의 관측이며 일반적인 성능·가격 차이나 이미지 도구 내부 비용을 증명하지 않는다. 각 모델이 읽은 문구로 생성했으므로 글자 생성만의 통제 비교도 아니다. 더 높은 모델이 모든 사례를 더 잘 처리한다는 가정은 이번 결과로 뒷받침되지 않는다. Terra/Luna를 제품 기본값으로 승격하지 않았다.

비교 화면과 원래 요청·실제 크기·사용량은 `.tmp/codex-terra-sfx-three/index.html`, `review.json`, 각 번호의 원본 JSON/PNG에 보존한다. 실행 스크립트와 생산 JS는 `executed-code`에 봉인했다. 생성 뒤 수동 문구 수정이나 결과 선별은 하지 않았다.

### Terra 수동 번역문 확정 시험

사용자 요청으로 같은 영역 3·5·6에서 앱의 `editTranslatedPageWithCodex`와 `confirmReading`을 사용했다. 원문 판독과 좌표는 유지하고 사용자가 입력하는 번역문만 각각 꾸벅·아아앗·쿵으로 확정했다. 기존 생성 이미지를 재사용하지 않고 원본에서 제거 1회와 글자 생성 1회를 새로 실행했다. 신규 판독 호출·생성 재시도는 없다. 총 6회 생성, 기록된 생성 시간 합 281.032초이며 토큰 사용량은 반환되지 않아 null로 기록한다.

- 3번은 꾸벅이 생성됐다. 검정 채움과 흰 외곽선은 원문과 유사하지만 배치·크기가 완전히 같지는 않다.
- 5번은 정확한 아아앗을 프롬프트에 전달했으나 첫 글자가 하처럼 보이고 마지막 받침도 모호하다. 수동 입력이 이미지 모델의 글자 모양 오류까지 보장하지 않는다. 실패를 수정된 이미지로 교체하지 않았다.
- 6번은 쿵으로 생성됐다. 외곽선 표현은 유지하지만 원문보다 따뜻한 베이지색과 입자가 추가됐다. 완전한 스타일 일치로 세지 않는다.

첫 격리 실행은 설정 저장소 검증에서 생성 전 중단됐다. 실제 앱 설정을 수정하지 않고 시험 프로세스에만 기본 설정 스냅샷을 공급했다. 3번 최종 렌더 이후 Electron의 마지막 창 종료 때문에 완료 JSON 기록이 빠진 사실도 그대로 남겼다. 뒤의 5·6번은 격리 러너의 종료 수명만 수정해 각각 처음 실행했다. 원본 SHA와 원문/위치는 모두 보존됐으며 세부 기록은 `.tmp/codex-terra-manual-confirmed/index.html`, `review.json`, `executed-code`에 있다.

Luna/Terra는 실험용으로만 호출했고 앱 모델 목록에는 추가하지 않았다. 제품의 이미지 기본 모델은 Astra, 이미지 생성 추론 기본값은 낮음이다. 이미지 도구 설명에 Astra를 강력 권장하고, 다른 이미지 모델 선택 시 기능이 제대로 동작하지 않을 수 있다는 경고를 표시한다. 일반 번역 모델에는 이 이미지 경고를 적용하지 않는다.
