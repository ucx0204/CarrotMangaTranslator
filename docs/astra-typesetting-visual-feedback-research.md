범위가 빗나간 결과와 저자 목록은 제품 변경의 근거에서 제외했다.

- [PSSTRNet](https://arxiv.org/html/2306.07842v1)은 이전 제거 결과와 마스크를 다시
  관찰해 누락된 글자 영역을 수정한다. 반복 횟수가 커지면서 왜곡이 증가하는 반례도
  보고한다. 학습한 신경망과 SCUT 데이터의 결과이므로 Astra의 성능 예측은 아니다.
  가져올 가설은 재생성보다 먼저 잘못된 마스크 자체를 수정해야 한다는 것이다.
- [FocalClick](https://arxiv.org/html/2204.02574v2)은 이미 맞는 마스크를 반복 추론이
  망가뜨릴 수 있음을 다루며 의도한 국소 수정만 합친다. 클릭을 받는 학습된 분할
  모델이다. 해당 가중치나 처리 속도를 현 앱에 가져오지 않는다. 성공한 영역의 상태를
  보존하고 수정 범위만 갱신하는 계약에 참고한다.
- [Vision-Guided Iterative Refinement](https://arxiv.org/html/2604.05839v1)는 실제
  웹 렌더를 바탕으로 코드를 수정한다. 반복의 토큰·지연 비용과 VLM 평가자 편향을
  함께 지적한다. 만화·Astra 검증은 아니므로 렌더 피드백이라는 방식만 후보로 남긴다.
- [EditInspector](https://aclanthology.org/2025.acl-long.1428/)는 편집 정확성, 아티팩트,
  접합과 시각 품질을 나눠 검사하고 모델 평가가 변경 내용을 잘못 설명하는 문제를
  보고한다. 자동 검수의 빈 issue 목록만으로 승격하지 않는 이유다.
- [Codex 공식 소스](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/dynamic_tools.rs)와
  현재 번들 0.153.1에서 생성한 `DynamicToolCallResponse.json`은 tool 결과의
  `contentItems`에 `inputText`와 `inputImage/imageUrl`을 허용한다. 현재 앱은
  experimentalApi=false이고 서버 요청을 기본 거절한다. 아직 실행형 시각 도구를
  연결한 것은 아니다. 로컬 버전의 schema와 실제 synthetic 왕복 시험이 우선이다.

## 실행형 도구의 최소 계약

다음 구현 전에 synthetic fixture로 현재 Codex 바이너리가 실제 이미지 tool 결과를
받고 그 결과에 근거해 수정하는지 확인한다. 원고의 새 후보로 세지 않으며, 이 시험이
통과하기 전 앱에 기능이 연결됐다고 하지 않는다.

도구는 region ID, 원본 좌표, 실제 이미지 크기, proposal revision을 입력 권위로 삼는다.
임의 파일 경로 대신 실행에 등록된 원고/영역만 조회한다. 실제 production 마스크와
renderer가 만든 결과를 돌려준다. 최종 제안은 마지막으로 렌더한 proposal 해시와 일치해야
한다. 말로 "봤다"는 설명만으로 새 좌표를 승인하지 않는다. JSON 유효성은 시각 품질과
별개의 검사다.

마스크 검토는 흰색/검은색 배경의 실제 제거 시안과, 그림 위 글자의 원문·마스크를
구분해서 제공한다. 아직 복원하지 않은 그림을 성공적인 배경처럼 표시하지 않는다.
미완료 영역만 수정하되 보존 숫자와 인접 원문에 대한 충돌 검사는 매번 적용한다.
초기 제안과 최대 두 번 수정이라는 한도를 먼저 고정하고 초과하면 원문을 보존한다.

화 전체 원문 crop 비교, 서체 계열과 처리 강도의 분리, 최대 10개 실제 프리셋 폰트,
폰트 용도 설명, 편집 가능한 번역 레이어와 고정 배경, 최종 전체 native 검수는 유지한다.
다음 새 원고 후보를 실행하기 전에 최종 변경 묶음·예산·실패 조건을 별도로 사전 등록한다.
이번 discovery-003은 마스크 부족의 같은 실패 가족이 확인됐으므로 최종 보고서 이후
같은 화에서 후보 5를 추가하기보다 다음 미사용 화로 이동한다. 기존 6번은 1/10이며
자동 재생하지 않는다.

## 비용 비교 전에 필요한 계측 수정

현재 `observeTurnAccounting`은 `tokenUsage.last`만 저장한다. 번들 schema에는
`last`와 `total`이 별도로 있고,
[공식 소스 설명](https://github.com/openai/codex/blob/main/codex-rs/tui/src/token_usage.rs)은
전자와 누적 세션 총량을 구분한다. 도구를 여러 번 사용하는 한 턴의 총량을 마지막
응답만으로 비교하면 안 된다. 기존 기록은 저장된 마지막 사용량 snapshot의 합이며,
그 자료만으로 과거의 누락된 중간 요청 사용량을 복원하거나 정확한 비용을 단정하지 않는다.
ImageGen 사용량 unknown도 계속 분리한다.

후속 구현은 새 ephemeral thread의 누적 총량과 마지막 snapshot을 구분해서 남기고,
장기 세션을 도입한다면 실행 전후 누적 차이를 써야 한다. 같은 알림 재전송을 합산해서
이중 집계하지 않는다. 이 계측 변경은 현재 동결된 v0.3.4에 섞지 않는다.
서로 다른 화의 총량 차이나 마지막 snapshot만으로 절감률을 만들지 않는다.

### 계측 source 수정 · 현재 실행에는 미적용

`codexAppServerTransport`는 thread/turn에 해당하는 마지막 알림의 `total`과 `last`를
별도로 보관한다. 같은 누적 알림을 합산하지 않는다. `runEphemeralTurn`의 새 세션만
`tokenUsageScope=ephemeral-thread-total`을 붙인다. `total`이 없으면 `last`를 대신
전체 사용량으로 표시하지 않는다. 이전 immutable 실행 기록은 바꾸지 않았다.

실제 child-process fixture로 item/turn 완료 두 경로에서 누적 알림 여러 번, 중복 알림,
다른 thread/turn, last-only, 알림 부재를 검증했다. 관련 21개 테스트와 typecheck/lint,
architecture/maintainability 검사는 통과했다. v0.3.5 source 준비에만 포함되며 동결된
v0.3.4 out/는 그대로다. 앞으로 persistent thread를 도입하면 이 총량을 턴 사용량으로
재사용하지 말고 실행 전후 차이와 누락 여부를 별도로 정의해야 한다.

## 다음 source 묶음 사전 등록 · v0.4.0 준비

현재 v0.3.4 실행과 보고서가 끝날 때까지 out/를 동결한다. 새 원고를 예약하기 전에
다음 변경을 구현·검증한다. v0.3.5 폰트 견본과 누적 사용량 수정도 이 묶음에 포함한다.

- 제거 계획 요청에만 전용 dynamic-tool capability를 사용한다. 기존 번역/조사 경로의
  권한은 그대로 유지하고, 실행에 등록된 원고의 마스크 미리보기만 제공한다.
- 한 batch의 전체 제거 계획을 실제 production geometry/mask로 표시한다. 원본,
  허용 범위, 흰색/검은색의 실제 제거 시안을 보여 주며 artwork는 복원 완료로 표시하지 않는다.
- 초기 미리보기와 최대 두 번 수정만 허용한다. 최종 JSON의 영역/배경/폴리곤이 마지막
  미리보기의 canonical 해시와 다르면 적용하지 않는다. region membership, 숫자 보존,
  취소, 중복 호출/다른 입력 충돌을 검증한다.
- 이 후보에서 반복 생성의 정합 알고리즘이나 실패 crop 피드백, 전체 판독·식자 batching을
  추가 변경하지 않는다. 제거 계획을 확인하는 방식의 품질·시간·누적 사용량을 측정한다.
- 화 전체 서체 묶기, 최대 10개 실제 폰트 견본, 편집 가능한 텍스트, 고정 배경,
  최대 두 번 후속 보정 및 실패 원문 복원은 유지한다. 승격 기준도 완화하지 않는다.

synthetic proof 1은 code-mode host 차단으로 preview가 전달되지 않아 실패했다.
proof 2는 host 활성화 후 세 번의 proposal로 통과했다. 초기 5,448개 target 픽셀이
남았고 마지막에는 0개, 별도 그림의 픽셀은 보존됐다. 원본/초기/마지막 PNG를 직접
열었다. 최종 사각형과 SHA는 마지막 실제 preview와 일치했다. 누적 105,562토큰과
마지막 snapshot 18,536토큰은 서로 다르다. 매체 반환 처리가 비효율적이었으며,
이를 명시한 별도 proof 3을 진행한다. 이 증거는 프로토콜과 합성 픽셀 시험에만 해당하며
만화 식자 품질이나 production 연결 완료를 뜻하지 않는다.

### 실제 실행 결과와 source 연결

명시적인 media 전달 지침을 추가한 proof 3은 초기+한 번 수정으로 통과했다.
동일 합성 이미지에서 누적 18,612토큰, 마지막 snapshot 6,674토큰이었다.
proof 2와의 차이는 단일 합성 시험에서 관측한 값이며 만화의 예상 절감률이 아니다.
일반 content-item 결과가 code mode에서 줄로 합쳐진 문자열로 변환될 수 있는 것은
[공식 tool output 구현](https://github.com/openai/codex/blob/main/codex-rs/tools/src/tool_output.rs)에서도
확인했다. 지원 여부는 실행한 0.153.1의 실제 왕복 결과를 우선한다.

`dynamic-production-proof-001`은 새 source client/transport/preview host/실제 crop·mask
producer를 메모리에서만 컴파일하고 동결된 v0.3.4의 geometry를 사용했다. 두 번의
미리보기로 남은 검은 글자 픽셀 0개, 별도 그림의 차이 0개, 최종 geometry 일치를
확인했다. 누적 17,338토큰으로 기록됐으며 초기/수정 crop과 최종 PNG도 직접 열었다.
이것은 실제 source 연결의 합성 통합 증거다. 전체 앱 빌드·원고 후보 통과는 아직 아니다.
각 proof 폴더의 `report.html`에 실제 이미지와 결과를 자급형으로 보관했다.

source는 현재 v0.4.0 준비다. scoped tool host는 다른 thread/tool/namespace,
같은 call ID의 다른 입력, 세 번을 넘는 시도, 진행 중인 미리보기와 동시 수정, 취소와
종료 이후 응답을 제한한다. 마지막으로 저장한 미리보기와 최종 geometry가 다르면
적용하지 않는다. 흰색/검은색 시안은 기존 `fillPlainMask`를 직접 재사용하며 그
알고리즘은 이동·변경하지 않았다. 합성 원본의 모든 픽셀을 실제 허용 범위와 대조하는
characterization test로 제거 결과와 범위 밖 보존을 확인했다.

현재 v0.3.4 만화의 기록된 accepted patch 세 개도 별도로 직접 확인했다.
허용 범위 밖 변경은 모두 0이지만 일부 바탕의 직사각형 톤 차이와 희미한 윤곽이 보인다.
따라서 수치 gate 통과를 완성 품질로 세지 않는다. 자세한 독립 국소 합성 증거는
