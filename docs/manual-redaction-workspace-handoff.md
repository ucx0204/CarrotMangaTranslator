# 수동 전송 이미지 가리기 작업 인계

## 최신 상태

작업 브랜치: `feat/manual-redaction-workspace-20260910`

**단일 편집 화면의 제품/테스트 25개 파일을 반영하는 커밋이다.** 과거 문서의 "단일 화면 제품 코드 미반영"은 이 체크포인트 이전 기록이다. 최신 정확한 포함/제외 목록과 검사 범위는 `manual-redaction-continuous-ui.md`를 우선 읽는다.

원격 부모는 `a80f060d3b77308102402d722844f670bdd751cd`, 문서 수정 전 제품 트리는 `9333220417394ad5a6cfa137c4dc43e971b94b73`다. 전체 보기 탭 없이 연속 편집, 썸네일 탐색/다중 선택, 메뉴 안의 일괄 작업, 아이콘 도구/툴팁, 하단 페이지 이동/확인을 구성했다. 정확히 이 반영 조합으로 Linux 타입 검사와 9개 파일 58개 회귀 테스트가 통과했다. 전체 check와 실제 Windows/Electron 화면 검증까지 완료된 것은 아니다.

## 사용자 범위

- 수동 전용. 자동 위치 감지, 자동 마스킹, 자동 추천은 추가하지 않는다.
- 전체 보기 탭은 사용하지 않는다. 가능한 작업을 연속 편집 하나에서 처리한다.
- 화면의 긴 설명은 줄이고 필요한 안내는 툴팁에 둔다. 필수 확인 조건과 오류는 짧게 명시한다.
- 같은 작업 브랜치에서 이어가며 중간 결과와 검증 범위를 커밋으로 보존한다.
- master 병합, 버전 변경, 태그/릴리즈는 하지 않는다.
- 사용자 원본 이미지, 보관함, 기존 출력물은 수정/삭제하지 않는다. 가리기는 외부 전송 복사본에만 적용한다.

## 아직 남은 일

- 보존본의 미반영 7개 파일은 `manual-redaction-continuous-ui.md`에 정확히 기록했다. 원격 기존 버전을 유지하며 반영했다고 표시하지 않는다.
- 전체 lint/check/build, 실제 production component의 넓은/좁은 화면, Windows 개발 실행, 저장 실패/중복 종료/키 반복/포커스/빠른 전환의 추가 인수 검증.
- 3차 사전 편집을 작품/화/선택 페이지에서 여는 앱 진입점과 공통 명령 연결. main 준비/저장 계약이 존재하는 것과 사용자 진입점 완성을 구분한다.
- 검토 결과 재사용, 변경 페이지 재검토, 작업 창 소유권과 초안 이어하기의 앱 전체 흐름 검증.

## 재개 순서

1. 최신 branch HEAD와 `AGENTS.md`, 이 문서, `manual-redaction-continuous-ui.md`, 실제 diff를 확인한다.
2. 기존 32개 파일 패치를 통째로 다시 적용하지 않는다. 이미 반영한 파일은 보존하고 미반영 파일만 기준/수정 해시와 비교한다.
3. 이 커밋의 58개 테스트와 과거 문서의 122개 테스트를 혼동하지 않는다. 74개 파일의 과거 ZIP은 현재 대화에서 확보하지 못했으므로 존재/완성을 가정하지 않는다.
4. 정상 허용되는 도구 작업만 수행한다. 차단된 요청을 다른 API/인코딩/워크플로로 우회하지 않는다.
5. 검사한 코드 SHA와 실제 결과를 함께 기록한다. 코드 존재, 부분 검사 통과, 전체 인수 완료를 구분한다.
6. 다른 사람의 최신 변경을 덮어쓰거나 강제 push하지 않는다.
