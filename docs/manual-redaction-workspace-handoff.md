# 수동 전송 이미지 가리기 작업 인계

## 최신 상태 — 이 브랜치에서 계속

작업 브랜치: `feat/manual-redaction-workspace-20260910`

기존 단일 화면 32개 파일은 `6590be8`까지 통합되어 있다. 그 뒤 사용자 지적에 따라 작은 단위로 `8280d9c`, `f1c960d`, `4575ec6`, `07ff90b`, `6e96e0d`를 반영했다. 핵심 UX 변경은 실제 원격 제품 코드에 있으므로 처음부터 다시 만들지 않는다.

선택 페이지 확인/전체 선택/해제는 메뉴 밖에 있다. 페이지 확인은 이미지 아래, 전체 작업 재개는 별도 하단에 있다. 진행률과 저장 상태는 텍스트이며 체크 아이콘이나 클릭 영역이 아니다. 보류 버튼/단축키/런타임 상태는 제거했다. 과거 보류 초안은 가림을 보존하며 미확인으로 읽는다. 자동 저장과 마지막 Enter가 전송을 승인하지 않는다.

정확한 변경 범위는 `manual-redaction-ux-clarity-checkpoint.md`, 최신 검사와 미반영 후속 수정은 **`manual-redaction-latest-validation.md`를 우선 읽는다.**

## 검증과 남은 문제

Windows 소스 `392eaac4af95d04b4f52b2683693e41e462fda9b`, Actions `34500583095`에서 실제 개발 main 컴파일, 타입 검사, 집중 ESLint, 전체 앱 build와 12개 파일 71개 테스트가 통과했다. 전체 Actions는 failure다. 좁은 창 QA가 실패했고, 전체 check는 문서 포맷에서 중단되었다. 해당 포맷 문제와 검사 기록은 문서 전용 커밋 `d94abb9`에서 정리했다. 전체 check를 재실행해 통과한 것은 아니다.

실제 캡처/회귀에서 발견한 모달 너비, 숫자 입력 겹침, Enter 뒤 포커스의 추가 수정은 **아직 원격 미반영**이다. 세 제품 파일의 저장 요청이 도구 확인 단계에서 차단됐다. 관련 테스트까지 네 파일의 작은 패치와 QA 강화는 대화의 `manual-redaction-ux-followup-checkpoint.zip`에 보존했다. ZIP/패치의 정확한 기준, 검증 범위와 재개 절차는 최신 검증 문서에 있다. 이것은 이미 커밋한 전체 작업을 대체하는 누적 패치가 아니다.

## 사용자 범위

- 수동 전용. 자동 위치 감지, 자동 마스킹, 자동 추천은 추가하지 않는다.
- 전체 보기 탭이나 보류 기능을 다시 만들지 않는다. 가능한 작업을 연속 편집 하나에서 처리한다.
- 핵심 동작은 짧은 텍스트 버튼으로 노출한다. 설명만 툴팁에 두고 상태와 동작을 혼동시키지 않는다.
- 같은 브랜치에 작고 빌드 가능한 단위마다 커밋하고 실제 원격 ref를 확인한다.
- master 병합, 버전 변경, 태그/릴리즈 게시는 하지 않는다.
- 사용자 원본 이미지·보관함·기존 출력물은 수정하거나 삭제하지 않는다.

## 다음 작업

1. 최신 HEAD와 두 최신 문서를 읽고, 이미 반영된 코드와 미반영 네 파일을 구분한다. 로컬 기준 해시와 원격을 대조한다.
2. 정상 허용되는 환경에서만 미반영 후속 코드를 반영한다. 차단된 요청을 다른 API/인코딩/워크플로로 우회하지 않는다.
3. 수정한 소스로 넓은/좁은 UI QA, 개별 버튼 가림과 연속 키보드 포커스, Windows 검사 및 전체 check를 완료한다.
4. 원래 3차의 작품/화/선택 페이지 사전 편집 앱 진입점과 공통 명령 연결, 앱 전체 이어하기 흐름은 별도의 미완료 작업이다.

과거 74개 파일/122개 테스트 기록은 현재 원격의 완료 상태를 뜻하지 않는다. 다른 사람의 변경을 보존하고 강제 push하지 않는다. 다음 재개에서도 코드 존재, 집중 검사 성공, 실제 화면 인수를 구분해 기록한다.
