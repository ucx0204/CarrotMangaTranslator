# 글자 크기·말풍선 분할·배치 연구

## 현재 상태 — 사용자 승인 후 앱 적용

- 사용자가 confirmation-002 C5의 전반적 개선을 확인하여 `typeset-v0.1.0`으로 승격했다. 이후 앱 기본 코드 적용과 커밋을 지시했다.
- 기본 작업 폴더의 앱 2.4.4 위에 승인한 제품 코드 18개 파일을 그대로 통합했다. 추가 시각 검토는 사용자의 명시적 생략 지시로 종료했다. 국소적인 작은 글씨·부호 줄 문제를 이유로 승격을 다시 보류하거나 새 후보를 만들지 않는다.
- 추가 비교는 표지 제외 57개 작품·100페이지·직접 번역 725개로 완성했다. 전체 페이지 100개와 확대 비교 8장을 실제 열람했으며, 생성된 확대 270장 전부를 개별 감사했다고 주장하지 않는다. 이 표본을 이용한 추가 튜닝은 없다.
- 최종 계약, 실제 적용 경로, 남은 한계와 검증 기록은 [제품 인계 문서](typeset-aesthetics-production-handoff.md)를 따른다. 아래의 후보 기각·조사 재개 기록은 당시 이력이며 현재의 추가 작업 지시가 아니다.

## 연구 계약 — 2026-09-05

- 최초 기준: `b9071432`, 앱 2.4.3. 현재 내부 승격 버전 `typeset-v0.1.0` (002 C5).
- 작업: 연구는 `codex/typeset-aesthetics-20260905`의 별도 워크트리에서 수행했다. 이후 사용자의 앱 적용 지시로 기본 작업 폴더에 제품 코드를 통합했다. 사용자 원본·보관함·기존 출력물은 보존한다.
- 목표: 원문의 체감 크기와 속삭임/본문/강조를 보존하면서 한국어 식자의 크기, 연결 말풍선의 식자 영역 분할, 글 덩어리와 줄바꿈을 개선한다.
- 고정: 실제 HayaiOCR (`hayai-regions`, CUDA/cu126). 한국어 번역은 Codex가 원문과 페이지 문맥을 보고 직접 작성하고 후보 생성 전에 봉인한다. 번역 모델 호출과 임시 `검증` 문자열로 품질을 평가하지 않는다.
- 범위: 일반 대사의 크기 추정/환산/맞춤, 렌더용 말풍선 소유 영역, 내부 배치. OCR 블록 분리 정책과 폰트/말풍선 모델은 유지한다. 효과음과 표지는 개선 대상에서 제외한다.
- 사용자 정정: 기존 91페이지 OCR 블록 분리 실패 세트는 이번 미학 평가에서 제외한다. 49개 사용자 직접 판정과 8개 경계 표적의 기존 보호 조건은 유지한다. 이를 이번 식자 미학의 정답이나 새 일반화 증거로 세지는 않는다. OCR 블록 분리 코드는 변경하지 않는다. 초기 기록에서 49/8까지 제외한 해석은 잘못되어 정정했다.
- 자료: Tachidesk mangas 읽기 전용 코퍼스. 과거 사용 화 레지스트리를 재사용 제외용으로만 읽는다. 새 3화의 seed, inventory, 페이지 SHA-256을 먼저 봉인한다. 첫 화는 발견용, 나머지 두 화는 후보를 고정한 뒤 확인한다.
- 비교: 번역문, 폰트/굵기, 인페인팅 결과를 동일하게 고정한다. 원문, 기준선, 후보를 같은 좌표·해상도·배율로 본다. 전체 페이지와 모든 일반 대사 확대를 직접 검토한다.
- 판정: 원문 크기 인상, 글 덩어리, 여백, 읽기 호흡별 개선/동등/악화/애매를 문장으로 기록한다. 수치는 진단용이다. 문자 누락/겹침/잘림, 발화 오결합, 강조 훼손은 기각한다. Codex 시각 판정은 human gold가 아니다.
- 예산: 한 발견화에서 제품 후보 최대 5개. 계수/조합 변경도 별도 후보다. 명확한 개선이면 조기 종료한다. 5개 소진에도 개선이 없으면 고유 질의 최소 200개 조사로 전환하고 새 메커니즘은 다음 미사용 화에서 검증한다.
- 산출물: `artifacts/typeset-aesthetics/`에 화별 자체 포함 HTML, 직접 번역 manifest, 원시 OCR, 단계별 진단, 원문/기준선/후보 이미지, 시각 판정과 코드 상태를 보존한다.
- 통합: 기존 domain contract/renderer를 재사용하며 공개 schema를 불필요하게 바꾸지 않는다. 실제 화면의 넓은/좁은 QA, 관련 행동 테스트, check/build, 화면-출력 parity를 검증한다. 공개 release/tag는 만들지 않는다.

## 반복 금지와 초기 가설

- 기존 크기 연구의 전역 min px, merged bbox 폭/면적을 글자 크기로 사용, page median 무차별 복사, 일반 VLM px 직접 회귀를 반복하지 않는다.
- 분할선이 곡선이라는 이유만으로 채택하지 않는다. 두 원문이 차지하는 몸통과 연결부, 최종 식자 결과로 판단한다.
- 후보 순서: 크기 경로의 최초 오류 → 연결부 분할 → 뾰족한 끝을 비워두는 식자 영역 → 문단 전체 줄바꿈 → 통과한 요소 결합. 원인 부재면 해당 후보는 실행하지 않는다.
- 현재 코드 관찰: `resolveBubbleWrappedText`는 처음 들어가는 slot plan을 반환한다. `assessWrappedTextQuality`는 선택 과정에서 호출되지 않는다. 크기 추정 오류와 최종 배치 오류는 분리해 추적한다.

## 상태

- 현재 승격 상태는 `typeset-v0.1.0`, 발견화 002 후보 5다. 사용자가 실제 002 비교본을 보고 전체적으로 명확히 좋아졌으면 우선 승격하라고 지시했다. 이 직접 판정이 앞선 에이전트 기각 결정을 대체한다. 제품 소스는 별도 워크트리에 통합되어 있으며 실행 검증을 마무리한다.
- 승격 기준 정정: 전체 사용자 가치가 분명히 높아졌다면 일부 잔존/국소 악화만으로 전체 승격을 막지 않는다. 알려진 반례는 삭제하지 않고 다음 기준선의 후속 개선 항목으로 보존한다. 사용자 판정을 새 human gold 데이터셋으로 확대 해석하지 않는다.
- 연구 003은 실제 고유 질의 104개에서 중단했다. 200개 계획을 완료했다고 주장하지 않는다. 003/004 콘텐츠는 여전히 미열람으로, 이후 신선한 개선 단위에 사용할 수 있다. 공개 배포/릴리스는 하지 않는다.
- `node_modules`는 기존 설치를 가리키는 정션이며 패키지 설치/수정에 사용하지 않는다. 워크트리 제거 시 정션 자체를 먼저 분리하고 원본 보존을 확인한다.

## 발견화 기준선 — campaign-001

- 32페이지 원문 및 기준 출력 전체를 직접 열어 확인했다. 일반 식자 215개, 제외 21개이며 번역 SHA-256은 `498d0f3d9b6896b7050e0ffcb586d598d4ff30af1c18d9ef1e270bc8ecb8f2d3`이다. 유효 기준선은 `baseline-v0`이며 이전 `baseline`은 좌표/폰트 프로토콜 하네스 오류로 무효다.
- 원인 A: source-match의 임시 nominal 크기 12px로 main 단계에서 자동 개행을 넣은 뒤, 실제 렌더 크기 20~40px와 확장된 말풍선에서도 해당 개행을 보존한다. 단어/물음표 고립과 좁고 긴 글 덩어리가 자주 발생한다. P006/P009/P012/P016/P018/P030에서 직접 확인했다.
- 원인 B 조사: P002의 단독 `!`와 P018의 `앗.`은 source face 추정이 없어 12px로 남는다. 큰 원문 느낌과 달리 읽기 어려운 실제 사례다. P012의 조심스러운 대사는 face 14.73px로 추정되었으므로 원래 속삭임인지 래스터 추정 오류인지 원문 확대를 추가 검토한다.
- 연결부와 배치: P006/P009/P030은 좁은 끝의 한두 글자와 아래쪽 넓은 줄이 문제다. P024/P026/P032는 발화 분리가 이미 양호한 비교 보호 사례다. 직선 자체를 실패로 판정하지 않는다.
- P007/P004의 OCR geometry 오결합, 일부 외부 글자의 인페인팅 잔류는 고정된 범위 외 결함으로 기록한다. 후보의 미학 개선으로 세지 않는다.
- 사용자 중간 관찰: 작아서 읽기 어려운 글자가 있음. 해당 관찰을 우선 진단 대상으로 반영하며 전역 최솟값 확대는 하지 않는다.

## 후보 1 사전 기록 — 실제 폰트 로드 후 줄바꿈

- 가설: source-match의 main 단계 자동 hard break만 유보하면 실제 글꼴/크기/말풍선이 정해진 renderer에서 더 자연스럽게 줄을 나눌 수 있다.
- 변경: `applyNaturalTextLayout`의 자동 세로쓰기 판정, 사용자 줄바꿈/markup 보존은 유지하고 source-match의 근사 수평 hard break만 생략한다.
- 고정: 215개 번역 내용, source face, 폰트/굵기, OCR 블록, 말풍선 mask/소유 영역, 지우기 결과. 과거 자동 개행을 제거한 재생은 봉인 번역으로 새 번역을 시작하는 경로를 재현한다. 사용자 수동 개행 마이그레이션은 하지 않는다.
- 판정 전: 32페이지 전체 비교와 변경된 모든 대사 확대를 확인한다. 크기 누락/오추정은 이번 후보로 해결되었다고 주장하지 않는다.

## 후보 2 사전 기록 — 짧은 원문과 말줄임표 크기 증거

- 후보 1의 자동 개행 유보를 유지하고, 실제 래스터에서 원인 확인된 두 크기 경로를 수정한다. 1은 단독 채택하지 않았으며 전체 미학은 아직 불충분하다.
- P012 `あの...領主様...`: 11자/3열 가설이 face 14.73px를 만들지만 원문은 두 열이다. 점 세 개를 인쇄된 말줄임표 한 칸으로 세면 7자/2열이며 실제 래스터 두 열 face 23.26px와 일치한다. P013 `いえ!詳しくは...ただ......`도 같은 원인이다.
- 한 글자 가나와 `!?`는 복수 글자 반복 증거를 요구하는 기존 추정기에서 무조건 탈락한다. 한 글자에 한해 정제된 래스터의 교차축 잉크 2~98% 폭을 사용한다. 박스 폭/면적이나 페이지 중앙값을 글자 크기로 복사하지 않는다.
- 보호: 일반 복수 글자 경로, OCR 원문/블록/인페인팅/폰트는 고정. 단일 점/말줄임표의 크기는 가나처럼 취급하지 않는다. P029의 배경 오염에 의한 과대 크기는 별도 미해결로 남긴다.

## 후보 3 사전 기록 — 실제 폭으로 문단과 위치 함께 선택

- 후보 2의 P002 느낌표, P012 조심스러운 대사, P013 설명, P018 감탄사를 원문 확대와 직접 비교했다. 체감 크기는 모두 개선이다. 전체 페이지 판정은 최종 후보까지 이어서 확인한다.
- 생성된 source-match 말풍선의 수평 문단만 실제 글꼴로 동적 계획법을 수행한다. 같은 번역문에서 어절 분리, 한 글자 줄, 불균형한 줄 길이를 함께 비교한다. 사용자 hard break/세로쓰기/수동 레이아웃은 기존 경로를 유지한다.
- 위치는 영역 외접 중심과 잉크가 아닌 말풍선 내부 면적 중심 및 반 줄 이동을 후보로 두되, 글자 줄의 전체 높이가 mask 안에 들어가는 기존 안전 조건을 유지한다. 다른 발화의 소유 영역으로 넘어가지 않는다.
- 이 후보는 아직 크기 축소를 추가하지 않는다. 문단과 위치 개선만으로 충분한지 먼저 본다.

## 후보 4 사전 기록 — 모델 mask의 연결부를 따른 소유 영역

- 후보 3에서 가늘게 늘어지는 글 덩어리가 줄었으나, 넓이를 조금 더 확보하거나 크기를 조금 조절해야 하는 짧은 단어 분리는 남았다. 크기 조정은 후보 5로 분리한다.
- 동일 Koharu 검출을 공유하는 기존 OCR 발화만 대상으로, 실제 mask 안에서 좁은 통로를 지나는 비용이 큰 경로 거리를 비교한다. 원문 중심을 seed로 사용하며 bbox 면적을 글자 크기로 쓰지 않는다.
- 소유 필드는 각 블록의 폰트별 여백을 적용하기 전에 동일 모델 mask에서 공동 계산한다. 서로 다른 inset으로 독립 계산하여 겹치는 위험을 피한다. 기존 두 발화의 경계/읽기 순서는 유지한다.
- 별도로 검출된 두 말풍선의 겹침, manual 영역, 0-gap 인페인팅 prepass는 기존 경로를 유지한다. seed가 mask로 뒷받침되지 않거나 연결되지 않으면 기존 소유 분할로 돌아간다.

## 후보 5 사전 기록 — 원문 근처의 제한된 크기 조정과 조합

- 후보 4의 공유 모델 mask 분할은 발화 경계를 유지했으나 일부 짧은 문장에서 renderer가 다시 greedy fallback하여 느낌표가 고립됐다. 분할 경계만으로 식자가 완성되지는 않는다.
- 원문 환산 크기가 실제로 측정된 생성 말풍선에서, 현재 줄바꿈 손상이 있을 때만 원문 환산 크기의 86~100%를 큰 쪽부터 검사한다. 단어 분리/한 글자 줄이 실제로 줄어든 경우만 작은 후보를 고른다. 정상 문단/수동 크기/사용자 개행/세로쓰기는 유지한다. 박스를 채우려고 축소하지 않는다.
- 후보 2의 중점 `・`까지 말줄임표로 정규화한 처리는 기각한다. P018의 비틀거리는 발화가 오히려 커졌다. ASCII `...`만 정규화하고 중점의 의미는 보존한다.
