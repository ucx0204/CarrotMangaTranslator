# MCP: 기존 블록 하나의 원문 영역 수정

## 도구와 범위

`carrot_update_block_source_rect`는 기존 페이지의 블록 하나만 대상으로 한다.
기존 앱의 페이지 편집 인계·점유·저장 트랜잭션을 사용한다. OCR, 모델,
원문 제거, 렌더링, 출력, 블록 생성·삭제, 실행 취소는 시작하지 않는다.
읽기·편집·처리 승인이 필요하며 이미지 전송 승인은 요구하지 않는다.
결과는 메타데이터뿐이다. 파일 첨부·이미지·로컬 경로를 반환하지 않는다.

## 사용 순서

1. `carrot_get_page_blocks`로 현재 페이지 버전, 크기와 블록 ID를 읽는다.
2. 원본 이미지 픽셀 기준 `sourceRect`를 지정한다. 정규화 좌표를 그대로
   보내지 않는다. 소수 픽셀은 허용하며 반환된 이전 영역을 정확히 재사용할 수 있다.
3. 결과의 새 `revision`, 실제 `sourceRect`, 경고를 확인한다.
4. 이전 영역을 다시 적용하려면 현재 버전을 다시 읽고 `previousSourceRect`를
   새 편집으로 제출한다. 이는 별도의 Undo 기록을 만드는 기능이 아니다.

```json
{
  "chapterId": "chapter-id",
  "pageId": "page-id",
  "blockId": "block-id",
  "revision": "page-v1:0123456789abcdef",
  "sourceRect": { "x": 100.25, "y": 200.5, "w": 250.5, "h": 160.25 }
}
```

위 ID와 버전은 설명용이다. 실제 조회 결과를 사용해야 한다.
자연어 예: "이 블록의 원문 영역만 오른쪽으로 넓혀줘. 번역 위치는 그대로
두고 OCR이나 원문 제거는 실행하지 마."

## 좌표·재시도 계약

- 영역은 페이지 안에 완전히 포함되어야 한다. 잘라내거나 이동시켜 받아들이지 않는다.
- 앱의 정규화 좌표가 표현할 수 없는 작은 영역도 거부한다. 각 축의 최소 크기는
  페이지 해당 축의 1/1000이다. 기존 좌표 변환 알고리즘은 변경하지 않았다.
- 같은 영역을 현재 버전으로 보내면 `already_applied`, `changed: false`이며 저장하지 않는다.
- 오래된 버전은 같은 영역이어도 `revision_conflict`다. 응답을 놓쳤으면 먼저 다시 읽는다.
- 이 도구에는 `requestId`, `force`, 다중 블록 배열, `renderRect`, 파일 경로를 보내지 않는다.

## 보존과 명시적인 제한

원문·번역문, 저장된 서식, 다른 블록, 읽기 순서, 원본·제거 이미지·마스크를
보존한다. 기존 `renderBbox`는 그대로 둔다. 표시 영역이 없는 옛 블록은 원문
좌표를 바꾸기 전에 기존 실제 표시 틀을 명시적으로 고정하고
`renderFramePinned: true`를 반환한다. 저장 시 타임스탬프와 기존 앱의 처리
완료 판정이 갱신될 수 있다. 소스 영역은 정규화 표현으로 저장하므로 옛
픽셀 표현으로 되돌리는 것까지 보장하는 파일 단위 롤백은 아니다.

**자동 생성된 말풍선 배치와 원문 기반 글자 크기 정보가 결합된 블록은
실제 영역 변경을 거부한다.** 원문 좌표만 바꿔도 기존 렌더러의 글자 크기나
다른 블록의 대체 측정이 바뀔 수 있기 때문이다. 저장된 폰트 값만 같다고
실제 식자가 유지된다고 주장하지 않는다. 이 경우 `invalid_edit`와 이유를
반환하고 저장하지 않는다. 폰트·자동 맞춤 설정을 몰래 바꾸지도 않는다.
원문 영역을 바꾸면서 이 자동 식자까지 보존하는 확장은 별도 작업이다.

## 경고의 의미

`source_text_not_rechecked`, `erasure_and_masks_retained`,
`generated_lettering_retained`, `source_font_metrics_retained`,
`bubble_layout_retained`는 기존 자료를 보존했지만 새 원문 영역에 맞는지
재검토가 필요할 수 있다는 뜻이다. 재판독·새 마스크 생성·재식자는 수행하지 않는다.
후속 단계는 사용자가 명시적으로 지시한 경우에만 실행한다.

## 검증 경로

- `tests/mcpSourceRectPolicy.test.ts`: 범위·정규화·보존·경고·잘못된 입력.
- `tests/mcpSourceRectEditing.test.ts`: 실제 서비스의 버전·페이지 점유·저장 직전 검사.
- `tests/mcpSourceRectLayout.test.ts`: 기존 렌더러의 배치 계산과 자동 글자 크기 영향 재현.
- `tests/mcpSourceRectHttp.test.ts`: 격리 보관함의 실제 OAuth HTTP·저장·접근 제한.
- `scripts/mcp-native-source-rect.cjs`: 기존 네이티브 시험에서 원문 영역 변경·복원과
  실제 렌더링 픽셀·원본·다른 블록 보존을 확인한다. 사용자 보관함을 선택하지 않는다.

실행 결과와 완료 범위는 `mcp-source-rect-checkpoint.md`를 참조한다.
