# Font Matching runtime artifact contract v1

## Purpose

The training checkpoint is not a deployable image model by itself. It contains
only the prototype-conditioned ranker head. Production inference also needs the
exact frozen SigLIP vision encoder and the prototype features generated by that
encoder. A runtime bundle is `ready` only when all three are present, hash-bound,
and parity-tested:

1. `encoder.onnx`: RGB `224x224` pixels to normalized 768-dimensional features.
2. `ranker.onnx`: three source views plus the prototype bank to candidate and
   semantic logits.
3. `prototype-features.f32`: little-endian float32 features in the sealed
   candidate/prototype order.

`scripts/build_font_matching_runtime_artifact.py` builds and validates this
bundle. It does not train, open frozen-test pixels, or export ONNX graphs.

## Fail-closed release boundary

The builder requires all of the following before it writes an output:

- a safely owned trainer output with a production ordinary-font regression gate;
- the exact authoritative 22-ID production vocabulary, in its sealed order
  (`98100cbcdf9745a15504262d9da32284381bc072d1328320725bd5d1a283608f`);
- the dynamic catalog registry, font catalog, render bank, and prototype hashes;
- the pinned encoder model ID, immutable revision, source-weight SHA, and ONNX SHA;
- the ranker checkpoint SHA, tensor inventory, architecture version, and ONNX SHA;
- a sealed conversion report showing PyTorch/ONNX and onnxruntime-web WASM parity;
- a sealed aggregate frozen-test release report whose required metrics pass;
- equality between that report's test-manifest SHA and the upstream frozen-test
  manifest SHA sealed into the trainer model contract;
- an explicit runtime policy with calibrated thresholds and a weak chapter prior.

The runtime bundle contains no source crops, train/validation/test rows, sample
IDs, or row-level predictions. The test report contributes only an immutable
manifest hash, row count, aggregate metrics, and thresholds.

Missing, invalid, stale, reordered, or hash-mismatched assets disable automatic
mutation. Semantic bootstrap and automatic profile application without the pixel
model are forbidden fallbacks. Manual user locks remain allowed.

The production CLI cannot override the candidate count or vocabulary. Small
candidate sets exist only behind an internal test helper. The builder fully
validates its staging directory before publish, validates again at the published
path, and restores the previous safely owned bundle if the post-publish check
fails.

## Chapter consistency policy

Chapter consistency is metadata, not a hard model constraint. The policy caps
its score contribution at `0.1`, requires multiple anchor observations, and says
that real local typography evidence wins. This keeps ordinary dialogue stable
without suppressing handwritten lines, emphasis, shouts, signs, or sound effects.

## ONNX feasibility and current blocker

Full vision inference is technically feasible, but it is not yet release-ready:

- The pinned SigLIP vision tower has 92,884,224 parameters, about 372 MB in fp32
  or 186 MB in fp16 before ONNX graph overhead.
- The installed Transformers legacy ONNX feature registry does not expose a
  built-in `siglip` export configuration. A custom eager-attention wrapper or a
  verified Optimum custom configuration is therefore required.
- `onnxruntime-web` supports Electron and WASM, while WebGPU supports only a
  subset of operators. The exact exported graph must be tested on the app's
  pinned `onnxruntime-web@1.27.0`; Python ONNX Runtime success is not sufficient.
- The current repository has Python ONNX Runtime but not the `onnx` or
  `optimum-onnx` exporter packages. No unverified graph was generated or wired
  into production.

Relevant primary references:

- <https://huggingface.co/docs/optimum-onnx/onnx/package_reference/export>
- <https://huggingface.co/docs/transformers/model_doc/siglip2>
- <https://onnxruntime.ai/docs/tutorials/web/>
- <https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html>

The next safe implementation step is a separate ONNX converter that exports the
vision-only tower and ranker, runs at least 32 synthetic-plus-validation parity
cases in both Python ORT and the pinned Electron WASM runtime, benchmarks memory
and latency, and emits the sealed conversion report consumed by this builder.

## App status boundary

`src/main/pipeline/fontMatchingRuntimeArtifactStatus.ts` is a main-process file
loader. It verifies the exact inventory, ownership marker, every file hash, the
canonical contract seal, artifact descriptors, authoritative catalog order, and
runtime contract before producing one of these explicit states:

- `ready`
- `missing_artifact`
- `artifact_verification_failed`
- `invalid_contract`
- `catalog_mismatch`
- `runtime_version_mismatch`
- `runtime_inference_unavailable`

Every disabled state has `automaticMutationAllowed: false` and
`semanticBootstrapAllowed: false`. Because no real Electron ONNX/WASM session is
yet connected, even a completely verified bundle currently resolves to
`runtime_inference_unavailable`, never `ready`. The page pipeline additionally
requires block-bound verified pixel inference before it may apply a work profile,
palette, intentional override, or page-local coordinator state. Persisted manual
block/role locks are the only mutation path that remains available while the
runtime is disabled.
