# Astra 식자 메커니즘 조사 · 2026-09-05

상태는 **다음 후보 설계 근거**다. 논문의 성공률이나 검색량을 이 앱의 품질
증거로 전용하지 않는다. 후보 2는 처음 봉인한 10쪽 화에서 완료·기각했으며,
25개 영역이 검토 대상으로 남았다. 경계 손상과 불투명 효과음 실패가 반복되어 미세 조정을 중단했다. 기존 출력의
정합 진단 후보 3도 기각했다. 새 메커니즘은 다음 미사용 화에 적용한다.

`.tmp/astra-typesetting-research/research-transition/query-ledger.json`에 있다.
1–4번은 최초 도구 응답 전체를 파일로 보존하지 못하여 질의와 반환된 링크만
있다. 나머지는 원시 응답을 보존했다. 검색 결과에는 무관한 항목도 있으며
200개 문헌을 읽었다는 뜻이 아니다. 아래는 별도로 열어 확인한 1차 자료다.
CVF 일부 원문은 403으로 열리지 않아 검색 발췌만 확인했고 채택 근거에서

## 채택할 원리와 적용 한계

1. **제거할 글자와 문맥 bbox를 분리한다.** Stroke-Based Scene Text Erasing은
   글자 획을 작은 구멍으로 추출해 더 많은 배경을 남기는 접근이다. 이 앱에서는
   bbox 전체를 복원하는 대신 Astra가 크롭에서 고른 글자별 제거 외곽을 별도
   계약으로 받는 방식을 검증한다. 다각형 외곽은 학습된 픽셀 단위 획 마스크와
   같지 않으며, 외곽선 잔류·그림 포함 여부는 실제 결과에서 확인해야 한다.
   [논문](https://arxiv.org/abs/2104.11493)

2. **마스크 밖 픽셀 보존은 앱의 책임이다.** 공식 GPT Image 문서도 마스크가
   지침으로 쓰이며 정확한 모양을 따르지 않을 수 있다고 설명한다. 생성 출력
   전체를 붙이지 않고 원본과 정렬한 뒤 앱의 허용 마스크 안만 복사한다.
   Codex 내장 도구에서 직접 API의 input_image_mask 파라미터를 제어할 수
   있다고 주장하지 않는다. 현재는 설명용 마스크 이미지를 함께 제공한다.
   [공식 문서](https://developers.openai.com/api/docs/guides/image-generation)

3. **정합은 양쪽의 유효한 문맥으로 판단한다.** OpenCV의 마스크 ECC는 변환된
   입력 마스크와 기준 마스크의 교집합만 목적함수에 쓴다. 본 구현은 ECC가 아닌
   제한된 위치·등방 크기 탐색이다. 생성된 글자/복원 영역을 정합 근거에서
   제외하고, 지원 범위를 벗어나거나 국소 경계가 맞지 않으면 거부한다.
   정합 수치가 좋아도 복원 영역 내부의 선 손상을 증명하거나 배제하지 못한다.
   [OpenCV](https://docs.opencv.org/5.0/main_modules/video_track.html)

4. **블러로 어긋남을 가리지 않는다.** 현재 진단에서 위치·크기 보정은 r5의
   경계 오차를 줄였지만 r2 내부 손상은 남겼다. 이는 앱 자체 관찰이며 문헌의
   성능 수치가 아니다. 정합 탐색용 저역 필터와 실제 붙이는 원본 해상도 픽셀을
   구분한다. Poisson/feathering은 선의 의미를 복구한다는 근거가 없으므로
   초기 후보의 자동 성공 우회로로 쓰지 않는다.

5. **투명 전경은 생성 후 실제 알파로 판정한다.** LayerDiffuse는 투명도를
   잠재 표현에 넣는 접근을 제시한다. 논문의 특정 모델을 추가 설치하지 않는다.
   이 실험에서는 불투명 원문 그림을 편집하는 호출과 새 투명 글자 생성 호출을
   구분한다. 흰색을 무조건 투명화하면 흰 외곽선까지 잃으므로 자동 색상 제거를
   기본 복구로 쓰지 않는다. 현재 새 이미지 단일 smoke 성공은 참고 크롭을
   포함한 호출들의 불투명 실패를 상쇄하지 못한다.
   [LayerDiffuse](https://arxiv.org/html/2402.17113v4)

6. **폰트 이름의 계열과 변형을 혼동하지 않는다.** OpenType의 typographic
   family/subfamily 구분은 regular/bold/italic 네 가지 이상의 계열도 표현한다.
   사용자 폰트를 단순 파일명만으로 다른 계열이라고 단정하지 않는다.
   원문은 크롭 전체의 직접 시각 묶음을 먼저 고정하고, 대상 폰트는 최대 10개
   프리셋과 용도 설명·실제 regular/bold 견본으로 선택한다. 폰트의 메타데이터가
   일본어 원문과 한국어 대상 서체의 시각적 대응을 대신하지는 않는다.
   [OpenType name](https://learn.microsoft.com/en-us/typography/opentype/spec/name)

7. **폰트 로딩 완료와 글리프 지원을 구분한다.** CSS Font Loading의 check는
   폰트가 없거나 문자 범위를 지원하지 않아 fallback이 일어나는 경우에도
   true일 수 있다. ready 이후 실제 렌더를 확인하고, 최종 지원 문자 검증은
   cmap 또는 실제 사용 폰트 확인을 추가해야 한다. 현재 QA 화면만으로 커스텀
   폰트 전체의 모든 도착어 지원을 검증했다고 하지 않는다.
   [CSS Font Loading](https://www.w3.org/TR/css-font-loading/)

8. **줄바꿈은 언어 규칙과 실제 잉크 크기를 함께 본다.** Unicode 줄바꿈 규칙은
   가능한 경계를 제공하며 최적의 만화 식자를 선택하지 않는다. 실제 폰트,
   굵기, 문장부호와 말풍선 공간을 렌더한 뒤 Codex가 자연스러운 행을 선택해야
   한다. 끝 행의 느낌표 하나, 고립된 짧은 어절, 외곽선 잘림은 별도 실패로
   기록한다. 글자 수만으로 폰트 크기를 일괄 축소하는 방식은 채택하지 않는다.
   [Unicode UAX 14](https://www.unicode.org/reports/tr14/)

9. **문장 하나만으로 화의 번역을 확정하지 않는다.** 만화 번역 연구는 이전
   장면과 넓은 문맥이 생략된 주어 해석에 도움이 됨을 보고한다. 현재 누적
   summary만으로 이름·화자·말투 일관성이 보장되지는 않는다. 전체 판독 뒤
   번역문·화자/호칭·용어의 일관성을 확인하고 확정된 내용을 식자에 전달하는
   후속 후보가 필요하다. 인물 성격이나 말투를 근거 없이 만들어내지 않는다.
   [LREC-COLING 2024](https://aclanthology.org/2024.lrec-main.1505/),
   [멀티모달 만화 번역](https://arxiv.org/abs/2411.02589)

10. **완성본 판정과 독립 재판독을 나눈다.** VIEScore는 설명 가능한 시각 판정
    접근의 참고다. 이를 human gold로 취급하지 않는다. 생성 효과음은 정답
    문구를 보여주지 않는 별도 재판독을 하고, 정답 문자열과 비교한다. 같은
    Astra의 별도 호출은 문맥을 분리한 검사이지 서로 다른 모델의 독립적
    확인은 아니다. 알파·경계·영역 보존의 결정론적 검사와 직접 이미지
    검수가 함께 필요하다.
    [VIEScore](https://arxiv.org/abs/2312.14867)

## 다음 후보의 사전 계약

다음 미사용 화의 원본 목록은 내용을 보기 전에 봉인하고, 실행 코드와 조건도
첫 모델 호출 전에 별도로 봉인한다. 후보의 새 메커니즘은
별도 제거 외곽 + 원본 문맥 정합 + 허용 픽셀만 합성이다. 준비한 선택적 보정,
독립 글자 재판독, 편집형 왜곡, 원시 이미지 증거 보존도 함께 적용하되, 묶음
후보이므로 개선을 한 구성요소의 인과 효과라고 주장하지 않는다.

최초 + 최대 두 번 보정 정책을 유지한다. 실패가 남은 영역과 겹쳐 영향을 받는
영역은 원본을 보존하고 검토 표시한다. 성공한 영역은 다시 생성하지 않는다.
전체 화의 실패 수, 변경된 배경 면적, 보존 픽셀 위반, 문자 불일치, 이미지 생성
횟수, 실제 모델 토큰/캐시/시간, 최종 저장본을 기록한다. 사용량을 제공하지 않은
이미지 호출은 unknown이며 0원/0토큰으로 합산하지 않는다.

옛 6번은 별도 locked regression으로 사용을 먼저 예약하고 최대 10회 제한을
적용한다. 첫 보고서에 적어도 한 번 포함하되, 새 일반화 화로 세지 않는다.
추가 확인은 서로 다른 작품의 미사용 화 두 개다. 앱에서 편집·저장·재열기·출력
검증과 UI 및 저장소 검사가 완료되기 전에는 승격하지 않는다.

## 비용 최적화 순서

1. 전체 결과가 실패 없이 자연스러운지 먼저 확인한다.
2. 성공한 배경/글자를 재생성하지 않는 선택적 보정의 실제 절감을 측정한다.
3. 동일 원본 해시·목표어·프리셋 파일 해시·서체 묶음·레시피·모델·렌더러 조건이
   모두 같을 때만 산출물 재사용을 후보로 평가한다.
4. 모든 크롭을 본 뒤 고정된 계열의 대표 견본을 후속 호출에 재사용하는 절감을
   검증한다. 전체 크롭을 최초에 확인하라는 사용자 요구를 생략하지 않는다.
5. 큰 전체 페이지와 불확실한 부분의 원본 크롭을 조합해 이미지 입력 비용을
   줄이는 후보를 마지막에 비교한다. 작은 일본어·망점·경계 결함을 놓치면
   기각한다. 저렴한 모델로 바꾸는 절감은 현재 범위가 아니다.
