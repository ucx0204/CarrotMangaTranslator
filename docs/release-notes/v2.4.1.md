# v2.4.1 패치노트

## 동시 작업 데이터 보호

- 번역·인페인팅·가져오기 같은 작업이 진행 중일 때, 잠기지 않은 다른 페이지에서 화 전체 조건부 일괄 편집을 실행하면 작업 대상 페이지까지 함께 수정되어 진행 중인 결과가 누락될 수 있던 문제를 수정했습니다. 이제 전체 작업 상태를 기준으로 일괄 편집을 비활성화하고, 실제 반영 직전에도 같은 상태를 다시 확인합니다.
- 텍스트 모아보기의 TXT 및 검수표 가져오기가 진행 중인 작업과 동시에 화 데이터를 바꿀 수 있던 문제를 수정했습니다. 가져오기 버튼과 결과 반영 시점에 작업 상태를 확인하며, 가져오기 도중 작업이 시작된 경우에도 오래된 콜백으로 결과를 적용하지 않습니다. TXT 저장·복사와 CSV/TSV 내보내기는 계속 사용할 수 있습니다.

## 검사 및 빌드

- `npm run check`의 26개 검사를 의존 관계에 따라 실행하도록 바꾸고, 서로 독립적인 검사는 CPU와 가용 메모리 범위에서 병렬 실행합니다. 테스트·커버리지와 빌드처럼 단독 실행이 필요한 단계는 계속 분리하며, 실패한 단계에 의존하는 후속 작업은 실행하지 않습니다.
- Prettier 검사 결과와 Electron·렌더러·런타임·ONNX 빌드 출력을 입력 내용과 도구 설정에 묶인 검증 캐시로 재사용합니다. `npm run check:cold`는 이 캐시와 증분 타입 검사를 우회하며, Windows·macOS의 검사 및 릴리스 워크플로도 동일한 검사 캐시를 복원합니다.
- Vitest 작업자 수를 CPU와 가용 메모리에 맞춰 선택하고 기본값을 최대 12개로 제한했습니다. 명시적 작업자 수도 안전 범위 안에서 최대 16개까지 허용하며, 반복 측정 프로필은 테스트·커버리지 결과가 동일하고 자원 한도를 넘지 않은 경우에만 유효한 권장값을 만듭니다.
- 로컬 Bug Hunter 감사 산출물 디렉터리인 `.bug-hunter/`를 버전 관리와 저장소 검사 대상에서 제외했습니다.
