# v3.8.7

MCP 작업 이력이 쌓여 새 작업을 시작하지 못하던 저장 구조를 개선하고, 보관함 등록을 요청 합계 500장까지 지원합니다. ([#176](https://github.com/ucx0204/CarrotMangaTranslator/issues/176))

## MCP 작업 기록

- 중복 실행 방지용 최소 기록과 작업 상세를 작업별로 나누어 저장합니다. 전체 이력의 용량·건수 상한을 없애고, 필요한 상세만 읽어 메모리 캐시를 제한합니다.
- 종료된 작업의 상세와 동일 소유자·요청 ID의 중복 실행 방지 기록은 종료 시점부터 7일간 보존합니다. 조회나 재전송으로 보존 기간이 늘어나지 않습니다.
- 응답 유실이나 앱 재시작 뒤 같은 요청을 보내면 기존 작업을 확인하며, 저장 실패·기록 손상을 새 요청으로 취급해 자동 재실행하지 않습니다.
- 기존 작업 기록은 검증과 백업을 거쳐 새 형식으로 전환합니다. 전환 후에는 이 형식을 지원하지 않는 구버전에서 MCP 기록을 읽을 수 없으므로 v3.8.7 이상을 사용해야 합니다.
- 기록 정리는 원본 이미지·보관함·출력물을 삭제하지 않습니다.

## 500장 등록

- 일반 이미지·ZIP 등 기존 지원 원본, 일괄 등록, 작품 파일의 신규·추가 가져오기를 요청 합계 최대 500장·10개 챕터까지 지원합니다.
- 500장을 한 챕터로 등록할 수 있으며, 검토한 챕터 구분과 페이지 순서를 유지합니다. 요청 합계가 500장을 넘으면 저장 전에 거절합니다.
- 파일 크기와 압축 해제 용량 제한은 유지합니다. 등록 이후 OCR·번역·내보내기 등은 각 도구의 기존 작업 한도를 따릅니다. 50장 한도의 composite에 초과 등록을 연결하면 가져오기 전에 거절합니다.

## 검증

- 실제 파일 저장소에서 작업 10,000건·약 140MiB의 기록을 저장하고 재시작·중복 요청·작업별 읽기와 쓰기 범위를 확인했습니다.
- 실제 importer의 500장 이미지·ZIP·작품 파일 등록, 중간 실패 롤백, 재시작 후 매핑과 영수증 보존을 검증했습니다. 격리된 Electron에서 OS 암호화 저장과 동일 요청 재전송도 확인했습니다.
- 저장 형식·마이그레이션·오류 복구와 측정 범위는 [운영 문서](https://github.com/ucx0204/CarrotMangaTranslator/blob/v3.8.7/docs/mcp-job-storage-v2.md)에 있습니다.
