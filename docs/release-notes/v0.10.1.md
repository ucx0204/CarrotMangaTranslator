# v0.10.1 패치노트

기준 범위: `v0.10.0` 이후부터 `v0.10.1`까지의 변경 사항입니다.
포함 커밋: `fix: skip CUDA runtime probes on ZLUDA`, `chore: release v0.10.1`.

## 개선 및 수정

### AMD ZLUDA 인페인팅 초기화 실패 수정

- AMD ZLUDA 인페인팅을 시작하면 런타임 준비 직후 `Missing symbol cudaGetDeviceCount: GetProcAddress failed` 오류로 종료되던 문제를 수정했습니다.
- ZLUDA의 hybrid CUDA Runtime 라이브러리가 제공하지 않는 `cudaGetDeviceCount` 진단을 ZLUDA 경로에서 실행하지 않도록 변경했습니다.
- ZLUDA 준비가 끝나면 Candle이 사용하는 CUDA Driver API 경로로 바로 모델 로딩을 이어가도록 했습니다.
- Flux 풀로드뿐 아니라 같은 CUDA Runtime 진단을 사용하던 AOT 최소·LaMa 절약 인페인팅 실행기에도 같은 처리를 적용했습니다.
- NVIDIA CUDA 경로에서는 기존 장치 진단을 계속 실행하며, CPU 인페인팅 경로의 동작도 바꾸지 않았습니다.
- ZLUDA 경로에서 진단을 건너뛴 사실을 실행 로그에 남겨, 정상적인 분기와 런타임 준비 실패를 구분할 수 있게 했습니다.

## 내부 정리 및 테스트

- Flux와 Koharu 인페인팅 실행기의 ZLUDA 분기에서 CUDA Runtime API 진단을 호출하지 않는지 확인하는 회귀 테스트를 추가했습니다.
- 수정된 Flux 및 Koharu 인페인팅 실행기를 릴리스 모드로 다시 빌드했습니다.
- NVIDIA CUDA 환경에서 Flux와 LaMa 모델 로딩 및 worker 준비가 기존처럼 완료되는지 확인했습니다.
- AMD 실기 환경은 없어 RX 9070 XT에서 직접 검증하지 못했으며, 이슈에 보고된 즉시 종료 경로를 코드와 회귀 테스트로 확인했습니다.
