# v1.8.1 패치노트

기준 범위: `v1.8.0` 이후부터 `v1.8.1`까지의 변경 사항입니다.
주요 포함 변경: 가져오기·내보내기 종류별 최근 폴더 기억, 취소·실패 시 기존 경로 보존, 최근 경로 저장소의 복구 안정성 강화.

## 가져오기 폴더 기억

### 작업 종류마다 독립된 최근 경로

- 이미지 열기, 이미지 폴더 열기, 압축파일 열기와 압축파일 폴더 열기가 각각 마지막으로 성공한 폴더에서 다시 시작합니다.
- 작업 공유 파일 가져오기, 사용자 글꼴 추가, 로컬 GGUF 모델과 MMProj 선택도 서로의 경로를 덮어쓰지 않고 각 대화상자에 맞는 최근 폴더를 사용합니다.
- 하나의 공통 다운로드 폴더로 계속 초기화되던 흐름을 분리해, 서로 다른 위치의 원고·압축파일·모델을 번갈아 다룰 때도 마지막 작업 위치를 유지합니다.
- 앱을 종료하고 다시 실행해도 최근 경로가 앱 데이터에 보존됩니다.

### 성공한 작업만 반영

- 이미지·폴더·압축파일 가져오기는 미리보기만 열었을 때가 아니라 실제 가져오기가 완료된 뒤 최근 경로를 갱신합니다.
- 대화상자를 취소하거나 가져오기와 글꼴 등록이 실패하면 이전에 성공한 폴더를 그대로 유지합니다.
- 로컬 GGUF 모델과 MMProj 선택 경로는 각각 독립적으로 기억하며, 선택을 취소하면 기존 경로를 바꾸지 않습니다.

## 내보내기 폴더 기억

- 작업 공유 파일 저장, 페이지 PNG 내보내기, 검수용 텍스트와 일반 텍스트 내보내기가 각각 마지막으로 저장한 폴더에서 시작합니다.
- 파일 저장 대화상자는 최근 폴더 안에 기존 기본 파일명을 함께 제안해, 저장 위치를 유지하면서 이름을 바로 확인할 수 있습니다.
- 저장이나 내보내기가 취소되거나 실패하면 최근 경로를 덮어쓰지 않습니다.

## 경로 저장 안정성

- 최근 경로는 설정과 분리된 `recent-dialog-paths.json`에 대화상자 종류별로 저장합니다.
- 기억한 폴더가 삭제되면 존재하는 가장 가까운 상위 폴더로 자동 복구하고, 복구할 위치가 없으면 운영체제 기본 위치를 사용합니다.
- 저장 파일이 없거나 손상되어도 앱 실행과 파일 대화상자를 막지 않고 안전하게 기본 위치로 돌아갑니다.
- 런타임 경로 파일이 앱 패키지에 섞이지 않도록 빌드 제외 규칙을 추가하고, Windows 완전 제거 시 함께 정리합니다.
