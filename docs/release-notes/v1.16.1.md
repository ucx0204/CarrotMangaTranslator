# v1.16.1 패치노트

기준 범위: `v1.16.0` 태그와 `v1.16.1` 태그의 최종 트리를 직접 비교했습니다. 아래에는 두 최종 버전 사이에 실제로 남은 차이만 기록했습니다.

v1.16.1은 Windows AMD Flux 실행 전에 HIP SDK를 정확히 찾고 검증하며, 공식 미지원 GPU와 NVIDIA 번역 런타임 오선택을 설정 화면에서 분명히 알립니다. 동일 데이터 폴더의 오래된 실행 잠금을 여러 프로세스가 동시에 회수할 때 발생할 수 있던 경합도 함께 보완했습니다.

## AMD Flux·HIP SDK 실행 안정성

- Flux ZLUDA가 `ROCm 7.1` 이하의 고정 경로만 찾던 방식을 제거했습니다. 이제 `HIP_PATH`, `ROCM_PATH`, 시스템 `PATH`, `C:\hip_sdk`, `C:\Program Files\AMD\ROCm` 아래의 설치 버전을 순서대로 확인하고, 버전 폴더는 숫자 기준으로 최신 항목부터 찾습니다. 따라서 ROCm 7.2와 이후 버전도 앱 업데이트 없이 같은 규칙으로 탐색할 수 있습니다.
- ZLUDA 실행 파일이나 보조 자산을 준비하기 전에 `amdhip64_7.dll` 또는 `amdhip64_6.dll`이 실제로 있는지 검사합니다. 찾지 못하면 확인한 경로와 필요한 DLL을 오류에 표시하고 CPU 백엔드로 바꾸는 방법을 안내합니다.
- 찾은 HIP SDK 루트와 `bin` 경로를 Flux 실행 환경에 명시적으로 전달합니다. 사용자가 설치한 최신 SDK를 앱이 찾았더라도 내부 런타임의 과거 경로 목록 때문에 다시 실패하던 문제를 막습니다.
- AMD의 현재 [Windows HIP SDK 공식 지원표](https://rocm.docs.amd.com/projects/install-on-windows/en/latest/reference/system-requirements.html)를 Flux 지원 판정에 별도로 적용했습니다. RX 6700 XT처럼 공식 지원 목록 밖인 GPU는 새 기본 설정에서 Flux CPU를 사용하며, ZLUDA를 직접 선택하면 실험 실행 중 오류가 날 수 있다는 경고와 `CPU 백엔드로 전환` 버튼을 표시합니다.
- 기존에 사용자가 직접 저장한 ZLUDA 선택은 강제로 지우지 않습니다. 공식 지원 여부를 판정할 수 없는 AMD GPU도 임의로 미지원 처리하지 않습니다.
- 설정의 HIP SDK 다운로드 문구에서 특정 ROCm 버전 번호를 제거해, AMD가 제공하는 현재 설치 버전과 앱 안내가 어긋나지 않게 했습니다.

## NVIDIA 번역 런타임 선택 경고

- 감지된 RTX 50 계열 GPU에서 llama.cpp `CUDA 12` 런타임을 선택하면 `RTX 50` 런타임을 권장하는 경고를 표시합니다.
- RTX 50 계열이 아닌 NVIDIA GPU에서 `RTX 50` 런타임을 선택하면 실행되지 않을 수 있음을 알리고 `CUDA 12`를 권장합니다.
- 두 경우 모두 고급 사용자의 수동 선택은 막지 않으며, 감지된 GPU 이름과 현재 선택이 어긋날 때만 경고합니다.

## 데이터 폴더 잠금 경합 안정화

- 앱 시작 시 여러 프로세스가 같은 데이터 폴더의 오래된 잠금을 동시에 회수하면, 다른 프로세스가 먼저 잠금 파일을 옮긴 짧은 순간을 손상된 잠금으로 잘못 판정할 수 있던 경합을 수정했습니다.
- 관찰 중인 잠금 파일이 교체되어 사라진 경우에는 새 잠금 상태를 다시 확인하고, 실제로 누락되거나 손상된 잠금 메타데이터는 기존처럼 거부합니다.

이번 패치는 모델 가중치, Llama 런타임 바이너리, Flux 실행기 자산을 교체하지 않습니다. 이미 정상 설치된 캐시는 그대로 재사용합니다.
