## 새 기능

### 용어/기억과 2차 번역 강화

- `용어/기억` 화면에서 작품의 용어집, 캐릭터 기억, 번역 규칙, 스토리 메모리를 관리할 수 있습니다.
- `AI 자동 분석`으로 현재 화 또는 작품 전체의 원문을 읽어 용어, 캐릭터, 스토리 흐름을 채울 수 있습니다.
- 번역 시작 모달에서 `2차 번역 (품질 향상)`을 켜면 1차 번역 뒤에 용어/기억 분석을 거쳐 다시 번역합니다.
- 2차 번역은 이전 번역을 그대로 믿지 않고, 페이지 이미지와 OCR 후보를 기준으로 OCR 오독과 부자연스러운 한국어를 다시 확인합니다.
- OCR이 하나의 말풍선을 여러 조각으로 쪼갠 경우, 2차 번역에서 같은 말풍선/캡션 안의 조각을 하나의 번역 블록으로 합치도록 보강했습니다.
- 용어집과 캐릭터 말투는 스토리 메모리보다 우선해 반영하고, 스토리 메모리는 앞뒤 흐름을 이해하는 참고 자료로 씁니다.

### 영역 번역 품질 개선

- 영역 번역도 일반 페이지 번역처럼 작품 용어집, 캐릭터 기억, 스토리 메모리를 참고합니다.
- 선택한 crop만 보내던 방식에서, `Image 1`은 선택 crop 좌표 기준 이미지로 유지하고 `Image 2`는 원본 전체 페이지 문맥 이미지로 함께 보냅니다.
- 전체 페이지 이미지는 말하는 사람, 주변 장면, 선택 영역이 말풍선 일부인지 판단하는 데만 사용하고, crop 밖의 텍스트를 새 블록으로 만들지 않게 했습니다.
- 현재 페이지 OCR 캐시가 있으면 선택 영역과 겹치는 OCR 후보만 crop-local 좌표로 변환해 참고 자료로 전달합니다.
- OCR 캐시가 없을 때는 기존 OCR 선분석 경로로 원본 페이지 OCR을 시도하고, OCR이 실패해도 이미지와 작품 문맥만으로 영역 번역을 계속 진행합니다.
- 영역 번역 출력 계약을 단일 객체로 바꿨습니다. 선택 영역 하나는 번역 블록 하나 또는 추가할 텍스트 없음으로 처리합니다.
- 영역 번역 결과가 가짜 page id로 스토리 메모리에 저장되지 않게 했습니다.

### 검수표 CSV/TSV 내보내기와 가져오기

- `텍스트 모아보기`에서 현재 화의 검수표를 CSV 또는 TSV로 저장할 수 있습니다.
- 검수표에는 `chapter_id`, `page_id`, `page_index`, `page_name`, `block_id`, `block_order`, OCR 원문, 번역문, 검수 상태, 메모가 들어갑니다.
- 외부 편집기나 스프레드시트에서 번역문, 검수 상태, 메모를 수정한 뒤 다시 가져올 수 있습니다.
- 가져오기는 `block_id` 기준으로 적용합니다. 페이지 순서가 바뀌어도 같은 블록이면 반영됩니다.
- 기본 가져오기에서는 OCR 원문을 바꾸지 않고, 번역문/검수 상태/메모만 업데이트합니다.
- 없는 블록, 중복 block id, 다른 화의 행, OCR 원문 불일치 같은 문제는 경고로 보여줍니다.

### 기본 서식과 서식 일괄 적용

- 설정에 `기본 서식` 탭을 추가했습니다.
- 새로 만들어지는 번역 블록의 방향, 정렬, 폰트, 글자 크기, 자동 맞춤, 줄 간격, 자간, 글자색, 외곽선, 굵게, 기울임을 미리 정할 수 있습니다.
- 기존 블록은 기본 서식을 바꿔도 자동으로 변하지 않으므로, 새 번역 결과와 기존 편집 결과가 섞이지 않습니다.
- 블록 편집 패널에 `일괄 적용`을 추가했습니다.
- 선택한 블록의 서식을 기준으로 글꼴, 글자 크기, 정렬, 가로/세로, 굵게/기울임, 줄 간격, 자간, 색상, 외곽선, 기울기/투명도 중 필요한 항목만 골라 적용할 수 있습니다.
- 적용 범위는 선택한 여러 블록, 현재 페이지, 현재 화 전체 중에서 고를 수 있습니다.

### 단축키 설정

- 설정에 `단축키` 탭을 추가했습니다.
- 보기 전환, 번역 옵션 열기, 이어서 번역, 텍스트 모아보기, 인페인팅 시작/종료, 보정 실행 취소/다시 실행, 블록 삭제/복제, 명령 팔레트, 설정 열기 같은 단축키를 바꿀 수 있습니다.
- 항목을 클릭하고 원하는 키 조합을 누르면 바로 지정됩니다.
- 같은 키 조합을 다른 기능에 지정하면 기존 기능의 단축키는 자동으로 해제되어 충돌을 줄입니다.
- 필요 없는 기능은 `비우기`로 단축키를 제거할 수 있고, 언제든 `기본값`으로 되돌릴 수 있습니다.

### Koharu AOT/LaMa 인페인팅 추가

- 인페인팅 모델에 `AOT 최소`와 `LaMa 절약`을 추가했습니다.
- 두 모델은 Koharu runner 경로를 사용하며, Flux보다 가벼운 원문 제거 선택지입니다.
- `AOT 최소`는 실행 가능성과 낮은 사용량을 우선합니다.
- `LaMa 절약`은 만화 말풍선 안 작은 글자 제거를 빠르고 가볍게 처리하는 용도입니다.
- `Flux 풀로드`는 기존처럼 품질 우선 경로로 유지됩니다.

## 개선 및 수정

### OCR과 번역 블록 안정성 개선

- OCR 후보 좌표를 번역 블록의 위치 기준으로 더 강하게 활용해, 가까운 말풍선이나 효과음이 엉뚱한 위치에 붙는 문제를 줄였습니다.
- 작은 OCR 조각이나 확신도가 낮은 OCR 텍스트가 일반 번역 블록으로 번지는 경우를 줄였습니다.
- 단, 사용자가 직접 선택한 영역 번역에서는 효과음 후보를 지나치게 버리지 않도록 전체 페이지 번역과 기준을 분리했습니다.
- Paddle OCR 캐시 schema를 갱신하고, 같은 페이지 재번역 시 OCR 후보를 더 안정적으로 재사용합니다.
- OCR 후보 id, group id, container type 정보를 프롬프트와 파이프라인에서 더 일관되게 다룹니다.
- 모델 응답 파서는 영역 번역과 전체 페이지 번역의 계약을 분리해, 영역 번역에서 여러 블록이 생기는 문제를 더 빨리 드러내도록 했습니다.

### 저사양/하드웨어 경로 보강

- Paddle OCR에 `최소`, `절약`, `풀로드` 품질 모드를 추가했습니다.
- `최소`/`절약`은 CPU 기반 PP-OCRv6 small/tiny 조합으로 저사양 PC에서 더 가볍게 OCR을 돌릴 수 있습니다.
- CPU OCR 워커 수를 RAM 여유에 맞춰 조절해, 저메모리 환경에서 OCR 때문에 시스템이 과하게 밀리는 상황을 줄였습니다.
- RTX 50번대와 일반 NVIDIA CUDA OCR 경로의 런타임 선택을 더 명확히 했습니다.
- AMD OCR GPU 경로는 ROCm Transformers engine 설정을 분리하고, 실패 시 CPU OCR로 우회하기 쉽게 정리했습니다.
- AMD ROCm Gemma 31B DFlash preset에서 BeeLlama HIP/Radeon 런타임을 사용할 수 있게 했습니다.

### 인페인팅 실행 안정성 개선

- Flux 실행기를 별도 runner/engine 구조로 정리해 작업 실행과 오류 메시지를 더 안정적으로 다룹니다.
- Flux Python 런타임 설치, 경로 파일, 패키지 확인, 런타임 레이아웃 처리를 분리했습니다.
- AMD ZLUDA Flux 실행 전 HIP SDK와 환경 상태를 더 잘 확인합니다.
- 인페인팅 작업 진행률, 작업 카드 메시지, 실패 원인 표시를 보강했습니다.
- 보정/출력 작업을 job runner로 분리해 긴 작업 중 UI 상태가 더 안정적으로 유지되도록 했습니다.

### 편집과 보관함 사용성 개선

- 블록 편집 컨트롤을 정리하고 줄 간격/자간 등 서식 항목을 더 직접적으로 조절할 수 있게 했습니다.
- 페이지 목록과 화 목록의 드래그 순서 변경을 보강했습니다. 저장 실패 시 이전 순서로 되돌리고 상태 메시지에 원인을 표시합니다.
- `*.mgtshare` 가져오기에서 기존 작품에 병합할 때 화 카드를 드래그해 들어갈 순서를 정할 수 있게 했습니다.
- 공유 파일 가져오기/내보내기, 보관함 저장, 페이지 이미지 이동 관련 코드를 정리해 큰 작품을 다룰 때의 안정성을 높였습니다.
