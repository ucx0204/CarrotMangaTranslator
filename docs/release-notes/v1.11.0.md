# v1.11.0 패치노트

기준 범위: `v1.10.1` 이후부터 `v1.11.0`까지의 변경 사항입니다.

v1.11.0은 작업 공간 전반의 UI·UX를 일관되게 정리하고, 페이지 단위 작업 안전성, 서식 프리셋, 인페인팅·내보내기 흐름을 크게 개선한 릴리즈입니다. 동시에 OCR 백엔드 설치 오류, AMD·구형 NVIDIA GPU 경로, 강제 종료·취소·가져오기 중 데이터 손상 가능성을 함께 보강했습니다.

## v1.10.1 대비 핵심 차이

- **작업 잠금:** 화 전체를 막던 흐름에서 실제 작업 대상 페이지만 잠그는 방식으로 바뀌어, 번역 중에도 완료된 다른 페이지를 열고 편집할 수 있습니다.
- **진행 상태와 목록:** 보관함·페이지 상태를 더 정확히 동기화하고 `번역 완료`와 후처리까지 끝난 `완료`를 구분합니다. 페이지 썸네일, 섹션 접기, 작업 센터 5개 높이 제한도 추가했습니다.
- **서식 프리셋:** 별도 관리 화면을 오가던 방식에서 기본 서식 화면 안에서 바로 선택·편집하는 방식으로 바뀌었고, 프리셋 그룹과 가로 스크롤을 지원합니다.
- **인페인팅과 출력:** 분리된 말풍선 영역 사이에 원문이 남는 문제를 보완하고, 여러 페이지 결과는 별도 적용 미리보기 없이 순서대로 즉시 반영합니다. PNG 출력에는 사전 점검과 `글자 없이 출력`이 추가됐습니다.
- **OCR·GPU 런타임:** CUDA 레거시 OCR 풀로드 경로를 제거하고, NVIDIA·AMD·CPU별 패키지를 엄격히 고정합니다. AMD ROCm, RTX 20 계열 Flux, NVIDIA CUDA·cuDNN manifest 호환성도 보강했습니다.
- **데이터 안전성:** 저장·가져오기·작업 결과 반영을 트랜잭션과 revision으로 보호하고, 중복 실행·취소·강제 종료·손상된 입력·과도한 다운로드와 메모리 사용에 대한 방어를 강화했습니다.

## 작업 공간과 진행 상태

- 보관함과 페이지 목록을 각각 접고 펼칠 수 있습니다. 페이지를 길게 검토하거나 작품·화 목록을 넓게 보고 싶은 상황에 맞춰 왼쪽 영역을 조절할 수 있습니다.
- 페이지 목록에 썸네일과 처리 상태를 함께 표시하고, `번역 완료`와 후처리까지 마친 `완료`를 구분합니다.
- 화의 모든 페이지가 완료됐는데 보관함에는 `부분 완료`로 남던 집계 오류를 수정했습니다.
- 다른 페이지가 번역 중이어도 이미 완료된 페이지는 계속 열고 편집할 수 있습니다. 실제 작업 대상 페이지만 잠그며 화 전체를 불필요하게 막지 않습니다.
- 현재 페이지의 빈 공간을 클릭해 블록 선택을 해제한 뒤 번역문을 편집할 때, 이전에 선택했던 블록의 서식·텍스트 배치로 편집 경로가 잘못 이동하던 문제를 수정했습니다.
- 저장 상태를 별도 줄이 아니라 화 제목 옆에 `저장 대기 중`, `저장 중`, `저장됨`으로 간결하게 표시합니다. `저장됨`은 일정 시간이 지나면 자동으로 사라집니다.
- 작업 센터는 최근 상태를 최대 5개 높이로 표시하고, 더 많은 기록은 내부 스크롤로 확인합니다. 불필요한 `스크롤해서 더 보기` 문구는 제거했습니다.
- 작업 중에는 작은 알림 종보다 실행 중 표시를 더 크게 보여 현재 백그라운드 작업을 바로 알아볼 수 있습니다.

## 일관된 UI와 입력 컴포넌트

- 설정, 가져오기, 내보내기, 재번역, 확인 창의 제목·본문·하단 작업 버튼·위험 안내 간격을 공통 구조로 통일했습니다.
- Windows 기본 셀렉트 대신 앱 디자인에 맞는 자체 드롭다운을 사용합니다. 키보드 이동, 검색, 포커스 복원, 화면 경계 배치도 함께 지원합니다.
- 작품 선택은 제목·최근 수정·생성 순서로 정렬할 수 있으며, 긴 작품 제목은 말줄임 상태에서 마우스를 올리면 전체 제목을 툴팁으로 보여줍니다.
- 작품/화 검색창의 겹친 사각 테두리를 제거하고 입력 글자색이 배경과 섞이던 문제를 수정했습니다.
- 새 원본 추가 창은 이미지·폴더·압축파일 선택을 같은 우선순위로 정리하고, 특정 항목만 선택된 것처럼 보이던 초기 강조를 제거했습니다.
- 설정의 기본 서식 화면에서도 왼쪽 메뉴 폭이 다른 설정 페이지와 같게 유지됩니다.

## 서식 프리셋

- 기본 서식 화면 상단에서 프리셋을 바로 선택하고 그 프리셋 자체를 편집할 수 있습니다. 기본값을 임시로 바꾸고 프리셋 관리 창을 오가는 과정을 없앴습니다.
- 프리셋이 많으면 탭 영역이 가로로 스크롤됩니다.
- 프리셋을 `순정만화`, `액션만화` 같은 2단 그룹으로 묶을 수 있습니다. 일반 프리셋과 그룹은 다른 모양으로 표시되며, 그룹을 누르면 소속 프리셋이 옆으로 펼쳐지고 다시 누르면 닫힙니다.
- 프리셋에 포함할 서식 항목은 편집 영역 하단에서 선택합니다. 제외된 항목은 같은 위치를 유지한 채 비활성화되며, 마우스를 올리면 하단에서 다시 활성화하는 방법을 안내합니다.
- 적용 항목을 0개로 만들려고 하면 저장 버튼만 조용히 막는 대신 `프리셋에는 최소 1개 항목을 적용해야 합니다` 토스트를 표시합니다.
- 줄 간격을 프리셋에서 제외했을 때 슬라이더 위치가 위로 튀던 레이아웃 문제를 수정했습니다.
- 적용 미리보기 높이를 줄여 실제 서식 설정을 더 많이 볼 수 있게 했습니다.
- 블록 편집 패널의 프리셋 선택·적용·삭제 흐름과 공통 숫자 입력, 체크박스, 진행 표시, 팝업 컴포넌트를 통합했습니다.

## 페이지 작업 안전성과 검토 흐름

- 페이지 revision과 작업 snapshot을 도입해 작업을 시작한 시점의 페이지 상태를 명확히 기록합니다.
- 인페인팅 작업 중 원문·블록·페이지 상태가 바뀌었다면 오래된 결과를 현재 페이지 위에 적용하지 않습니다.
- 번역, 재번역, 인페인팅, 내보내기 작업은 대상 페이지별 잠금을 사용하며 완료된 다른 페이지 편집을 허용합니다.
- 페이지 블록 목록과 편집 패널의 이동·선택 동작을 분리해, 블록을 선택하는 것과 특정 서식 편집 경로로 이동하는 것이 더 이상 묶이지 않습니다.
- 페이지 재번역과 완료 페이지 덮어쓰기처럼 기존 결과가 바뀌는 작업은 영향 범위와 위험 안내를 실행 전에 보여줍니다.
- 검토가 필요한 페이지를 빠르게 이동하고 블록 서식을 적용할 수 있는 페이지 검토 흐름과 단축키 기반 탐색을 추가했습니다.

## 인페인팅과 PNG 내보내기

- 하나의 말풍선 안에서 텍스트 영역이 둘 이상으로 분리된 경우, 영역 사이의 좁은 틈까지 연결 마스크로 지워 세로 글자 흔적이 남는 문제를 수정했습니다.
- 연결 처리는 같은 말풍선으로 판단되는 가까운 영역에만 적용하고, 관계없는 블록 사이를 과하게 지우지 않도록 거리·겹침 조건을 둡니다.
- 인페인팅 결과는 별도의 적용 전 미리보기 없이 작업이 끝나는 즉시 반영됩니다. 여러 페이지를 연속 처리할 때 미리보기의 undo·redo 상태가 다음 결과와 충돌하던 경로를 제거했습니다.
- PNG 출력 전에 선택 페이지 수, 출력 가능 여부, 누락된 인페인팅 결과, 기존 파일 덮어쓰기 위험을 사전 점검합니다.
- 페이지 범위와 화 단위 선택을 지원하며 출력 파일명 충돌을 실행 전에 확인합니다.
- `글자 없이 출력` 옵션을 추가했습니다. 기본값은 꺼짐이며, 켜면 번역 글자를 합성하지 않고 인페인팅된 배경만 PNG로 출력해 Photoshop 등 외부 도구에서 직접 식질할 수 있습니다.
- 인페인팅 결과가 없는 페이지는 글자 없는 출력이 불가능하다는 이유를 사전 점검에서 명확히 알려줍니다.

## 번역·OCR 설정

- `정밀 2차`를 `정밀 2차 (레거시)`로 변경하고, 처리 시간이 길고 품질 향상 효과가 제한적이어서 추후 제거될 예정임을 안내합니다.
- Paddle OCR의 기존 CUDA 레거시 풀로드 경로를 제거했습니다. 저장돼 있던 레거시 별칭은 현재 지원하는 풀로드 경로로 자동 마이그레이션합니다.
- OCR `최소`는 `최소 (레거시)`로 표시하며 추후 제거 예정임을 안내합니다.
- GPU OCR 권장값은 최소 모드로 자동 하향하지 않습니다. 사용 가능한 GPU 메모리가 4GB 이상이면 풀로드를, 그보다 작거나 CPU를 사용하면 절약을 권장합니다.
- OCR 풀로드는 PaddleOCR의 고품질 좌표·조각과 Transformers 처리를 결합하며, Gemma가 의미 단위로 묶는 현재 경로를 사용합니다.

### NVIDIA·AMD·CPU OCR 런타임 수정

- v1.10.1 이후 개발 빌드에서 NVIDIA CUDA OCR 폴더에 CPU PyTorch가 설치될 수 있던 의존성 잠금 오류를 수정했습니다.
- NVIDIA CUDA 12.6/13.0은 `torch`와 `torchvision`을 각각 정확한 `+cu126`/`+cu130` wheel 및 SHA-256으로 고정합니다.
- AMD는 Windows ROCm 7.2.1 wheel, CPU는 CPU PaddlePaddle, NVIDIA Paddle 경로는 CUDA 12.6/12.9 wheel만 허용합니다.
- 설치 전 lock 파일과 설치 후 실제 패키지 버전을 모두 검사합니다. 선택한 장치와 다른 백엔드가 설치되면 이를 드라이버 문제로 잘못 안내하지 않고, 해당 런타임을 폐기해 올바른 패키지를 다시 설치합니다.
- 기존에 잘못 설치된 OCR 런타임이 남아 있어도 재사용하지 않습니다. 업그레이드 후 첫 OCR 실행에서는 올바른 런타임을 다시 내려받느라 시간이 걸릴 수 있습니다.

## GPU와 플랫폼 지원

- NVIDIA 공식 CUDA·cuDNN 재배포 manifest가 파일 크기를 숫자 문자열로 제공할 때 정상 파일을 거부하던 문제를 수정했습니다. CUDA Flux와 AMD ZLUDA 보조 런타임이 사용하는 네 아카이브의 크기와 SHA-256을 앱 내부에도 고정해 원격 manifest와 다운로드 결과를 이중 검증합니다.
- AMD Flux ROCm 7.2.1 런타임을 복구하고, OCR용 관리 Python을 캐시해 반복 설치 비용을 줄였습니다.
- RTX 20 계열과 같은 SM75 GPU에서 Flux를 사용할 수 있는 실험적 CUDA 경로를 추가했습니다.
- macOS Apple Silicon 패키지는 런타임 자산, ZIP 의존성, 앱 실행 수명주기와 Metal 경로를 더 엄격하게 검증합니다.
- Windows와 macOS 패키징 모두 포함 런타임과 다운로드 자산의 무결성 계약을 강화했습니다.

## 데이터 보존과 작업 수명주기

- 같은 데이터 보관 위치를 두 앱 인스턴스가 동시에 열지 못하도록 단일 인스턴스 데이터 잠금을 추가했습니다.
- 작품·화·페이지 변경을 트랜잭션으로 저장하고, 쓰기 도중 앱이 종료돼도 다음 실행에서 완료 또는 롤백할 수 있는 복구 기록을 남깁니다.
- 가져오기·공유 패키지 읽기와 내보내기를 스트리밍 처리해 큰 작업이 메모리를 과도하게 점유하지 않도록 했습니다.
- 공유 패키지 가져오기 중 취소·충돌·종료가 발생해도 기존 작품과 새 파일이 반쯤 섞이지 않도록 원자적 게시와 휴지통 복구를 적용했습니다.
- 번역·인페인팅·내보내기·모델 테스트 같은 장시간 작업을 중앙 작업 레지스트리에서 추적하고, 취소와 앱 종료 시 자식 프로세스 트리까지 제한 시간 안에 정리합니다.
- 종료 정리가 끝나지 않는 경우 무한히 멈추지 않도록 하드 타임아웃을 적용했습니다.
- 치명적인 메인 프로세스 오류나 창 수명주기 실패가 발생하면 새 저장 작업을 계속 받지 않는 fail-closed 동작을 적용했습니다.

## 입력·다운로드·내보내기 방어

- 가져오기 전에 PNG·JPEG·WebP 헤더와 실제 이미지 크기를 검사해 비정상적으로 큰 이미지나 손상된 파일을 디코더에 넘기지 않습니다.
- 페이지 렌더링과 PNG 출력에 픽셀·메모리 예산을 적용해 지나치게 큰 캔버스가 프로세스를 고갈시키는 것을 막습니다.
- 모델·런타임 다운로드와 API 응답에 크기 제한과 절대 시간 제한을 적용하고, 취소 시 남은 응답 스트림과 자식 프로세스를 정리합니다.
- ZIP·tar 압축 해제 경로, 심볼릭 링크, 파일 개수와 해제 크기를 검증해 대상 폴더 밖으로 쓰거나 비정상적으로 팽창하는 압축파일을 거부합니다.
- 런타임 설치는 hash-complete lock과 무결성 manifest를 사용하며, 임시 디렉터리에서 검증을 끝낸 뒤 완성된 디렉터리만 게시합니다.

## 업그레이드 안내

- 기존 작품·화·페이지·서식 프리셋과 설정은 유지됩니다.
- 앱 삭제 후 설치 경로에 `data` 폴더만 남아 있다면 작품 보관 데이터를 위해 정상적으로 보존된 상태입니다. 해당 폴더를 직접 삭제하지 마세요.
- 잘못된 OCR 런타임만 자동 재설치 대상이며 작품 보관함은 삭제하지 않습니다.
- `정밀 2차 (레거시)`와 `최소 (레거시)`는 이번 버전에서는 계속 사용할 수 있지만 추후 제거될 예정입니다.
