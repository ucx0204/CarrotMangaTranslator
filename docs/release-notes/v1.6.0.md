# v1.6.0 패치노트

> [!WARNING]
> v1.6.0과 v1.6.1 설치 파일은 일부 Windows 환경에서 마지막 앱 실행 파일의 한국어 이름을 풀지 못해 설치가 중단될 수 있습니다. [v1.6.2](https://github.com/ucx0204/CarrotMangaTranslator/releases/tag/v1.6.2) 이상을 사용해 주세요. 실패한 설치 폴더 안의 `data`를 수동 삭제하지 말고 v1.6.2를 그대로 덮어 설치하면 복구할 수 있습니다.

기준 범위: `v1.5.0` 이후부터 `v1.6.0`까지의 변경 사항입니다.
주요 포함 변경: 앱 내 오류 보고와 개인정보 정제 진단 정보, 치명적 오류 복구 흐름, 설치판 Windows 장경로 이미지 표시 수정 및 재발 방지.

## 새 기능 및 개선

### 앱 안에서 작성하는 오류 보고서

- 번역·분석 작업이 실패하거나 앱에서 예상하지 못한 오류가 발생하면 오류 보고 창을 열어 바로 제보를 준비할 수 있습니다.
- 이슈 제목과 오류 직전 작업을 작성하고, GitHub에 공유할 Markdown 본문을 앱 안에서 미리 확인할 수 있습니다.
- 앱·Windows·하드웨어 정보와 정제된 최근 오류 로그를 각각 포함하거나 제외할 수 있습니다.
- `Ctrl+K` 명령 팔레트의 `문제 신고`에서 오류가 사라진 뒤에도 보고 창을 직접 열 수 있습니다.
- `GitHub에서 이슈 작성`을 누르면 시스템 브라우저에 제목과 본문이 채워진 새 이슈를 열며, URL에 담기 어려운 긴 보고서는 클립보드로 복사해 붙여 넣도록 안내합니다.

### 개인정보를 보호하는 진단 정보 공유

- API 키, 인증 헤더, 사용자 홈 경로, 앱 데이터 경로와 알려진 구조화 필드의 작품 텍스트처럼 민감할 수 있는 값을 공유용 진단 정보에서 자동으로 가립니다. 자유 형식 설명과 모든 로그 내용을 완전히 탐지하는 방식은 아니므로 공유 전에 미리보기를 확인해야 합니다.
- 현재 실행과 직전 실행 로그에서 최근 `WARN`·`ERROR` 항목만 제한된 크기로 수집하고, 전체 원본 로그를 보고서에 그대로 넣지 않습니다.
- 오류 내용, 시스템 정보와 로그의 크기를 각각 제한해 지나치게 큰 스택이나 반복 로그가 GitHub 이슈를 가득 채우지 않도록 했습니다.
- 앱은 오류 보고서를 자동 업로드하거나 GitHub 이슈를 자동 제출하지 않습니다. 사용자가 미리보기를 확인하고 GitHub에서 직접 제출해야 합니다.
- 원본 `app.log`와 `previous.log`는 자동 정제되지 않는다는 점을 앱 안내와 5개 언어 README에 명확히 표시했습니다.

## 사용성 개선

### 치명적 오류에서도 이어지는 복구와 제보

- React 화면 오류가 발생하면 오류 내용 확인, 진단 정보 복사, GitHub 이슈 작성, 로그 폴더 열기와 앱 재시작을 한 화면에서 선택할 수 있습니다.
- 메인 렌더러가 비정상 종료되거나 일정 시간 응답하지 않으면 별도의 격리된 오류 보고 창을 열어, 손상된 기존 화면에 의존하지 않고 문제를 확인할 수 있습니다.
- 앱 시작 또는 렌더러 로딩 자체가 실패한 경우에도 기본 오류 대화상자에서 GitHub Issues와 로그 폴더를 열거나 앱을 종료할 수 있습니다.
- 작업 실패 알림에서 바로 오류 보고 창을 열 수 있고, 같은 실패가 여러 상태 경로로 전달되더라도 보고 창이 반복해서 뜨지 않도록 했습니다.
- 오류 보고 화면과 안내 문구를 한국어, 영어, 일본어, 중국어 간체와 번체에 추가하고 공개 이슈용 버그 신고 템플릿을 정리했습니다.

## 성능 및 안정성 개선

### 설치판의 긴 경로에서 이미지가 보이지 않던 문제 수정

- 이슈 #15와 #16에서 확인된, 개발 모드에서는 정상이나 설치판에서 인페인팅 결과 미리보기가 `net::ERR_FILE_NOT_FOUND`로 사라지던 문제를 수정했습니다.
- Electron의 `net.fetch(file:)`에 의존하지 않고 Node 파일 스트림으로 이미지 데이터를 직접 제공해 260자를 넘는 Windows 경로도 정상적으로 표시합니다.
- 같은 장경로 문제가 사용자 등록 폰트에서 재발하지 않도록 커스텀 폰트도 동일한 파일 스트림 방식으로 제공합니다.
- 새 인페인팅 결과 파일은 긴 원본 이름을 반복하지 않고 `작업종류-UUID.png` 형식으로 짧게 생성하며, 작업 종류 길이에도 상한을 둡니다.
- 기존에 생성된 긴 이름의 결과 파일은 이동하거나 변환하지 않아도 새 버전에서 그대로 읽을 수 있습니다.

### 파일 교체와 오류 캐시 방지

- 서명된 이미지 주소를 확인한 뒤 실제 열린 파일의 크기와 수정 시각을 다시 비교해, 확인과 읽기 사이에 파일이 삭제되거나 교체되는 경쟁 조건을 차단했습니다.
- PNG, JPEG, WebP와 TTF/OTF에 정확한 콘텐츠 형식을 지정하고 `nosniff`와 스트림 프로토콜 설정을 적용했습니다.
- 일시적인 404·500 응답이 캐시에 남아 같은 이미지의 재시도를 막지 않도록 오류 응답을 `no-store`로 제공합니다.
- 현재 실행을 시작할 때 직전 `app.log`를 `previous.log`로 보존해 앱을 재시작한 뒤에도 바로 전 오류를 진단할 수 있습니다.
- 오류 보고와 재시작 IPC는 메인 앱 창, 등록된 패널 창과 격리 오류 보고 창에서만 호출할 수 있도록 발신자 검증 범위를 강화했습니다.

## 내부 정리 및 테스트

- 실제 Electron 39에서 288자 Windows 경로의 PNG를 프로토콜로 가져오고 숨겨진 BrowserWindow의 `<img>`에 렌더링하는 smoke test를 추가하고 `npm run check`에 연결했습니다.
- 긴 경로 PNG·JPEG·WebP와 커스텀 폰트의 본문·MIME·캐시 헤더, 파일 삭제·교체와 예상 오류 처리를 회귀 테스트로 검증합니다.
- 보고서 개인정보 정제, 로그 회전·선별·크기 제한, 긴 GitHub 본문의 클립보드 대체 흐름과 신뢰할 수 있는 IPC 발신자만 허용하는지 테스트합니다.
- 작업 실패, React 오류, 렌더러 크래시·무응답, 렌더러 로드 실패와 중복 보고 방지를 단위·통합 테스트로 고정했습니다.
- 오류 보고 창의 넓은 화면과 좁은 화면 레이아웃, 입력·선택·스크롤과 작업 버튼 정렬을 실제 프로덕션 컴포넌트로 확인합니다.
