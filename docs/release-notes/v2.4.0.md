# v2.4.0 패치노트

## 작업 화면 구조

- 화를 연 뒤에도 원고가 작업 화면의 중심에 유지되도록 왼쪽 보관함·페이지 탐색 패널과 오른쪽 검수·편집 패널을 문맥 패널로 재구성했습니다. 창 너비가 부족하면 각 패널은 52px 레일로 접히며, 필요한 쪽만 버튼으로 펼쳐 원고 위에서 확인할 수 있습니다.
- 좁은 창에서 보관함과 편집 패널이 원고 아래로 쌓여 화면 전체에 스크롤이 생기던 구조를 없앴습니다. 펼친 문맥 패널은 화면 가장자리에서 겹쳐 열리고, `Esc`로 닫을 수 있어 캔버스의 위치와 확대 상태를 유지합니다.
- 왼쪽 탐색 패널과 오른쪽 검수·편집 패널을 서로 독립적으로 펼치고 접을 수 있게 했습니다. 화를 열지 않은 보관함 화면은 기존처럼 전체 탐색 패널을 사용합니다.
- 창의 가로·세로 공간이 짧으면 오른쪽 빠른 도구 모음의 위·아래 그룹이 자동으로 접히도록 했습니다. 보기 조절, 원본 불투명도, 작업 센터 버튼은 접힌 상태에서도 각각 눌러 해당 패널을 열 수 있습니다.
- 캔버스 도구 모음과 세부 도구 메뉴의 위치·선택 표시·입력 반응을 통일했습니다. 도구 그룹은 마우스뿐 아니라 방향키와 `Esc`로 열고 닫을 수 있으며, 양쪽 도구 모음의 아이콘 버튼 전체가 실제 동작 영역으로 반응합니다.
- 캔버스 도구 모음을 숨긴 동안에만 현재 선택한 도구 이름을 오른쪽 빠른 도구 옆에 표시합니다. 선택, 영역 번역, 브러시·지우개 등 실제 활성 도구가 바뀌면 표시도 함께 갱신됩니다.

## 번역 실행과 페이지 작업

- 오른쪽 작업 패널의 주 동작을 `번역 설정…` 하나로 정리하고, 페이지 선택과 실행 옵션은 해당 창에서 설정하도록 정보 계층을 단순화했습니다. 다시 번역하면 기존 결과가 바뀐다는 내용은 공간을 차지하는 설명문 대신 경고 아이콘의 툴팁으로 제공합니다.
- 현재 페이지에서 사용하는 원문 지우기, 말풍선 맞춤, 결과 보기, PSD 출력은 `페이지 작업` 아래에 모았습니다. 반복 안내와 별도의 접기 제목을 제거하고 버튼 상태와 저장·동기화 상태가 작업 내용 바로 아래에 이어지도록 정리했습니다.
- 현재 페이지 블록 목록은 선택하지 않은 블록을 원문 또는 번역문 한 줄 요약으로 접어 표시하고, 선택한 블록만 원문과 번역문 편집란을 펼칩니다. 블록이 많은 페이지에서도 목록을 훑고 필요한 항목을 편집하기 쉬워졌습니다.
- 블록 목록에 남은 `검토 필요` 개수와 검토 완료 상태를 표시하고, `검토만` 필터로 확인이 필요한 블록만 모아 볼 수 있게 했습니다. 읽기 순서 번호와 상태 배지를 유지하며, 선택한 블록은 목록 안에서 자동으로 보이는 위치까지 이동합니다.
- 블록이 없거나 검토할 블록이 없는 상태를 구분해 안내하고, 좌표순 정렬처럼 현재 페이지에서 쓸 수 있는 작업만 표시하도록 빈 상태와 버튼 노출을 정리했습니다.

## 화면 전환과 움직임

- 모달 배경과 본문이 따로 자연스럽게 나타나도록 전환 효과를 추가했습니다. 가져오기, 번역 설정, 일괄 편집을 포함한 공통 모달 전체가 같은 속도와 움직임을 사용합니다.
- 도구 메뉴, 선택 목록, 라디오 메뉴, 서식·정렬 메뉴, 오른쪽 보기 조절, 작업 센터, 분리 편집 패널, 알림과 블록 상세 펼치기에 짧은 등장 효과를 적용했습니다. 버튼과 아이콘 버튼에는 누른 상태를 알아볼 수 있는 가벼운 피드백을 추가했습니다.
- 왼쪽·오른쪽 문맥 패널과 캔버스 도구 모음에도 같은 전환 규칙을 적용해 어느 쪽에서 열어도 움직임의 방향과 속도가 일관되도록 했습니다.
- 운영체제의 `동작 줄이기` 설정을 사용하면 이동·확대·흐림 효과를 제거하고 짧은 투명도 전환만 사용합니다.
- 텍스트 모아보기에서 텍스트 일괄 편집을 열 때 일괄 편집 창이 완전히 나타난 뒤 기존 창을 닫습니다. 원본 선택에서 웹 가져오기 또는 가져오기 미리보기로 넘어갈 때도 같은 방식으로 전환해 창 사이의 빈 화면과 갑작스러운 교체를 줄였습니다.
- 텍스트 일괄 편집 창이 다른 분리 패널과 겹칠 때 뒤로 가려지지 않도록 떠 있는 화면의 표시 순서를 정리했습니다.

## API 공급자 설정

- Custom API, NVIDIA NIM, Gemini API, Vertex AI, OpenRouter, Ollama의 Base URL·인증 키·인증 방식·추가 헤더·모델을 공급자별 프로필로 따로 저장합니다. 공급자를 바꿔도 다른 공급자의 연결 정보가 같은 입력란에 섞이거나 덮어써지지 않습니다.
- 각 API 공급자와 모델의 출력 토큰 한도와 문맥 한도를 독립적으로 저장합니다. 로컬 Gemma와 Codex도 각각의 모델 설정을 사용하므로 한 모델의 생성 한도를 바꿨을 때 다른 공급자까지 함께 바뀌지 않습니다.
- 인터넷 조사도 번역 설정과 분리된 공급자별 연결 정보·모델·출력 한도·문맥 한도를 사용합니다. 번역용 설정을 바꾸지 않고 조사 모델만 따로 구성할 수 있습니다.
- 기존에 저장된 공용 API 설정과 인증 정보는 해당 공급자 프로필로 이전합니다. 모델 목록 조회와 연결 테스트도 화면에서 현재 선택한 공급자의 프로필만 사용합니다.
- Vertex AI는 Google Cloud 프로젝트, 리전, 인증 방식과 서비스 계정 JSON을 전용 항목으로 저장하며, 서비스 계정 파일을 설정 화면에서 직접 선택할 수 있습니다.

## 모델 호환성과 실행 수명

- Gemini 3.5 Flash-Lite와 Vertex AI가 요구하는 요청 본문, 모델 경로, 토큰 한도와 구조화 응답 형식을 각각의 API 규격에 맞게 처리합니다.
- NVIDIA NIM과 OpenAI 호환 공급자가 Chat Completions 또는 Responses 형식을 사용할 때 공급자에 맞는 요청을 만들고, 구조화된 번역 결과를 동일한 블록 계약으로 검증합니다.
- Ollama Cloud에는 번역 블록을 `items`, 효과음 결과를 `labels`로 반환하는 JSON 스키마를 직접 전달합니다. Cloud 응답을 일본어 OCR 원문으로 대신 채우지 않고, 요청한 한국어 번역 필드와 블록 ID를 검증해 저장합니다.
- 로컬 Ollama는 번역, PaddleOCR·HayaiOCR 후처리, 페이지 분석, 효과음 번역, 인터넷 조사와 연결 테스트가 끝나면 그 작업에서 실제 사용한 모델만 메모리에서 내립니다. 같은 작업 안에서 모델을 계속 쓸 때는 유지하며 Ollama Cloud에는 언로드 요청을 보내지 않습니다.

## 텍스트 편집

- 번역문을 한글 IME로 직접 편집할 때 조합 중인 초성·중성·종성이 매 갱신마다 다시 입력되던 문제를 수정했습니다. 조합이 끝난 문자열만 편집 결과에 한 번 반영됩니다.
- 캔버스에서 번역문을 편집할 때 커서가 보이도록 하고, 편집 종료·블록 전환·컴포넌트 해제 시 남아 있던 조합 상태와 예약된 화면 갱신을 정리합니다.
