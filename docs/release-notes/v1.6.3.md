# v1.6.3 패치노트

기준 범위: `v1.6.2` 이후부터 `v1.6.3`까지의 변경 사항입니다.
주요 포함 변경: Gemma 12B vision mmproj 다운로드 오류 수정, 대용량 모델·런타임 다운로드 병렬화와 자동 복구 강화, 다운로드·설치 로그 자동 스크롤 개선.

## 다운로드 오류 수정

### Gemma 12B vision mmproj 404 수정

- [이슈 #17](https://github.com/ucx0204/CarrotMangaTranslator/issues/17)에서 확인된, Gemma 12B 최소 VRAM 모드 준비 중 vision mmproj 다운로드가 HTTP 404로 실패하던 문제를 수정했습니다.
- 원인은 Hugging Face에 게시된 파일명의 `bf16` 부분이 `BF16`으로 교체됐는데 앱이 이전 소문자 경로를 계속 요청한 것이었습니다.
- 새 설치에서는 현재 유효한 `mmproj-gemma-4-12B-it-BF16.gguf`를 다운로드합니다.
- 기존 버전에서 받아 둔 소문자 파일은 정상 파일이면 그대로 재사용하므로 다시 다운로드할 필요가 없습니다.
- 새 대문자 파일과 기존 소문자 파일이 모두 있으면 현재 공식 파일을 우선 사용합니다.

## 다운로드 속도 개선

### 대용량 파일 병렬 다운로드

- 기존의 10MiB 값은 초당 속도 제한이 아니라 한 번에 나누어 받던 조각 크기였습니다.
- 파일 크기를 확인할 수 있는 대용량 다운로드는 기본 16MiB 조각과 최대 4개의 병렬 요청을 사용하도록 개선했습니다.
- 단일 연결 속도가 제한되는 환경에서 여러 구간을 동시에 받아 회선과 저장장치를 더 효과적으로 사용할 수 있습니다.
- 모델, mmproj, OCR 모델과 llama 런타임의 파일 크기 확인도 병렬로 처리해 실제 다운로드 시작 전 대기 시간을 줄였습니다.
- 실제 속도 향상 폭은 인터넷 회선, Hugging Face·GitHub 서버 상태, 저장장치와 백신 실시간 검사 상태에 따라 달라질 수 있습니다.

### 인페인팅 다운로드 경로 통합

- Flux·Koharu 모델과 Python·CUDA·ROCm·ZLUDA 관련 인페인팅 런타임도 같은 고속 공통 다운로더를 사용합니다.
- 기능마다 달랐던 단일 스트림 다운로드 구현을 통합해 병렬 다운로드, 재시도, 진행률과 오류 처리가 동일하게 적용됩니다.
- 이미 정상적으로 받은 파일과 다운로드 메타데이터는 계속 재사용합니다.

## 다운로드 안정성 개선

### 끊김과 서버 호환성 자동 복구

- 일시적인 네트워크 오류와 HTTP 429·5xx 응답은 지수 백오프로 자동 재시도하며, 서버의 `Retry-After` 안내도 따릅니다.
- 서버가 범위 다운로드를 지원하지 않거나 잘못된 범위를 반환하면 일반 단일 스트림 방식으로 한 번 자동 전환합니다.
- 다운로드 도중 원격 파일의 ETag 또는 수정 시각이 바뀌면 서로 다른 버전의 조각을 합치지 않고 안전하게 다시 받습니다.
- 서버가 알린 크기보다 짧게 끝난 응답과 대용량 파일 대신 반환된 짧은 오류 문서를 완료 파일로 오인하지 않습니다.
- 중단·취소·실패 시 불완전한 `.part` 파일을 정리하고 다음 재시도를 새 파일에서 시작합니다.

### 파일과 요청 충돌 방지

- 같은 대상 파일이 동시에 요청되면 실제 전송 하나를 공유해 중복 다운로드와 파일 충돌을 방지합니다.
- 여러 모델과 런타임을 준비하더라도 앱 전체의 동시 요청 수를 제한해 서버와 네트워크에 지나친 요청을 보내지 않습니다.
- 백신 검사 등으로 완성 파일 교체가 잠시 막히면 자동으로 다시 시도합니다.
- 인증 오류, 존재하지 않는 파일, 디스크 공간 부족과 권한 오류처럼 반복해도 해결되지 않는 실패는 불필요하게 재시도하지 않고 바로 오류를 표시합니다.

## 다운로드·설치 화면 개선

### 긴 로그에서도 항상 최신 내용 표시

- 다운로드·설치 로그가 80줄 제한을 넘어 오래된 줄을 밀어낸 뒤에도 최신 로그를 계속 따라갑니다.
- 파일명이나 오류 메시지 한 줄이 길어서 여러 줄로 감기고 높이가 늦게 변해도 스크롤이 조금씩 위로 밀리지 않습니다.
- 레이아웃 변화와 앱의 자동 스크롤을 사용자 조작으로 오인하지 않도록 했습니다.
- 사용자가 휠, 스크롤바 또는 키보드로 직접 위로 이동했을 때만 현재 위치를 보존합니다.
- 사용자가 다시 맨 아래로 내리면 자동 추적이 재개되며, 새 작업이 시작되면 최신 로그 위치로 초기화됩니다.

## 재발 방지

- GitHub Actions 릴리스 과정에서 Gemma 12B·26B·31B, draft 모델, Flux·Koharu와 Paddle OCR에 내장된 48개 Hugging Face 파일 주소와 크기를 확인합니다.
- 잘못된 대소문자나 삭제된 모델 파일이 하나라도 있으면 설치 파일을 공개하기 전에 릴리스 빌드를 중단합니다.
- 병렬 범위 다운로드, 범위 미지원 fallback, 원격 파일 변경, 잘못된 응답 크기, 중복 다운로드, 취소와 부분 파일 정리를 회귀 테스트로 고정했습니다.
- 긴 로그, 80줄 순환, 사용자 스크롤 유지와 긴 줄 높이 변경을 실제 프로덕션 컴포넌트와 회귀 테스트로 검증합니다.
