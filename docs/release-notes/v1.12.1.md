# v1.12.1 패치노트

기준 범위: `v1.12.0` 태그의 최종 상태와 `v1.12.1`의 최종 상태를 비교했습니다.

v1.12.1은 RTX 20 시리즈 Flux 인페인팅의 검은 출력 문제와 글자 없는 PNG 출력 오류를 수정하고, 제거 예고했던 Paddle OCR `최소` 및 번역 `정밀 2차` 레거시 모드를 정리한 안정화 릴리즈입니다.

## RTX 20 시리즈 Flux 검은 출력 수정

- RTX 2070 Super를 포함한 compute capability 7.5 경로가 최신 NVIDIA GPU와 다른 FP16·수동 어텐션 러너를 사용한다는 점을 기준으로 실제 모델과 만화 페이지 크롭에서 문제를 재현했습니다. 인페인팅 대상이 불투명한 검은 사각형으로 채워지는 현상이 동일하게 발생했습니다.
- VAE만 FP32로 바꾸거나 어텐션 누적만 FP32로 바꾼 대조에서는 검은 출력이 유지됐습니다. 입력·마스크·스텝·크롭 크기와 VAE/어텐션 구현을 고정하고 트랜스포머 계산만 FP32로 바꾸자 정상적인 밝은 배경으로 복원됐습니다.
- 최종 SM75 경로는 양자화된 모델 가중치와 VAE FP16, 기존 512px 보수적 크롭 및 수동 어텐션을 유지하고 트랜스포머 계산 dtype만 FP32로 변경했습니다. 출력 감지 후 재처리하거나 검은 결과를 덮는 방어 코드는 추가하지 않았습니다.
- 같은 실제 크롭의 GPU 총 사용량 증가 실측은 실패한 FP16 경로 `3,858 MiB`, 수정한 혼합 정밀도 경로 `3,857 MiB`로 측정 오차 수준이었습니다. 처리 시간도 약 5초로 비슷했습니다. 이 수치는 RTX 4090에서 SM75 정책을 강제한 진단 결과이며, strict 배포 바이너리는 compute capability 7.5에서만 실행됩니다.
- 수정된 Windows SM75 러너는 새 불변 프리릴리즈 [`flux-runners-cuda12.9-r3`](https://github.com/ucx0204/CarrotMangaTranslator/releases/tag/flux-runners-cuda12.9-r3)에 게시했습니다. v1.12.1은 r3 URL과 새 SHA-256을 사용하므로 기존 r2 SM75 캐시를 재사용하지 않습니다.

## 글자 없이 PNG 출력 오류 수정

- `글자 없이 출력` 점검에서 인페인팅 이미지가 없는 페이지를 발견하면 메인 프로세스는 `inpainted-image-missing` 문제 코드를 반환했지만, IPC 결과 스키마가 이 값을 빠뜨려 출력 전에 `invalid_enum_value` 오류가 발생했습니다.
- 사전 점검 문제 코드 목록을 타입과 IPC 스키마가 함께 사용하는 단일 상수로 통합했습니다. 이제 누락 페이지는 정상적인 경고로 표시되고 출력 UI가 오류로 중단되지 않습니다.
- 게시글에 첨부된 실제 오류 문구와 같은 결과 객체를 스키마에 통과시키는 회귀 테스트를 추가했습니다.

## 레거시 모드 제거

- Paddle OCR 품질에서 `최소 (레거시)`를 제거하고 `절약`과 `풀로드`만 유지합니다. 기존 `minimum`, `minimal`, `min`, `tiny` 계열 저장값은 읽을 때 `절약`으로 단방향 마이그레이션됩니다.
- `최소` 전용 tiny recognizer 선택과 언어별 예외 코드를 제거했습니다. 저메모리 OCR은 일본어를 지원하는 small detector/recognizer 조합으로 일원화했습니다.
- 번역 품질에서 `정밀 2차 (레거시)`와 분석 범위 설정을 제거하고 `빠른 1회`, `누적 컨텍스트`만 유지합니다. 기존 `two-pass`, `twoPassByDefault`, `analysisScopeDefault` 저장값은 `누적 컨텍스트`로 정규화하고 다시 저장하지 않습니다.
- 2차 재번역 실행, 선택 범위 확장, 작업 문맥 중간 분석, 관련 상태·스타일·번역 문자열과 사용되지 않는 export를 삭제했습니다. 스타일 가이드의 독립적인 작품 문맥 분석 기능은 그대로 유지합니다.

## 자산 게시와 검증

- r3은 SM75를 새로 빌드하고 SM80/86/89/90/120 ZIP은 r2와 바이트 동일하게 유지한 전체 GPU별 자산 세트입니다.
- 6개 ZIP, 결속 manifest와 체크섬 파일을 순차 업로드한 뒤 새 빈 디렉터리에 모두 재다운로드했습니다. 서버의 이름·개수·byte size·SHA-256, ZIP 내부 단일 루트 실행 파일, 압축 해제 후 실행 파일 SHA-256을 게시 전 manifest와 대조했습니다.
- 빈 도구 디렉터리와 빈 런타임 루트에서 실제 GitHub r3 SM75 자산을 내려받아 앱의 해시 검증, 안전 압축 해제, 캐시 marker 기록과 실행 파일 시작을 확인했습니다.
- 상세 inventory와 재현·rollback 정보는 [`flux-runners-cuda12.9-r3` handoff](../asset-manifests/flux-runners-cuda12.9-r3.md)에 기록했습니다.

## 검증

- 실제 프로덕션 번역 실행 모달을 1440×1000 및 760×900 Chromium 화면으로 캡처해 두 번역 모드만 표시되고 잘림·겹침·가로 오버플로가 없는지 확인했습니다.
- 실제 만화 페이지와 Flux 모델을 사용한 SM75 실패 재현, VAE·어텐션·트랜스포머 정밀도 분리 대조, 수정 경로 이미지 확인
- TypeScript·JavaScript 타입 검사, Prettier, ESLint, 구조·의존성·dead-code 검사
- Vitest 전체 회귀·커버리지 검사, 프로덕션 빌드, 페이지 출력 픽셀 일치 QA, 이미지 프로토콜 smoke
- 내장 Hugging Face 자산 검증과 r3 원격 자산 콜드 설치 smoke
- Windows 새 설치·업그레이드·사용자 데이터 보존 installer smoke
- Windows와 Apple Silicon macOS의 GitHub Actions 빌드 및 게시 산출물 SHA-256 재다운로드 검증

## 업그레이드 안내

- 기존 작품·페이지·번역문·서식과 모델 캐시는 유지됩니다.
- 기존에 OCR `최소`를 사용했다면 `절약`으로, `정밀 2차`를 사용했다면 `누적 컨텍스트`로 자동 전환됩니다.
- RTX 20 시리즈에서 Flux를 사용하면 첫 실행에 새 SM75 r3 러너를 다시 내려받습니다. 모델 가중치와 CUDA 런타임은 검증 가능한 기존 캐시를 그대로 사용합니다.
