# v1.13.2 패치노트

기준 범위: `v1.13.1` 태그의 최종 상태와 `v1.13.2`의 최종 상태를 비교했습니다.

v1.13.2는 Windows AMD Radeon 환경의 OCR 장치 라우팅을 바로잡고, 대형 실행 런타임의 설치 I/O와 긴 경로 처리를 강화한 안정화 릴리즈입니다.

## Windows AMD Radeon OCR 라우팅 수정

- Windows ROCm OCR 지원 목록에 없는 AMD GPU에서 GPU/ROCm OCR을 추천하거나 저장 후 NVIDIA CUDA 경로로 전환되던 문제를 수정했습니다. [Issue #65](https://github.com/ucx0204/CarrotMangaTranslator/issues/65)
- RX 6700 XT와 같은 `gfx103X` 계열은 OCR을 CPU/economy로 안전하게 정규화합니다. `gfx1100`, `gfx1101`, `gfx1200`, `gfx1201` 지원 GPU는 기존 ROCm GPU 경로를 유지합니다.
- 설정 불러오기, 저장, 모델 테스트와 실제 번역이 같은 하드웨어 판정 정책을 사용합니다. 오래된 GPU OCR 설정도 지원하지 않는 AMD GPU에서 자동으로 CPU 경로로 복구됩니다.
- 지원하지 않는 AMD GPU에서는 OCR의 Full 선택을 숨기고 ROCm 선택을 비활성화하며 CPU 전용 안내를 표시합니다. GPU 감지가 불가능한 수동 환경과 명시적으로 유효한 고급 환경변수 override는 기존대로 보존합니다.

## 대형 런타임 설치 경량화와 경로 안전성

- ZIP에서 검증을 마친 선택 파일을 같은 볼륨의 staging 안에서 이동해, BeeLlama HIP 런타임 설치 시 약 2.2GB의 중복 파일 복사를 제거했습니다.
- 다운로드가 반환한 검증 receipt와 최종 파일 상태가 일치할 때 불필요한 두 번째 전체 SHA-256 읽기를 생략합니다. receipt가 없거나 파일 상태가 바뀌면 기존 전체 검증으로 되돌아가며, 불일치 파일과 metadata는 게시하지 않습니다.
- 다운로드 임시 파일, metadata, 압축 해제 staging, rollback backup과 실제 런타임 파일의 Windows 경로 길이를 작업 전에 검사합니다. 기본 data root가 너무 길면 data root별로 격리된 짧은 위치를 사용하고, 기존의 완전한 legacy runtime과 명시적인 사용자 서버 경로는 계속 찾습니다.
- 압축파일의 traversal, link, entry 크기·개수·압축비·전체 해제 크기 제한은 그대로 유지됩니다. 고정 런타임 자산의 URL, 크기와 SHA-256 계약도 변경하지 않았습니다.

## 내부 계약 정돈과 회귀 방지

- Semantic OCR geometry, 설정 alias와 IPC shape, 파일 탐색, Font Matching 통계, 번역 서식과 Style Guide의 동일 도메인 중복을 공용 계약으로 정리했습니다. 사용자 API와 결과 정책은 변경하지 않았습니다.
- 실제 ZIP 추출, 다운로드 receipt 변조, checksum·metadata 실패, Windows 경로 경계, AMD OCR 지원·미지원·감지 불가 경로를 별도 회귀 테스트로 봉인했습니다.
- 변경된 production 파일의 lines/statements/functions/branches가 기준보다 낮아지면 실패하는 영속 coverage gate를 추가했습니다.

## 업그레이드 안내

- 기존 작품·페이지·번역문·서식, 설정과 모델 캐시의 저장 형식은 변경되지 않습니다.
- RX 6000 계열에서 OCR GPU 오류를 겪었다면 v1.13.2로 업데이트한 뒤 설정을 다시 열거나 저장하세요. 앱이 감지한 지원 범위 밖의 OCR 설정은 CPU/economy로 복구됩니다.
- 검증이 끝난 기존 실행 런타임과 다운로드 캐시는 계속 재사용됩니다.
