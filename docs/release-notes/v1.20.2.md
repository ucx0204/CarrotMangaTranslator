# v1.20.2 패치노트

기준 범위: `v1.20.1` 태그(`577f8238`)와 이번 `v1.20.2` 최종 트리를 직접 비교했습니다. 개발 중 되돌린 실험이 아니라 최종 제품과 문서에 남은 차이만 기록했습니다.

v1.20.2는 일부 번역 블록의 응답이 누락되거나 형식 검사를 통과하지 못했을 때 정상 블록까지 버리지 않도록 복구 절차를 보강하고, 생성 한도별 실패 원인을 구분해 안내하며, 작업 센터의 시간·상태 기록과 오류 보고 흐름을 개선한 안정성 패치입니다.

## 번역 블록 복구 안정성

- `Fixed-block translation repair exhausted with unresolved ids` 오류가 한 블록 때문에 페이지 전체 실패로 이어지는 빈도를 줄였습니다. 최초 응답에서 정상인 블록은 그대로 보존하고, 누락·중복·형식 오류·원문 문자 잔존이 확인된 블록 ID만 최대 3회 다시 요청합니다.
- 각 재시도에서 아직 해결되지 않은 ID만 고정된 순서로 요청하며, 이미 검증된 번역은 후속 응답으로 덮어쓰지 않습니다. 재시도가 끝나도 비어 있거나 번역되지 않은 블록은 이전처럼 누락하지 않고 페이지를 안전하게 실패 처리합니다.
- 번역문 자체는 정상인데 쓰기 방향이나 글꼴 역할 같은 보조 메타데이터만 충돌한 경우에는 재시도를 먼저 수행한 뒤 검증된 안전 대체값을 적용합니다. 일본어 원문의 장음 기호가 한국어 강조 물결표로 사용된 제한적인 경우도 원문 문자가 남지 않는지 다시 확인한 뒤 복구합니다.
- 실패 로그에는 블록별 거부 사유와 재시도 이력을 남겨, 단순한 컨텍스트 부족과 모델의 특정 블록 형식 오류를 구분해 진단할 수 있게 했습니다.

## 생성 한도 오류 안내

- 모델 응답이 길이 제한으로 잘렸을 때 실제 요청에 적용된 제한을 기준으로 `최대 출력 토큰`, `작품 컨텍스트 예산`, 로컬 모델의 `컨텍스트 길이` 부족을 서로 구분합니다.
- 최대 출력 토큰 또는 작품 컨텍스트 예산이 원인이면 작업 센터와 하단 알림에서 `설정 → 번역 엔진`의 해당 값을 늘리도록 직접 안내합니다. 로컬 컨텍스트 길이가 원인이면 VRAM 사용량이 늘 수 있다는 점도 함께 표시합니다.
- 사용자가 설정으로 해결할 수 있는 생성 한도 오류는 GitHub 오류 보고 창을 자동으로 열지 않습니다. 앱 내부 구조화 출력 한도처럼 사용자 설정과 관계없는 제한도 별도 원인으로 유지해 잘못된 설정 안내를 피합니다.
- 전체 페이지 번역과 선택 영역 번역 모두 같은 실패 분류를 전달하며, 실패한 선택 영역의 불완전한 블록은 작업에 추가하지 않습니다.

## 작업 센터 상태 기록

- 각 페이지 완료 기록에 해당 페이지의 소요 시간을 표시하고, 전체 작업 완료 기록에는 시작부터 종료까지의 총 소요 시간을 표시합니다.
- 상태 기록은 최신 항목부터 보여 주되 처음에는 16개만 렌더링합니다. 목록 끝까지 내리면 이전 항목을 16개씩 계속 불러와, 현재 앱 실행 중에 쌓인 기록을 끝까지 확인할 수 있습니다.
- 상태 기록은 디스크에 저장하지 않습니다. 앱을 종료하면 사라지며, 새 실행 세션에는 이전 기록이 복원되지 않습니다.

## 오류 보고 접근성

- 설정 창의 `로그 폴더 열기` 옆에 `오류 보고` 버튼을 추가했습니다. 정제된 최근 오류와 시스템 정보를 검토하고 클립보드에 복사하거나 GitHub 이슈 작성 화면으로 보낼 수 있습니다.
- 작업 센터의 기존 로그 폴더 버튼도 같은 오류 보고 창을 여는 동작으로 바꿨습니다. 원본 로그 파일을 직접 전달하지 않아도 필요한 진단 정보만 공유할 수 있습니다.
- 오류 보고 창을 수동으로 열었을 때도 최근 진단 정보를 구성하도록 보강했습니다.

## 호환성 참고

- 프로젝트 저장 형식, 모델 자산과 런타임 다운로드 계약에는 변경이 없습니다.
- 지원 운영체제는 Windows 10/11과 Apple Silicon macOS 14+로 v1.20.1과 같습니다.
