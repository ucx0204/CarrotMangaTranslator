# v0.9.1 패치노트

기준 범위: `v0.9.0` 이후부터 `v0.9.1`까지의 변경 사항입니다.
포함 커밋: `chore: release v0.9.1`.

## 개선 및 수정

### AMD OCR GPU 안정성 보강

- Windows ROCm PyTorch가 실제로 지원하는 AMD GPU에서만 `rocm-transformers` OCR GPU 백엔드를 기본값으로 선택하도록 제한했습니다.
- RX 7700~7900(gfx1100/1101), RX 9000(gfx1200/1201), Radeon PRO V710 계열처럼 Windows ROCm OCR 지원 범위에 있는 GPU만 GPU OCR 기본값을 받습니다.
- RX 6000 시리즈, RX 7600/7650(gfx1102), Radeon 740M/760M/780M 같은 iGPU/모바일 계열은 Gemma ROCm/Vulkan 런타임은 계속 쓸 수 있지만 OCR은 CPU 기본값으로 내려갑니다.
- 예전 설정에서 저장된 `rocm-transformers` OCR 백엔드가 지원하지 않는 AMD GPU에 남아 있으면 CPU OCR로 정규화합니다.
- 고급 사용자가 환경 변수로 GPU OCR을 강제하는 흐름은 남겨 두었습니다.

### GPU OCR 실패 시 CPU 폴백

- PaddleOCR-VL GPU 실행이 실패하면 같은 페이지 또는 남은 페이지를 CPU OCR로 자동 재시도합니다.
- GPU OCR 실패가 한 번 확인된 세션에서는 이후 OCR을 CPU로 계속 실행해, 같은 GPU 오류를 반복해서 맞는 일을 줄였습니다.
- CPU 폴백이 꺼져 있거나 중단 요청이 들어온 경우에는 기존처럼 오류를 그대로 보고합니다.
- 모델 파일 손상처럼 CPU로 다시 돌려도 해결되지 않는 오류는 CPU 폴백 대상으로 보지 않습니다.
- 폴백 과정에서도 이미 성공한 페이지의 OCR 결과는 유지하고, 실패한 페이지만 빈 OCR 결과와 진단 정보로 남깁니다.

### VRAM 확보와 OOM 복구

- GPU OCR 시작 전에 캐시된 Flux/Koharu 인페인팅 엔진을 자동 해제해 VRAM을 확보합니다.
- 인페인팅 엔진 캐시가 해제되면 진행 로그에 `GPU OCR을 위해 인페인팅 엔진 캐시를 해제했습니다` 메시지를 남깁니다.
- PaddleOCR-VL 배치 처리 중 페이지 단위 OOM이 발생하면 GPU 메모리 캐시를 정리하고 해당 페이지를 한 번 다시 시도합니다.
- OOM이 반복되는 페이지는 건너뛰고 다음 페이지를 처리하며, 연속 실패가 일정 횟수 이상 이어지면 호출 쪽이 CPU 폴백으로 넘어갈 수 있도록 중단합니다.
- ROCm OCR 자식 프로세스에 HIP allocator fragmentation 완화 설정을 추가했습니다. 사용자가 `PYTORCH_HIP_ALLOC_CONF`를 직접 지정한 경우에는 사용자 값을 우선합니다.

### 다중 GPU/iGPU 환경 대응

- 여러 CUDA/HIP 장치가 보이면 기본 `gpu:0`만 믿지 않고, 가장 VRAM이 큰 GPU를 우선 선택합니다.
- `HIP_VISIBLE_DEVICES`, `ROCR_VISIBLE_DEVICES`, `CUDA_VISIBLE_DEVICES`, `GPU_DEVICE_ORDINAL` 같은 명시적 장치 제한 환경 변수가 있으면 사용자 지정을 우선합니다.
- 선택한 GPU 인덱스를 Paddle OCR textline detector에도 전달해, OCR pipeline과 detector가 서로 다른 장치를 잡는 일을 줄였습니다.
- 내장 GPU와 외장 GPU가 함께 잡히는 Windows ROCm 환경에서 생길 수 있는 HIP 런타임 크래시 안내를 강화했습니다.

### 오류 메시지와 문서 보강

- GPU OOM, GPU device lost/TDR, AMD HIP access violation을 구분해 더 구체적인 한국어 오류 메시지를 보여줍니다.
- VRAM 부족이면 다른 GPU 작업을 닫거나 OCR 장치를 CPU로 바꾸라는 안내를 표시합니다.
- Windows TDR로 의심되는 오류에는 드라이버 갱신, CPU OCR 전환, README의 `TdrDelay` 안내를 함께 보여줍니다.
- `amdhip64` access violation 계열 오류에는 AMD 드라이버 갱신과 iGPU 비활성화 가능성을 안내합니다.
- README FAQ의 AMD OCR GPU 실패 항목에 지원 GPU 범위, VRAM 부족, iGPU 동시 인식, Windows TDR 설명을 추가했습니다.

## 내부 정리 및 테스트

- AMD ROCm OCR 지원 판별 로직을 `ocrRocmSupport` 모듈로 분리했습니다.
- OCR GPU 실패 후 세션 단위 CPU 폴백 상태와 reset helper를 테스트 가능하게 정리했습니다.
- OCR batch progress에 `error` phase를 추가하고 파서를 보강했습니다.
- GPU OCR 전 인페인팅 엔진 캐시 해제 테스트를 추가했습니다.
- AMD OCR 기본값/저장 설정 정규화 테스트를 추가했습니다.
- PaddleOCR-VL 스크립트의 OOM 격리, GPU 메모리 해제, 다중 GPU 선택 로직 확인 테스트를 추가했습니다.
- 런타임 OCR 명령, CPU 폴백, ROCm child env, 오류 메시지 분류 테스트를 보강했습니다.
