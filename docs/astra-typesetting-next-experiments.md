제거 외곽은 최대 12영역, 식자는 최대 16영역씩 순차 요청한다. 모든 응답의 요청 ID
정확한 일치·중복·누락을 검사하고, 검수는 최대 16영역 묶음에 원본/완성본의 인접 native
뷰를 전달한다. 검수 묶음 밖 ID를 거절한다. 모든 원본/완성본 native 뷰가 최소 한 번은
검수에 포함되게 하며, 빈 구간도 통째로 생략하지 않는다. 화 전체 source-font crop 비교와
서체 배정은 그대로 유지한다. 제거·원문 보존·최대 두 번 보정·취소·저장 원자성은 유지한다.
새로운 배칭 응답을 만들기 전에 이 범위를 고정한다. 다음 실행도 discovery-003의 후보 3이며
fresh confirmation이 아니다. 이후 반복 실패 전환 조건을 다시 적용하고 기존 6번은 재사용하지 않는다.

이 단계에서는 이미 끝난 유료 호출을 다른 candidate로 가져오는 cache나 부분 재식자는
구현하지 않는다. 시간 초과 한도를 늘려 해결한 것으로 간주하지 않는다. 비용과 최종 원고
품질을 실제 측정하며, 요청 수 증가가 무조건 절감이라고 주장하지 않는다.

측정값 전달 설명 정정: 기존 raster helper는 첫 native view에만 전체 측정 label을 붙인다.
모든 view에 반복한다는 초기 설명은 helper까지 확인하지 않은 잘못된 추론이었다.
배칭 시 첫 view가 없는 요청에는 측정값이 빠질 수 있으므로, 전체 evidence는 저장하고
각 요청에는 그 묶음의 region ID에 대한 실제 줄·크기·overflow를 붙인다. 원본·완성본
이미지와 전체 구간 검수 범위는 유지한다. v0.3.3의 선언된 묶음에 포함하되, 실제 토큰
절감률은 확인되지 않았다.

## v0.3.4 사전 고정 · 판독 상태의 범위 분리

v0.3.3은 첫 view에서 모델이 담당 구간은 읽을 수 있으나 담당 밖 하단 효과음이 잘렸다고
명시하면서 전역 readability=unreadable을 반환해 실패했다. 입력 축소(v0.3.0)나 280영역
응답 시간 초과(v0.3.1)와 원인이 다르다. 후보 4는 `ownedReadability`와 주변 참고 구간의
`contextReadability`를 분리하고 판독 사유와 이야기 요약을 따로 받는 계약 수정으로 한정한다.
담당 사각형을 view-local 0..1000 좌표로도 명시한다. 담당 구간이 unreadable이면 여전히
중단하며, 기존 전역 unreadable을 성공으로 바꿔 재활용하지 않는다. 원본 해상도·분할 경계·
제거/식자/검수 batch·폰트·ImageGen·최대 보정 수는 v0.3.3 그대로다. 새 실행도 같은 화의
발견용 후보이며 fresh confirmation이 아니다. 원인 가족이 반복되거나 5후보를 소진하면
이 화를 종료하고 최소 200고유질의 조사 후 다음 미사용 화로 이동한다.

같은 입력 계약 점검에서 뒤쪽 native view label에는 원본/완성본 구분도 빠지는 것을 확인했다.
v0.3.4의 모든 view에 그 구분을 명시한다. 실제 crop pixels나 경계는 바꾸지 않으며,
native-view smoke에서 22개 원본/완성본 label과 픽셀 일치를 확인한다.

## v0.3.5 source 준비 · 실행 중 후보에는 적용하지 않음

v0.3.4가 원문 판독 중일 때 별도 합성 fixture로 실제 `renderFontSamples`를 검증했다.
긴 한국어 문구의 60px regular/bold 두 행이 실제로 아래쪽에서 잘렸고 production DOM의
overflow도 true였다. `.tmp/astra-typesetting-research/font-sample-qa/`가 원본 증거다.
이 진단은 만화 후보나 새 일반화 화가 아니며, 현재 out/와 폰트는 그대로 동결한다.

후속 source 수정은 견본에 대해 공백을 정규화하고 grapheme 경계에서 최대 8글자를
고르는 것으로 시작한다. 실제 24/40/60px regular/bold 견본을 렌더하고 모든 행의
overflow=false를 확인한다. 특이한 custom font가 넘치면 4글자, 1글자까지 최대 두 번
문구만 줄이며 글자 크기 자체는 바꾸지 않는다. 여전히 안 맞거나 측정 evidence가
없으면 잘린 견본을 모델에 주지 않고 명시적으로 실패한다. 원문·번역·최종 식자 문구는
줄이지 않는다. 견본에 들어가는 literal markup은 기존 serializer로 보존한다.

## 실제 비용에서 정할 우선순위

`discovery-001/cost-stage-audit.json`에서 모델 토큰은 999,370개였다.
식자 548,477개와 검수 322,710개가 합계 87.17%다. 반면 source-family와
font assignment는 합계 36,108개, 3.61%다. 이미지 생성 사용량은 unknown이다.
서로 다른 화의 토큰 총량만 비교해 절감률을 산출하지 않는다.

따라서 사용자가 요구한 화 전체 source crop 비교를 먼저 없애면 안 된다.
전체 화 문맥·서체 계열은 유지하되, 재식자 요청에서는 실패 영역과 영향받는 이웃만
보내고, 검수에는 실제 변한 위치의 원본/완성본 및 짧은 주변 문맥을 보내는 후보가
우선이다. 첫 전체 검수와 최종 전체 검수는 보존한다. 잘라서 보낸 영역이 전체 페이지
좌표와 실제 저장 상태에 연결되는 증거를 남긴다.

긴 화는 한 요청에 수백 개 식자·제거 외곽을 작성하게 하지 않는 편이 유리할 수 있다.
제한된 수의 영역으로 응답을 나눌 경우 요청 수는 늘지만 단일 응답의 크기·시간 초과와
실패 시 재작업량을 줄일 가능성이 있다. 이는 가설이며 실제 비용/완성도/시간을 함께
측정해야 한다. 같은 원문이 겹친 crop에 보인다고 별도 번역 영역으로 만들면 안 된다.

## 실제 폰트를 본 뒤 표현 방식 선택

2026-09-06 준비 중인 다음 source 후보의 범위를 다음과 같이 먼저 고정한다.
현재 v0.3.1 실행은 compiled out/와 폰트를 동결한 채 계속하며, 아래 source 수정은
그 실행이나 최종 보고서에 사용하지 않는다. 후보 예약/빌드는 현재 실행이 끝난 뒤 한다.
기존 안전한 richTextMarkup serializer/parser를 재사용해 run별 크기·굵기·기울임·색상을
표현하고, run의 plain text 합계가 번역문과 다르면 거절한다. 서체 ID는 기존 화 전체
계열 배정을 유지한다. 식자 단계의 action 선택을 원본 제거 위치와 분리하고 이미지
문자 생성/재판독에는 마크업을 제거한 실제 문구를 전달한다. 최대 두 번 보정과 원문
복원 계약은 유지한다. 읽기/검수 호출 batching과 agent 루프는 이 변경에 섞지 않는다.

현재 action(text/image)은 최초 원문 판독에서 고정되고, bold/italic은 source-family
비교에서 고정된다. 이후 실제 프리셋 폰트 견본과 완성본을 봐도 이를 바꾸지 못한다.
v0.2 원래 6번의 굵은 외침처럼 대조가 사라지는 실패에 대한 후속 후보는 다음과 같다.

- 원문 서체 계열과 source geometry는 보존한다.
- 실제 폰트 견본 확인 후 target weight/size/outline을 독립 결정한다.
- 식자 검수에서 폰트 변형으로 원래 특징을 살리지 못하면 image로 전환할 수 있게 한다.
- image는 실패를 숨기는 자동 대체가 아니다. alpha/재판독/합성 검수와 최대 보정 횟수를
  동일하게 적용하며, 안 되면 원문 보존·검토 표시를 유지한다.
- 한 블록 안의 다른 크기·굵기를 지원하려면 기존 rich text span 계약을 먼저 확인한다.
  전부 같은 크기로 만드는 방식으로 강조 문제를 해결했다고 하지 않는다.

## Codex 도구 루프 후보

번들 `@openai/codex` 0.153.1에서 생성한 로컬 schema에 dynamic tool 호출/응답이
존재한다. 현재 앱은 experimentalApi=false이고 서버 요청을 기본 거절한다.
단순히 developer prompt를 바꾸는 것만으로 agent 도구 루프가 활성화되지 않는다.
공식 App Server 문서와 로컬 버전 차이도 먼저 검증해야 한다.

도입한다면 전용 capability와 제한된 도구 계약이 필요하다. 후보 도구는 원문 영역 보기,
실제 폰트 견본 보기, 편집 가능한 식자 제안 렌더, 지정 마스크 배경 복원, 최종 저장이다.
원본·마스크·폰트·페이지 revision·도구 call ID를 결합한 journal로 동일 호출의 중복 적용을
막고, 취소/재시작 때 적용 완료 상태와 실패 상태를 구분해야 한다. 현재 다른 번역 경로의
도구 차단 정책을 풀어서는 안 된다.

장기 대화는 앞선 이미지와 렌더 피드백을 다시 사용할 여지가 있지만, 대화가 누적돼
입력 토큰과 compaction 비용이 커질 수도 있다. 지속 세션이라는 이유만으로 저렴하다고
단정하지 않는다. 같은 제한과 봉인된 평가 단위 아래 실제 요청/토큰/시간/실패 재작업을
비교하고, ImageGen 사용량이 누락되면 별도 unknown으로 보고한다.
